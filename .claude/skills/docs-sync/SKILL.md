# docs-sync — 코드-문서 정합성 검사·동기화

이 저장소의 문서는 **목표 아키텍처를 선언**하고 코드가 따라간다. 코드 변경이 "사실"을 바꾸면 문서가 조용히 낡고, 그동안 "문서 정합성 정정"류 사후 커밋이 반복돼 왔다. 이 스킬은 드리프트를 PR 안에서 해소해 사후 커밋 자체를 없앤다.

## 절차

### 1. 변경 범위 확정

기본 범위는 현재 브랜치가 dev에서 갈라진 뒤의 전체 변경 + 작업트리다:

```bash
git diff dev...HEAD --stat && git status --short
```

사용자가 특정 커밋/범위를 지정하면 그것을 쓴다. 현재 브랜치가 `dev` 자체라면 `dev...HEAD`는 빈 결과가 되므로, 그때의 범위는 작업트리 변경(`git status`)뿐임을 인지하고 진행한다.

### 2. 바뀐 "사실" 추출

diff에서 문서에 등장할 수 있는 사실만 골라낸다. 코드 내부 구현(함수명, 리팩터링)은 대상이 아니다:

모듈 추가/제거/역할 변경 · 라우트/포트/서비스 연결 · DB 테이블/컬럼 · 워크스페이스 등록(settings.gradle, pnpm-workspace.yaml, pyproject.toml) · 이미지 태그/배포 규약 · 실행/빌드 방법 · 테스트 개수(모듈 README가 개수를 명시하는 경우가 있다) · 아키텍처 결정.

이름 변경(rename)이라도 호출 대상·부수효과·외부 계약이 바뀌면 사실 변경으로 본다 (예: mock 함수를 실제 API 호출로 교체). 순수 내부 리팩터링만 제외한다.

### 3. 문서 지도 대조

사실 유형별로 확인할 위치가 정해져 있다. 해당 행만 읽고 대조한다:

| 바뀐 사실 | 확인할 위치 |
|---|---|
| 모듈 추가/역할/데이터 흐름 | 루트 README (구조 트리 · apps/libs 표 · 워크스페이스 표 · 데이터 흐름 다이어그램), docs/context.md |
| DB 스키마 | docs/implementation.md §4 (소유권 원칙 · 확장-수축 절차), docs/domain/state-machine.md (상태값·ERD), src/libs/schema/README.md |
| 라우팅/포트/서비스 연결 | docker-compose.yml 주석, gateway `application.yaml`, docs/context.md |
| 배포/이미지 태그/인프라 | 루트 README "이미지 태그 규약", infra/terraform/README.md · envs/*/terraform.tfvars 주석 |
| 모듈 내부 동작/테스트 개수/실행법 | 해당 모듈 README (예: src/apps/cloud/data-pipeline/README.md) |
| 코드 흐름/연동을 서술하는 인라인 주석 | 변경된 소스 파일 자체 — "추후 X로 교체 예정"류 주석이 이미 실현된 사실과 어긋나지 않는지 |
| 아키텍처 결정(구조를 바꾸는 선택) | docs/adr/ — 기록이 없으면 ADR 초안을 제안하고(0000-template 사용) docs/adr/README.md 목록에 등록 |

새 문서를 만들게 되면 docs/README.md의 문서 지도에 등록한다.

### 4. 드리프트 보고

발견한 드리프트를 표로 보고한다:

| 문서:위치 | 현재 기술 | 코드가 바꾼 사실 | 조치 |
|---|---|---|---|

드리프트가 없으면 "정합"이라고 명시한다 — 점검했다는 사실 자체가 산출물이다.

### 5. 수정 적용

pr-cycle 게이트로 호출됐거나 사용자가 수정을 요청한 경우 드리프트를 바로 고친다. 단, 방향을 판단하라:

- **코드가 목표 아키텍처를 향해 전진**한 경우 → 문서를 코드에 맞춰 갱신한다 (일반적인 경우).
- **코드가 문서의 목표와 다른 방향**으로 간 경우 → 문서를 조용히 코드에 맞추지 말고 충돌을 보고한다. 문서가 선언한 목표를 바꾸는 것은 사용자(또는 ADR)의 결정이다.

수정은 드리프트 해소에 한정한다 — 겸사겸사 문서를 "개선"하지 않는다 (surgical change).

**실행 명령을 쓰거나 고쳤다면 그 명령이 되는지 직접 확인한다.** 이 단계에서 추가·수정한
실행 예시(`python -m …`·CLI 호출·`VAR=… command` 블록·env 형태)는 edge-review 의
K각도가 볼 기회가 없다 — pr-cycle 게이트는 edge-review 루프를 **먼저** 돌리고 docs-sync
를 그 뒤에 1회 돌리기 때문이다. 내가 쓴 줄은 내가 검증한다:

- 셸이 그 형태를 파싱하는가(변수명에 하이픈·점·공백이 있으면 prefix assignment 가
  `command not found` 로 죽는다 — 설정 키가 도메인 값에서 파생되면 흔하다).
- 로더가 그 형태를 받는가(`env_prefix`·nested 구분자·JSON 복합 타입 파싱과 대조).
- 필수 전제(다른 env·선행 상태)가 그 블록에 다 있는가.

확인 비용이 명령 한 번이면 **실제로 돌려 본다**. 못 돌리는 경우(자격증명·AWS 필요)엔
그 사실을 보고에 적는다 — 안 돌려 봤는데 된다고 쓰지 않는다(Rule 12).
ALPHA-670 실증: 새 relay 엔트리포인트의 README 예시가 하이픈 든 env 이름이라 첫 문서
실행 경로가 통째로 불가였다.
