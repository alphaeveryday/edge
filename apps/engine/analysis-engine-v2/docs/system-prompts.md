# 분석 지시문 구조

에이전트가 받는 지시는 세 층이다. 기본 지침은 모든 작업에 같고 짧다. 깊이는 스킬에 있고, 작업이 그 스킬을 선언했거나 에이전트가 스킬을 열었을 때만 적용된다.

완성된 전망에서 화면 칸을 채우는 필드 단계는 `structured_only=True`를 쓴다. 이 단계에는 작업 노트 규칙이 든
`base.md` 대신 `outlook_fields.yaml`을 시스템 지침으로 직접 전달하고, 네 입력을 최초 메시지에 모두 넣는다.
스킬·작업 폴더의 문서·작업관리 도구는 제공하지 않는다. `system_prompt.txt`, `model_input.json`,
`events.jsonl`, `response.json`, `measurement.json`으로 입력·출력과 비용을 확인한다.

| 층 | 문서 | 언제 전달되나 |
|---|---|---|
| 기본 지침 | [base.md](../src/edge_analysis_v2/prompts/base.md) | 항상. 시스템 지침으로 전달. 어떤 작업에나 맞는 규칙만 둔다 |
| 작업 지시 | [outlook.yaml](../src/edge_analysis_v2/prompts/outlook.yaml), [movement.yaml](../src/edge_analysis_v2/prompts/movement.yaml), [question.md](../src/edge_analysis_v2/prompts/question.md)와 벤치마크·검증 질문의 지침 | 그 작업에서. 최초 메시지로 전달. 무엇을 얼마나 깊이, 어떤 형식으로 답할지를 정한다 |
| 스킬 | `skills/<이름>/SKILL.md` | 작업이 선언하면 작업 지시 뒤에 전문을 붙여 전달. 작업이 선택으로 내놓은 스킬은 이름과 설명만 보이고 에이전트가 열면 읽힌다. 둘 다 아닌 스킬은 그 실행에 없다 |

스킬이 하나라도 있는 실행에는 기본 지침 뒤에 [skills.md](../src/edge_analysis_v2/prompts/skills.md) 한 단락이 붙는다. 스킬이 없는 실행은 스킬이라는 말을 듣지 않는다.

| 스킬 | 담당 | 전망·가격변동 설명 |
|---|---|---|
| cause-investigation | 질문 등록, 경쟁 설명 비교, 종료 조건, 메모 | 선언(항상 실림) |
| analysis-report-writing | 근거 연결, 수치 조건 보존, 제목·요약·상세·결론 작성 | 선언(항상 실림) |
| hypothesis-analysis-workflow | 설명을 가르는 관측 고르기, 하위 질문과 복귀(ACH 기반) | 선택(필요할 때 연다) |
| etf-hypothesis-analysis | 사건 → 사업 → 이익 → 기대 → 평가 → ETF → 한 달 가격 | 선택(필요할 때 연다) |

## 왜 이렇게 나눴나

이전에는 조사 원칙·출력 계약·작성 원칙(약 156문장)이 모든 실행에 실렸고, 하네스 코드가 질문 등록과 경쟁 설명을 모든 실행에 강제했다. 종목코드 하나를 묻는 질문도 투자 질문으로 등록되고 경쟁 설명 두 개를 세운 뒤 열 배 길이로 답했다(릴리스 12, [CQ 벤치마크](cq-benchmark.md)). 지금은:

- 기본 지침은 규칙 두 개(확인하지 못한 것을 없다고 쓰지 않는다, 수치는 도구 값을 쓴다)와 실행 경계뿐이다. "짧게, 물은 것에만"은 질문 작업의 지시(`question.md`)에 있다. 이 규칙을 모든 작업에 맞게 쓰려고 기본 지침에 넣었을 때는 문장이 흐려져 답이 다시 길어졌다(릴리스 15~17).
- 질문 등록과 경쟁 설명 검사는 `cause-investigation` 스킬이 쓰이는 실행에서만 작동한다(`agent/work_session.py`).
- 작업 종류에 따른 분기는 없다. 작업은 지침, 출력 스키마, 선언한 스킬로 정의된다(`run_model(skills=...)`).

스킬 문서는 Anthropic의 스킬 작성 지침을 따른다. 설명(description)에 무엇을 하는지와 언제 쓰는지를 함께 적고, 본문은 쓸 때와 쓰지 않을 때, 단계와 각 단계가 끝나는 조건, 이유, 예의 순서로 쓴다. 지침은 실패가 관측됐을 때만 추가하고, 그 실패를 잡는 검증 가설을 함께 넣는다.

## 기록

실행 폴더에서 확인한다: `system_prompt.txt`(기본 지침), `AGENTS.md`(작업 지시와 선언한 스킬 전문), `model_input.json`(최초 메시지), `skills.json`(쓸 수 있던 스킬, 선언한 스킬, 실행 중 연 스킬과 문서 해시). 대시보드의 작업별 YAML 버전·비교는 해당 YAML만 대상으로 하고, 기본 지침과 스킬은 지시문 목록에서 현재 패키지 내용을 조회한다.

코드 테스트는 선언한 스킬이 작업 지시에 한 번씩 들어가는지, 선언하지 않은 스킬이 들어가지 않는지, 스킬을 쓰지 않는 실행에 질문 등록이 요구되지 않는지를 확인한다. 테스트 통과가 조사 품질이나 전망 적중을 보장하지는 않는다.
