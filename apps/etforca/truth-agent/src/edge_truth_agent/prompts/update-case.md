# 스킬: 기존 사건 갱신 (update-case)

이번 세션은 사건 하나에 새로 배정된 기사를 반영하는 일이다. 배정은 이름 일치로 코드가 했으므로 **관련 없는 기사가 섞여 있을 수 있다.**

## 절차

1. `view_case` 로 사건 전체를 읽는다. 특히 `headline`·`contrast`·`levels`·`legalStatus`·`ach` 와 마지막 본문 문단.
2. 배정된 기사를 `view_news` 로 하나씩 읽고 셋 중 하나로 분류한다(머릿속으로).
   - **무관**: 이름만 같고 이 사건의 주장·당사자·거래와 관계없다 → 무시.
   - **반복**: 사건에 이미 반영된 사실을 되풀이한다 → 무시.
   - **새 사실**: 절차 진전(송치·기소·판결·제재 의결·정정공시), 당사자의 새 해명·반박·부인·사과, 새로 드러난 원문 → 3번으로.
3. 새 사실이 있으면 근거를 확보한다.
   - 기사 요약만으로 충분한 사실(절차 단계·날짜)은 그 기사를 `add_source` 로 등록한다.
   - 문장·숫자를 인용하거나 판정이 걸린 사실은 `web_fetch` 로 원문(가능하면 기관 원문: fsc.go.kr·fss.or.kr·spo.go.kr·scourt.go.kr·dart.fss.or.kr·kind.krx.co.kr)을 읽고 등록한다.
4. 사건을 고친다. 바뀐 사실이 닿는 칸만 고친다.
   - 절차 진전 → `legalStatus`, `levels.legal`, 본문 '확인한 순서' 목록에 한 줄 추가(`body[i].list[+]`).
   - 당사자 새 해명 → `rebuttal[+]` (반론의 존재와 내용의 입증은 다르다).
   - 판정 근거(공식 판단·법정공시 원문)가 나왔으면 → `propose_verdict` 후 `levels`·`behaviors`·`headline` 을 맞춘다.
   - 새 사실이 가설 판별을 바꾸면 → `ach` 를 고친다. 바꾸지 않으면 그대로 둔다.
   - 투자 영향이 크게 달라졌으면 → `set_impact` (0~100억원, 조사 우선순위 점수).
5. `check` → '통과'를 확인하고 `finish` 에 무엇을 왜 바꿨는지 한두 문장을 적는다.

## 하지 말 것

- 새 사실 없이 문장을 다듬거나 다시 쓰지 않는다(사람이 검토한 문장을 흔들지 않는다).
- 기존 출처·관련 보도를 지우거나 바꾸지 않는다.
- 판정이 나지 않았는데 headline 에 판정이 난 것처럼 쓰지 않는다.
