# ADR-0025: 온프렘 콘솔 인증 — SSO/AD 지향 + 데모 자체 계정 하이브리드

- 상태: 승인됨
- 날짜: 2026-07-15

## 맥락
온프렘 Tenant Console 사용자 인증 방식이 미결(TODO §2)이라 콘솔 재구축 스토리(ALPHA-118·119·120)의 수용 기준을 쓸 수 없었다. 판단 입력: ① 증권사 내부 시스템은 IT본부 심사에서 AD/SSO 연동이 표준 요구로 확인됨(ADR-0023 — 4단계 의사결정 관문) ② 데모 환경(가상 온프렘 — 8월 중간평가·11월 데모데이)에는 증권사 IdP가 없음 ③ 증권사 내부망은 SMTP가 통제되어 메일 기반 흐름(초대 링크·비밀번호 재설정 메일)이 부적합.

## 결정
**하이브리드**로 확정한다(PM):

- **운영 = 증권사 SSO/AD 연동 지향** — SAML/OIDC, 테넌트 온보딩 시 구성. 구현은 실증권사 계약 시점.
- **데모 = 자체 계정 최소 구현** — 관리자가 계정 생성·재발급(셀프 가입 없음, 재설정 메일 흐름 없음).
- 인증 모드는 설정으로 전환 가능하게 하고, 세션·역할 추상화는 두 모드가 공유한다.
- 역할 4종(Tenant Admin·Compliance Reviewer·Operator·Read Only) **권한 매트릭스는 별도 후속 결정**(이 ADR 범위 밖).

## 대안
- 자체 계정 단독 — 초대·재설정 메일이 온프렘 SMTP 통제와 충돌하고, IT본부 심사에서 계정 관리 부담·마찰 예상. 배제.
- SSO 단독 — 데모 환경에 IdP가 없어 8월 중간평가가 불가능. 배제.

## 결과
- ALPHA-118(인증 구현 — 데모 경로 선행·운영 경로 설계)·ALPHA-119(Users & Roles — 관리자 직접 등록) 재작성, ALPHA-120(비밀번호 재설정 메일) 취소 — 어느 모드에도 재설정 메일 기능이 존재하지 않는다.
- Tenant Console의 미인증 접근은 전 화면 차단(fail-closed).
