# ADR-0050: 콘솔 규칙 엔진의 사실 공급 — 엔드포인트는 사실만 주고 평가는 클라이언트가 한다

- 상태: 승인됨
- 날짜: 2026-08-08

## 맥락

슈퍼 어드민 콘솔의 규칙 엔진(`super-admin-ui/src/rules/`)은 19개 규칙 + 인과 간선으로 운영 사실을
읽어 위반·사건을 만든다. 그 입력이 지금 **앱 번들 안의 정적 `facts-snapshot.json`** 이다 —
화면은 실판정처럼 그리는데 값은 2026-08-03 에 뜬 스냅샷이다(ALPHA-738).

이걸 실 응답으로 바꾸려면 두 가지를 정해야 한다: **평가를 어디서 하는가**, 그리고 **DB 에 없는
사실(AWS 제어면)을 어떻게 싣는가**.

`rules/README.md` 는 이 선택을 열어 뒀었다 — _"API 가 사실을 주기 시작하면 이 모듈을 그대로
서버(또는 BFF)로 옮기거나 스냅샷 import 를 fetch 로 바꾼다"_.

## 결정

### 1. 엔드포인트는 `Facts` 를 주고, 평가는 클라이언트가 계속한다

`GET /api/v1/console/facts` 의 응답은 사실이고 `Violation[]` 이 아니다.

- `evaluate(f, now)` 는 순수 함수이고, **실시간 축은 이미 클라이언트가 평가한다** — 화면이
  `evaluate({ ...facts, minute: 응답 })` 을 돌린다. 서버로 옮기면 같은 판정이 두 곳에 생긴다.
- 규칙은 IA 라운드마다 바뀐다(9라운드 동안 16 → 19개). 서버에 두면 규칙 문구 한 줄에 배포가 붙는다.
- 엔진과 테스트는 손대지 않아도 된다 — 순수 함수라 입력만 바뀐다.

### 2. AWS 제어면은 같은 응답에, 자기 부재 사유와 함께 싣는다

R03(제어면·원장 불일치)·R11·R12(큐)가 읽는 사실은 DB 에 없다 — Step Functions `DescribeExecution`
과 SQS `GetQueueAttributes` 가 필요하다. 이걸 별도 엔드포인트로 가르지 않고 같은 응답에 넣되,
**실패해도 DB 축을 막지 않는다**: `queues: null` + `awsUnavailable` 사유.

`[]` 로 보내지 않는 것이 핵심이다 — `[]` 는 "큐가 0개"라는 거짓말이고, 규칙이 그걸 통과시켜
`평가됨 · 위반 0`("봤고 괜찮다")이 된다. `null` 이면 `canRun` 이 false 라 `못 돎` 으로 남는다.

## 대안

**규칙 엔진을 서버(또는 BFF)로 옮긴다.** 판정이 한 곳에 모이고 응답이 작아진다. 그러나 실시간
축이 이미 클라이언트에서 평가되고 있어 옮겨도 판정이 두 곳으로 갈리며, 규칙 변경마다 배포가
붙는다. 규칙이 아직 IA 와 함께 흔들리는 단계라 그 비용이 크다.

**AWS 축을 별도 엔드포인트로 뺀다.** 실패 격리가 자연스러워 보이지만, 그러면 "AWS 를 못 봤다"가
타임아웃·404 로만 나타나고 그걸 `못 돎` 으로 옮기는 일이 화면 몫이 된다. **부분 실패를 축 단위
부재로 표현하려면 같은 응답이어야 한다.** ("화면이 두 응답을 합치지 않게"는 근거가 못 된다 —
실시간 축이 이미 별도 응답이라 어차피 합친다.)

**응답을 자를 때 `runs` 를 자른다.** 응답 크기를 줄이는 가장 직관적인 축이지만 안 된다.
`c.runId === p.targetId` 인과 간선 3개가 전부 런 규칙(R04)을 부모로 갖는다 — `runs` 를 자르면
부모가 사라져 자식 위반들이 고아가 되고, **위반 수는 그대로인데 사건 수와 P0 수가 부푼다.**
자른다면 `tasks` 쪽이다(자식이 줄 뿐 병합은 정상).

## 결과

- 계약은 [docs/contracts/console-facts-api.md](../contracts/console-facts-api.md).
- **19규칙 중 `facts` 단독 8개, `/sources/minute` 까지 오면 11개**가 실 응답만으로 선다.
  나머지 8개는 **AWS 호출이 붙어야 돌거나**(R03·R12) 계측이 없거나(R08·R11·R15·R16) 소스 자체가
  없다(R10·R13). 뒤 6개는 화면에 `못 돎` 으로 서야 한다 — `평가됨 · 위반 0` 과 같은 칸에 그리면
  계측 공백이 정상으로 보인다.
- 🔴 **R08(신선도 위반)은 지금 `평가됨` 인데 실 응답에서 `못 돎` 이 된다.** 계약 연결 작업이
  하나뿐이고 그 `actual_as_of_date` 가 [ADR-0043](0043-dataset-contract-freshness.md) 상 영구
  NULL 이기 때문이다. 목이 가리고 있던 계측 공백이 드러나는 것이므로 **회귀가 아니라 정정**이다.
- **런북은 29/29 미등록**이 된다 — 레지스트리 계약 1건의 `runbook_uri` 가 `None` 이고, 스냅샷의
  8개 항목은 손으로 쓴 목이다.
- 클라이언트 평가를 택했으므로 **화면 12곳의 동기 사실 접근을 비동기로 바꿔야 한다**(하나는
  모듈 import 시점에 읽어 fetch 로는 만족되지 않는다). "import 를 fetch 로 바꾸면 끝"이 아니다.
- 정적 스냅샷이 가리고 있던 결함들이 배선 시 함께 드러난다 — 계약 문서 "배선 시 함께 해야 하는 것".
