# ADR-0052: Sync 온프렘 토폴로지 표준의 배치 형태별 분기 — 클라우드 사상은 단일 모듈

- 상태: 제안됨
- 날짜: 2026-08-12
- 관련: ALPHA-956 · ADR-0036(2모듈 표준 — 재검토 대상) · ADR-0051(BYOC 배포 토폴로지) · ADR-0021(DMZ 배치) · ADR-0012(mTLS CSR) · [sync-protocol.md](../contracts/sync-protocol.md)

## 맥락

ADR-0036 은 Sync Agent(DMZ)+Intake(내부망) **2모듈 상시 분리를 표준**으로,
단일 모듈을 옵션으로 정했다. 표준 판정의 결정적 근거는 "다수 증권사의 망분리
정책(DMZ→내부망 직접 DB 커넥션 금지, 망연계 솔루션 경유 요구)과의 충돌" —
물리 망분리 전제다. ADR-0051 로 기본 납품 형태가 증권사 클라우드 계정(BYOC)
으로 확정되면서 이 전제가 기본 형태에서 사라졌다: 경계는 서브넷+SG 로 사상되고,
망연계(망간자료전송) 장비 범주 자체가 없으며, DMZ 사상 서브넷에서 내부망 사상
서브넷의 DB 로 가는 접근은 SG 규칙으로 명시 승인되는 통제 채널이다.

단 ADR-0051 은 이 재검토가 자동 강등이 아님을 못박았다 — 0036 의 핵심 논거
(외부와 닿는 Pull 과 데이터를 눕히는 저장은 신뢰 수준·공격 표면·장애 프로파일이
다르다)는 망연계 장비 유무와 무관하므로, 서브넷+SG 경계가 그 신뢰 구역 분리를
실제로 대체하는지 정면 대조가 필요하다. 지금이 결정의 최소 비용 시점이기도
하다: 온프렘 sync 는 walking skeleton 미구현(Sync Agent·Intake 둘 다 코드
없음, 0036 결과 절)이라 어느 쪽으로 정해도 재작업이 없다.

**정면 대조.** 2모듈 분리가 사던 것과 클라우드 사상에서의 대응물:

| 2모듈이 사던 것 | 클라우드 사상의 대응물 |
|---|---|
| ① DMZ 모듈이 내부망 DB 자격증명을 갖지 않음 — 외부 접점 탈취 시 DB 직행 차단 | sync-agent 는 inbound 리스너가 없는 outbound-only 클라이언트이고 전송 경로는 PrivateLink(0051 결정 3)라 **탈취당할 외부 유입 표면 자체가 물리 DMZ 웹서버와 다르다**. 잔여 위험(외부 통신 프로세스가 DB 자격증명 보유)은 대응물이 없다 — 아래 트레이드오프 |
| ② 경계가 조직 정책 장치(망연계 솔루션)로 강제됨 | SG 가 그 자체다 — 명시 규칙만 통과시키는 감사 가능한 경계 장치. sync-agent SG → DB SG 단일 인바운드 규칙으로 접근 폭을 좁힌다 |
| ③ 역할별 장애·스케일 프로파일 분리 | 모듈 분리 없이도 태스크/컨테이너 단위로 성립하고, 이 볼륨(분 단위 폴링·하루 수 MB)에서 실익이 미미하다 |

반면 2모듈의 실비용은 0036 자신이 "정확성 필수"라 명시한 배선이다: committed
cursor 권위를 Intake 에 두고 commit-ack 없이 DMZ 진행 마크를 전진시키지 않는
조율 프로토콜(내부망→DMZ 제어 신호), 컴포넌트 1개 추가, ack 경로 장애 시
재-Pull 폭 증가. 기본 납품 형태의 모든 배치가 이 비용을 치를 근거가 사라졌다.

## 결정

1. **Sync 온프렘 토폴로지의 표준을 배치 형태별로 분기한다 — 전역 단일 표준을
   두지 않는다.** 클라우드 사상(ADR-0051) 테넌트의 표준은 **단일 모듈**(Sync
   Agent 가 Pull·검증·적재를 수행하고 committed cursor 를 소유), 물리 망분리·
   망연계 요구 테넌트의 표준은 **2모듈**(ADR-0036 문면 그대로)이다.
2. **2모듈 구성과 그 계약은 옵션 카탈로그로 존치한다.** cursor 권위 = Intake,
   commit-ack 없이 DMZ 마크 전진 금지, 내부망→DMZ 제어 신호 허용 — 0036 이
   확정한 이 조율 계약은 문면 그대로 유효하며, 클라우드 사상 테넌트도 증권사
   심사가 요구하면 2모듈로 전환할 수 있다(서브넷 경계 위에서도 그대로 성립).
3. **단일 모듈 표준의 경계 요건**: sync-agent 는 DMZ 사상 서브넷, DB 는 내부망
   사상 서브넷에 두고, DB 접근은 SG 단일 규칙으로만 연다. inbound 리스너는
   두지 않는다(outbound Pull only). 이 요건은 ADR-0051 단계 2 이상에서 성립하며,
   단계 0·1(단일 호스트)이 이 요건 이전 단계라는 0051 의 한정을 그대로 따른다.
4. **Cloud 계약은 불변이다(0036 불변 절 승계).** pull 표면은 Tenant Sync API
   하나(cursor 기반 delta·mTLS·번들 체크섬), 방향은 outbound Pull only,
   인증서-테넌트 바인딩([sync-auth.md](../contracts/sync-auth.md)) 유지. 이
   분기는 온프렘 내부 구조의 분기일 뿐 Cloud 쪽에서는 두 형태가 구별되지 않는다.
5. **구현·문서 후속.** walking skeleton 은 단일 모듈을 우선 구현한다. context.md
   §3·§4.2 와 [sync-protocol.md](../contracts/sync-protocol.md)·
   [state-machine.md](../domain/state-machine.md)의 2모듈 표준 서술 개정은 이
   ADR 승인 후 구현 티켓에서 일괄한다. baseline 스키마의 `writer = sync-agent`
   주석은 단일 모듈 기준이므로 클라우드 사상 표준에서는 그대로 유효하다 —
   0036 이 예고했던 "2모듈 구현 시 Intake writer 반영 새 마이그레이션"은 2모듈
   옵션을 실제 채택하는 테넌트가 생길 때로 미뤄진다.

## 대안

- **전역 2모듈 표준 유지** — 기본 납품 형태(클라우드 사상)의 모든 배치가
  망연계 전제 없이 commit-ack 배선 비용을 치른다. 표준 판정의 결정적 근거가
  기본 형태에서 사라졌는데 표준만 남는 것. 배제.
- **전역 단일 모듈 표준(물리 포함)** — 망연계를 요구하는 물리 망분리 증권사에서
  매번 예외 설계를 유발한다. 0036 이 걷어낸 문제를 되살리는 방향. 배제.
- **결정 유보(구현 시점 판단)** — walking skeleton 이 어느 한쪽 가정을 코드에
  눕히는 순간 전환 비용이 생긴다. 미구현인 지금이 최소 비용이라는 것이 0051 이
  이 재검토를 의무로 명시한 이유다. 배제.
- **단일 모듈에서 DB 자격증명을 별도 브로커로 격리(중간 저장 계층 추가)** —
  2모듈의 위험 절감을 다른 이름의 컴포넌트 추가로 사는 것과 같다. 그 비용을
  치를 테넌트는 2모듈 옵션(결정 2)을 쓰면 된다. 배제.

## 결과

- 얻는 것: 기본 납품 형태에서 컴포넌트 1개와 commit-ack 조율 프로토콜 1세트
  절감, walking skeleton 구현 단순화(단일 모듈 = cursor 소유 조율 불요),
  baseline 스키마 writer 주석 정합 회복. 물리 트랙 증권사 대응력(2모듈 표준)은
  그대로 유지된다.
- 잃는 것/트레이드오프: 클라우드 사상 표준에서 **외부 통신 프로세스(sync-agent)
  가 DB 자격증명을 보유**한다 — outbound-only·PrivateLink·SG 로 유입 표면을
  좁혔어도 이 잔여 위험은 남고, 증권사 심사에서 쟁점이 되면 해당 테넌트를
  2모듈 옵션으로 전환해 흡수한다(전환은 배선 재작업 비용). 표준이 형태별
  2종이라 문서·딜리버리 스펙이 분기를 서술해야 하는 부담이 생긴다.
- 따라오는 의무: 이 ADR 승인 시 ADR-0036 상태를 `대체됨(→ 0052)`으로, README
  인덱스도 함께 표기(0051 의 0017·0033 부분 대체와 같은 승인 시점 처리).

  Relay/Intake Worker 매핑 주석 갱신은 승인 후 구현 티켓에서. 구현은 전부 별도
  티켓이다(제안 상태).
