# ADR-0052: Sync 온프렘 토폴로지 재검토 — 클라우드 사상에서도 2모듈 표준 유지, 근거 재정초

- 상태: 제안됨
- 날짜: 2026-08-12
- 관련: ALPHA-956 · ADR-0036(2모듈 표준 — 재검토 대상, 유지 결론) · ADR-0051(BYOC 배포 토폴로지) · ADR-0021(DMZ 배치) · ADR-0040(무결성 서명 목표 계약) · [sync-protocol.md](../contracts/sync-protocol.md)

## 맥락

ADR-0036 은 Sync Agent(DMZ)+Intake(내부망) **2모듈 상시 분리를 표준**으로
정했고, 표준 판정의 결정적 근거는 "다수 증권사의 망분리 정책(DMZ→내부망 직접
DB 커넥션 금지, 망연계 솔루션 경유 요구)과의 충돌" — 물리 망분리 전제였다.
ADR-0051 로 기본 납품 형태가 증권사 클라우드 계정(BYOC, 경계=서브넷+SG)으로
확정되면서 이 근거가 기본 형태에서 사라졌고, 0051 은 "서브넷+SG 경계가 신뢰
구역 분리를 대체하는지 정면으로 다루는 별도 ADR"을 의무로 남겼다. 이 ADR 이
그 재검토다.

재검토에서 두 가지를 대조했다.

**① 신뢰 구역 논거 대 서브넷+SG.** 2모듈 분리가 사는 것: 외부와 통신하는
프로세스(sync-agent)가 내부망 DB 자격증명을 갖지 않는다 — 외부 접점이 탈취돼도
DB 직행 경로가 없다. 클라우드 사상에서 유입 표면은 좁아지지만(sync-agent 는
inbound 리스너 없는 outbound-only 클라이언트, 전송은 PrivateLink — 0051 결정 3,
비AWS 테넌트는 인터넷 outbound 443) 이 분리 자체의 대체물은 서브넷+SG 에 없다
— SG 는 경로를 좁힐 뿐, "외부 통신 프로세스와 DB 자격증명의 분리"는 모듈
경계가 만든다. 즉 0036 의 핵심 논거는 망연계 장비가 아니라 신뢰 구역 분리이고,
이는 사상 후에도 유효한 방어 계층이다.

**② 전환 비용의 방향.** 0036 결과 절은 작성 시점(2026-07-21) 기준 "Intake 는
walking skeleton 단계에서 구현된다(현재 미구현)"고 썼으나, 이는 이미 지난
기록이다 — 현재 저장소에는 2모듈이 구현·검증돼 있다: sync-agent 의 릴레이
표면(`BundleRelayController`)과 intake 의 폴링·적재(`IntakePoller`·
`BundleIngestor`)가 테스트와 함께 존재하고, Raw Event Store writer 메타데이터도
`V202607211900__update_sync_writer_comments.sql` 로 **writer = intake** 가 이미
적용돼 있다. 따라서 "단일 모듈로 자리바꿈"은 배선 절감이 아니라 **기구현
자산의 병합·cursor 소유권 이전·마이그레이션 재작업을 새로 사는 것**이다 —
2모듈의 조율 비용(commit-ack 배선)은 이미 지불되고 테스트로 고정됐다.

## 결정

1. **클라우드 사상을 포함한 전 배치 형태에서 2모듈 표준을 유지한다.**
   ADR-0036 의 결정·계약(cursor 권위 = Intake, commit-ack 없이 DMZ 진행 마크
   전진 금지, 단일 모듈은 옵션)은 문면 그대로 유효하며 상태 변경(대체 표기)이
   없다. 바뀌는 것은 **표준 판정의 근거**다: "망연계 요구 증권사와의 충돌
   회피"(물리 전제, 기본 형태에서 소멸)가 아니라 ① 외부 통신 프로세스와 DB
   자격증명의 신뢰 구역 분리는 사상 후에도 유효한 방어 계층이고 ② 그 배선은
   이미 구현·테스트·마이그레이션까지 완료된 자산이라 유지가 최소 비용이다.
2. **클라우드 사상에서의 배치 대응을 명시한다.** sync-agent 는 DMZ 사상 서브넷,
   intake 와 DB 는 내부망 사상 서브넷에 배치한다(ADR-0051 단계 2 이상에서 성립).
   단계 0·1(단일 호스트 compose)에서는 두 모듈이 한 호스트에 공존한다 — 모듈
   경계(프로세스·역할 분리)는 전 단계에서 유지되고, 네트워크 경계만 단계 2에서
   생긴다(0051 의 "실 테넌트 배치 최소선 = 단계 2" 한정과 정합).
3. **단일 모듈 구성은 0036 문면 그대로 옵션으로 존치한다** — 컴포넌트 최소화를
   원하고 DMZ 사상 구역→DB 직접 커넥션을 승인하는 테넌트의 선택지.
4. **Cloud 계약은 불변이다(0036 불변 절 승계).** pull 표면은 Tenant Sync API
   하나(cursor 기반 delta·mTLS), 방향은 outbound Pull only, 인증서-테넌트
   바인딩([sync-auth.md](../contracts/sync-auth.md)) 유지. 무결성은 전송
   계층(mTLS/TLS)에 위임하며 앱 레벨 체크섬은 폐기됐고 발신자 서명이 목표
   계약이다(ADR-0040 — 이 ADR 은 건드리지 않는다).
5. **후속 문서 변경은 없다.** 표준·계약·구현이 전부 현행 유지이므로 context.md·
   sync-protocol·state-machine·아키텍처 뷰 매핑 개정이 필요 없다. 0036 결과
   절의 "미구현" 서술은 작성 시점의 사실 기록이라 수정하지 않는다 — 현행 구현
   상태는 이 ADR 맥락 ②가 기록한다.

## 대안

- **클라우드 사상 표준을 단일 모듈로 자리바꿈(재검토의 당초 후보)** — 근거였던
  "commit-ack 배선 비용 절감"은 배선이 이미 구현·적용된 지금 매몰비용이라
  절감이 아니고, 전환은 기구현 모듈 병합·cursor 소유권 이전·writer 메타데이터
  재변경이라는 신규 비용이다. 신뢰 구역 분리(맥락 ①)를 자격 없이 포기하는
  방향이기도 하다. 배제.
- **전역 단일 모듈 표준(물리 포함)** — 위와 같고, 추가로 망연계 요구 증권사에서
  매번 예외 설계를 부활시킨다(0036 이 걷어낸 문제). 배제.
- **0036 을 대체하는 재작성 ADR** — 결정이 그대로인데 문서만 갈아끼우면 이력
  노이즈만 생긴다. 근거 재정초는 이 ADR 의 기록으로 충분하다. 배제.
- **결정 유보** — 0051 이 재검토를 의무로 명시했고, 유보하면 "표준 근거가
  소멸했다"는 의심이 배치 계열 결정마다 재발한다. 지금 종결한다. 배제.

## 결과

- 얻는 것: ADR-0051 의 재검토 의무 종결. 2모듈 표준의 근거가 배치 형태와
  무관하게 성립하도록 재정초됐다("망연계 때문"이 아니라 "신뢰 구역 분리 +
  기구현 자산"). 구현·배포·문서 전부 무변경 — 이 ADR 은 방향 확인만 기록한다.
- 잃는 것/트레이드오프: 기본 납품 형태에서 commit-ack 조율 복잡도가 상존한다
  — 이미 지불·테스트로 고정된 비용이지만, 신규 기여자에게는 여전히 학습
  대상이다. 클라우드 사상 심사에서 "서브넷 분리가 있는데 왜 모듈도 나누나"는
  질문에는 맥락 ①(자격증명 분리는 SG 가 대체하지 못함)로 답한다.
- 따라오는 의무: 없음 — 상태 표기·문서 개정·구현 변경 전부 불요. ADR-0051 의
  "따라오는 의무" 중 0036 재검토 항목이 이 ADR 로 이행됐다.
