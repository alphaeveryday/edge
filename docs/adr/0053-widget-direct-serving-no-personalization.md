# ADR-0053: 고객 컨텍스트 제거 — MTS 위젯 직접 호출, Exposure Log 은퇴

- 상태: 제안됨
- 날짜: 2026-08-17
- 관련: ALPHA-991 · ADR-0010(하이브리드 온프렘) · ADR-0013(Exposure Log — 이 ADR 이 대체)
  · ADR-0035(위젯 빌드 산출물 납품) · ADR-0051(BYOC 배포 토폴로지) · ALPHA-501(요청 메트릭)

## 맥락

제품에 개인화 기능을 두지 않기로 확정했다(사용자 결정 2026-08-17). 이 확정은
서빙 경로의 두 전제를 동시에 무너뜨린다.

첫째, **고객 식별의 존재 이유가 사라진다.** `X-Customer-Hash`(증권사 백엔드가
생성하는 고객 해시, ADR-0013)는 고객 단위 노출 이력(민원/감사 재현)을 위한
장치였다. 개인화도, 고객 단위 재현 요건도 없으면 이 헤더는 필수 검증(400)만
남은 빈 계약이다.

둘째, **증권사 백엔드 경유 호출 전제가 풀린다.** 지금 계약
(docs/contracts/publication-api.md)은 "증권사 백엔드가 호출하는 조회 표면"이다.
그 이유는 ① 고객 해시를 생성할 주체가 백엔드뿐이고 ② 원본 고객 ID 비수취
경계를 서버 간 호출로 지키기 위함이었다. ①이 사라지면 ②는 "받을 고객 데이터
자체가 없음"으로 더 강하게 성립하므로, 경유를 강제할 근거가 없다.

배포 형태가 증권사 클라우드 계정(BYOC, ADR-0051)으로 확정되어 있으므로 MTS
위젯(빌드 산출물, ADR-0035)이 publication-api 를 직접 호출해도 트래픽은 증권사
통제 표면 안에서 끝난다 — ADR-0010 의 경계는 벤더/증권사이지 증권사 내부의
호출 토폴로지가 아니다. 데모는 이미 이 형상(위젯 → CloudFront /api 프록시 →
publication-api)으로 관통 검증됐고, mock-broker 의 고객 해시는 형식 요건을
채우는 껍데기 값이었다.

한편 관측 축은 이미 분리되어 있다 — `serving_request_metric`(ALPHA-501)은
요청 수·상태·에러 코드를 기록하는 관측 원장이고, 설계 시점부터 "고객 식별자·
문구를 싣지 않는다"를 규약으로 갖는다. 고객 축이 사라진 뒤 서빙 경로에 남는
기록 요구는 이 관측 축이 전부다.

## 결정

1. **MTS 위젯이 publication-api 를 직접 호출한다.** "증권사 백엔드가 호출하는
   조회 표면" 전제를 계약에서 걷어낸다. 서빙 응답은 게시분(Published)·비개인화
   공통 콘텐츠·읽기 전용이라 단말 직접 노출에 적합하고, 제공 범위 차단은
   지금처럼 204 수렴으로 증권사 단말에 제외 사실을 드러내지 않는다.
2. **고객 식별을 폐지한다.** `X-Customer-Hash` 헤더·`MISSING_CUSTOMER_HASH`
   (SERV4001)·서비스 관통 파라미터를 제거한다. "원본 고객 ID 를 받는 표면을
   만들지 않는다"는 원칙은 유지되되, 근거가 "해시로만 받는다"에서 "고객 식별
   자체를 받지 않는다"로 강해진다.
3. **`X-Channel` 도 함께 폐지한다**(SERV4002·SERV4003 포함). 직접 호출에서
   채널은 클라이언트 자가 신고 값이라 감사 근거가 못 되고, 위젯 단일 채널이라
   구분 정보량도 없다. 채널 구분이 실제로 필요해지는 시점(HTS 등 제2 채널
   실물)에 신뢰 가능한 공급 방식과 함께 재도입한다.
4. **Exposure Log 를 은퇴시키고 기록 요구는 `serving_request_metric` 이
   흡수한다.** ADR-0013 의 "조회=노출 기록, 민원 시점 상태 완전 재현" 요건을
   폐기한다 — 고객 단위 재현은 고객 식별 없이는 원리적으로 불가능하고, 남는
   관측 요구(어느 경로가 얼마나 호출되고 어떤 상태로 끝났는가)는 요청 메트릭이
   이미 전담한다. 메트릭 스키마는 **확장하지 않는다** — 노출 문구 스냅샷·티커
   축을 옮겨 싣는 것은 폐기한 감사 요건을 관측 원장에 되살리는 일이다.
   `ExposureLogRecorder`·`ExposureLog`·`exposure_log` 테이블을 제거한다
   (코드 은퇴 선행 → 수축 마이그레이션의 확장수축 순서, 적용분 수정 금지).
5. **직접 노출에 따르는 방어는 역할을 나눈다.** publication-api 는 CORS(허용
   오리진 = 증권사 위젯 도메인, 테넌트별 설정값)를 갖추고, rate limit·WAF 등
   엣지 보호는 증권사 인프라 영역으로 계약 문서에 책임 경계만 명시한다(벤더
   불관여 원칙 유지 — 해시 생성 규칙·salt 가 증권사 영역이었던 것과 같은 결).

이 결정으로 **바뀌지 않는 것**: 서빙 표면 자체(GET /api/v1/explanations —
경로·응답 형상·204 수렴·면책 문구 동반), 제공 범위(serving_scope) 판정, 게시분
캐시 방향(ALPHA-433 — 직접 호출로 요청량이 단말 수에 비례하게 되어 오히려
전제가 강해진다), 하이브리드 플레인 분리와 데이터 비반출(ADR-0010), Cloud 의
비개인화 원칙(원래부터 개인 데이터가 없던 플레인이라 무변경).

## 대안

- **경유 전제를 유지하고 헤더만 optional 로** — 호출 주체가 증권사 백엔드로
  남는 한 위젯→백엔드→publication-api 의 중계 구현을 증권사에 요구하게 된다.
  개인화가 없는데 중계가 하는 일은 헤더 부착뿐이라 납품 협의 표면만 늘린다. 배제.
- **exposure_log 를 고객 축만 빼고 유지**(문구 스냅샷·티커·시각) — 감사 요건
  없이 남는 것은 "요청당 텍스트 스냅샷 적재"라는 쓰기 비용뿐이다. 이 INSERT 는
  200 응답당 동기 쓰기 2건의 한 축으로, 진행 중인 캐시 실험(ALPHA-433 계열)이
  읽기 효과와 분리해 측정해야 할 만큼의 비용 축이다 — 요건이 사라진 쓰기를
  성능 비용을 내며 유지할 이유가 없다. 노출 문구 재현이 다시 요건이 되면 그때
  게시 이력(publication)+정책 이력(policy_version)의 역산이 아니라 스냅샷
  재도입을 정면으로 결정한다. 배제.
- **채널(X-Channel)만 존치** — 자가 신고 값의 통계는 엣지(CloudFront·ALB)
  로그로도 얻는다. 검증 로직·에러 코드 2종을 유지할 근거가 안 된다. 배제.
- **위젯 전용 BFF(backend-for-frontend) 신설** — 직접 노출이 불안하면 세울 수
  있는 층이나, 지금 요구(CORS·읽기 전용 조회)에 대해 모듈 하나가 통째로
  과잉이다(온프렘 반입 컴포넌트 최소화, ADR-0051 결정 6과 같은 계열). 배제.

## 결과

- 얻는 것: 계약이 실제 사용 형상(데모가 이미 검증한 직접 호출)과 일치한다.
  증권사 측 납품 요구사항에서 "고객 해시 생성·중계 구현"이 통째로 빠진다.
  서빙 hot path 의 요청당 INSERT 1건(exposure_log)이 사라진다. 사문화된 인접
  티켓 2건(ALPHA-778 해시 평문 로그 제거·ALPHA-775 면책 문구 스냅샷)이 함께
  종결된다.
- 잃는 것/트레이드오프: 고객 단위 노출 이력이 사라진다 — 민원 대응은 "그
  시점 게시 상태·활성 정책"의 재구성(publication·policy_version 이력)까지만
  가능하고 "그 고객이 무엇을 봤는가"는 증권사 영역(엣지 로그)으로 넘어간다.
  API 가 단말에 직접 노출되어 엣지 보호가 증권사 구성 품질에 의존한다(계약
  문서로 경계만 명시). 채널 축 관측이 사라진다(재도입 조건 명시로 상쇄).
- 따라오는 의무: 승인 전환 시 — ADR-0013 상태를 대체됨(0053)으로, README 색인
  갱신, docs/domain/exposure-log.md·data-residency.md 의 노출 이력 서술 정리,
  계약 문서(publication-api.md·openapi.yaml·README) 재작성은 구현 PR 과 동행.
  구현 순서 — ① 코드 은퇴+호출자 정리(mock-broker·loadtest·compose 예시)
  ② 수축 마이그레이션(exposure_log drop)+dbml 재생성. 진행 중인 서빙 캐시
  실험(ALPHA-433 계열, 미커밋)이 ExposureLogRecorder 를 건드리므로 구현 착수
  전 착지 순서를 조율한다. 사문화 티켓 2건은 승인 전환 시 사유를 남기고 닫는다.
