# DB 툴 기록 조회

대시보드는 분석 종류와 분석 ID로 DB에 저장된 툴 기록을 조회한다. 로컬 파일은 DB 저장 여부를 증명하지 않는다.

- 입력: `analysis_kind` (`movement` 또는 `outlook`), `analysis_id`.
- 출력: `storage: "postgresql"`, 분석 행 `analysis`, 실행 목록 `tool_runs`, 툴 정의 맵 `definitions`.
- 실행 목록: 성공·실패 모두 포함. 실행 시작 시각, 툴 실행 ID 순서.
- 실행 결과 `output`: DB에 저장된 값을 그대로 반환. 날짜 컬럼만 ISO 문자열로 변환.
- 툴 정의: 수식, 관리자 설명, 출처명. 기존 대시보드의 정의 맵 형태로 제공.
- 없는 분석: `None`. 존재하지만 호출이 없는 분석: 빈 목록.
- 잘못된 분석 종류나 DB 조회 실패: 오류. 로컬 기록으로 대체하지 않음.
- 한 번의 조회는 같은 DB 스냅샷을 사용. 원천 데이터·DB 스키마·권한 변경 없음.

이 단계는 조회 함수까지다. 기존 로컬 대시보드와 실제 에이전트 실행부의 연결은 다음 작업에서 적용한다.
