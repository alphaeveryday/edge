목 원천으로 실제 에이전트와 계산 툴을 실행하고, 클라우드 PostgreSQL에 저장한 결과로 화면 응답을 조립한다. 대시보드는 실행 중 이벤트와 실제 저장 행을 구분해 보여준다. 원천 데이터 수집·연결은 후속 작업이며, 분석 결과 DB 연결은 이번 목표에 포함한다. 로컬 PostgreSQL은 클라우드 적용 전 검증에 사용한다.

## 실행 경계

- 입력만 목데이터. 계산·툴 감사·수정 처리·저장·응답 조립은 실제 코드.
- 자동 테스트는 고정 에이전트 응답 사용. 대시보드의 에이전트 실행은 실제 모델 호출이며 비용 발생.
- 분석 실행기는 로컬에서 시작하고 결과는 클라우드 DB에 저장. 분석서버 배포는 필요한 시점에 별도 검토.
- 각 변경은 로컬 리뷰 후 필요한 파일만 실제 PR로 제출. 기존 미커밋 작업 일괄 포함 금지.

## 응답에서 저장을 거쳐 화면으로

기준: Obsidian `ETF ORCA/분석 저장 구조.erd`와 `화면 설계/`의 현재 계약.

| 기능 | 저장 위치 | 저장 후 조립할 응답 |
|---|---|---|
| 오늘 움직임 요약·선정 | movement_analyses: summary, selected_item_ids | 요약과 선택 순서 |
| 오늘 움직임 새 설명 | movement_items: 제목·문장·감정·자료 기준시각·근거 | 선택된 항목의 상세 목록 |
| 전망 요약·종합 스티커 | outlook_analyses: summary_title, summary, outlook_sticker | 전망 요약 |
| 전망 본문 | outlook_analyses.detail_title + outlook_items(section=detail) | 논점별 제목·불릿·강조·근거 |
| 오늘 업데이트 | outlook_items(section=update) | 같은 날짜의 논점 추가·수정·삭제 기록 |
| 5요인 | outlook_factors | 요인별 에이전트 스티커·설명 |
| 최종 결론 | outlook_analyses의 결론 + outlook_conclusion_keywords | 결론·도움·부담·변경 조건 |
| 수치 카드 | outlook_metrics (아래 보완) | 차트·매크로·밸류·수급 상세 |
| 툴 근거 | tool_runs → tool_definitions | 인수·반환값·수식·출처·시각 |

최종 JSON을 한 덩어리로 저장해 반환하지 않는다. 기존 ERD의 텍스트 컬럼·불릿 묶음·툴 인수/결과 저장 방식을 유지한다. 최종 조립은 커밋된 행을 재조회한다.

## ERD 보완이 필요한 곳

- `outlook_metrics`: `analysis_id`, `factor_type`, `metric_key`, `numeric_value`, `text_value`, `observed_at`, `subject`, `tool_run_ids`. 한 분석·요인·지표당 한 행. 숫자와 문자열 값 중 정확히 하나 사용. 이름·단위·정렬은 카드 정의에서 조립.
- 관측일만 있는 자료를 자정 관측으로 바꾸지 않음. 날짜와 시간 있는 관측값의 저장·반환 형식을 마이그레이션에서 명시.
- 이슈 상세 제목과 항목 목록은 기존 ERD에 전용 저장 위치가 없음. 전망 본문과 같은 자료인지 화면 계약과 대조한 후 PR 10에서 명세·마이그레이션 함께 보완. 임의로 본문을 재사용하지 않음.
- 기능별 실행 진행은 대시보드 이벤트로 표시. 최초부터 새 상태 테이블을 추가하지 않음. 재시작 후 화면 결과는 DB의 분석 상태와 저장된 행으로 확인.
- 위 보완은 설계이며, 아직 ERD 파일·DB에 적용한 것으로 보지 않음.

## 저장과 갱신

- 분석 요청마다 분석 ID 확보. 도구 실행은 해당 분석에 연결. 실패한 호출도 기록.
- 감사 기록은 분석 실패 후에도 남음. 사용자에게 제공할 결과는 관련 행을 한 트랜잭션으로 저장하고 완료 상태로 전환.
- 전망의 여러 기능 응답은 독립적으로 수신하되 같은 분석 ID로 저장. 미완성 발행본을 최신 완성 화면으로 노출하지 않음.
- 오늘 움직임 설명은 누적. 선택 ID는 같은 ETF·거래일의 기존/신규 항목에서 최대 5개 선택. 과거 항목의 근거 ID도 계속 조회 가능.
- 전망은 새 발행본에 완성 본문 저장. 논점 ID는 유지하고 이전 발행본 보존. 오늘 업데이트는 본문 변경으로 생성하며 별도 에이전트 작성 응답 없음.
- 무변경·중복 요청·늦게 완료된 실행이 최신 정상 결과를 덮어쓰지 않는 검증 포함.
- 실제 원천 raw의 실행별 복제 저장은 요구하지 않음. 목 시나리오 파일은 테스트 자료로 관리.

## 대시보드 확인 순서

1. 시나리오·기준시각·요청 종류·이전 분석·초기 JSON.
2. 실제 모델 호출 여부, 실행 진행·오류, 시스템 프롬프트·에이전트 응답.
3. 툴명·인수·반환 결과·실행 ID. 숫자는 LaTeX 수식·관리자용 정의·출처, 뉴스는 기사 ID·제목.
4. DB에서 다시 읽은 관련 테이블·행·키·저장값. 예정 값과 커밋된 값 구별.
5. 기능별 최종 JSON과 화면 미리보기. 전망 수정은 이전/이후와 변경 기록 나란히 표시.

각 PR에 문서/구현/필요 테스트만 포함. CI·패키지 기반이 없는 기능은 필요한 최소 기반을 별도 선행 변경으로 분리하고 의존성을 PR 설명에 명시한다. 전체 기존 로컬 패키지를 편의상 한꺼번에 포함하지 않는다.

자동 검사는 외부 모델·운영 DB 없이 수행한다. 실제 모델 품질 검수는 유형 완성 시 실행한다. 클라우드 DB 적용 후에는 실제 저장·재조회·권한을 확인한다. 기능 변경마다 서버를 배포하지 않는다. 스키마 PR을 dev에 병합하면 기존 schema-migrate가 클라우드 DB에 적용하므로 병합 시점과 권한 준비를 맞춘다.
