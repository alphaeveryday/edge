# 분석 요청과 저장

가격변동 설명 또는 전망 요청에 목데이터와 고정 분석 시각을 넣는다. 서버가 이전 완성 분석을 조회하고 실제 에이전트를 호출한다. 호출된 툴의 인수·결과는 즉시 DB에 남으며, 에이전트 응답이 완성되면 관련 결과 행을 한 번에 저장한다. 최종 화면 JSON은 저장한 행을 다시 읽어 반환한다.

- 요청 종류: `movement`, `outlook`. 요청 ID는 서버가 생성.
- 이전 ID를 생략하면 직전 완료 분석 조회. 명시한 ID는 그 분석만 이어받고, `None`은 독립 시작. 이전 항목도 해당 분석의 연결 이력에서만 조회.
- 가격변동: 같은 ETF·같은 한국 거래일의 누적 후보와 직전 선정 ID·순서를 전달. 최초는 최대 5개를 선정하고, 수정은 직전 선정에서 바뀐 설명만 반영.
- 재선정 시 현재 수치와 달라진 기존 문장은 최신 수치·근거로 새 항목을 작성하고 이전 항목을 내림. 지표 상태 유지가 예전 숫자의 재사용을 뜻하지 않음.
- 전망: 직전 완성 분석 본문과 같은 날 업데이트를 전달. 편집 툴이 본문을 수정하고 변경 목록을 계산.
- 본문 수정의 `tool_run_ids`는 해당 논점의 전체 근거 목록을 교체. 바뀐 문장뿐 아니라 유지한 숫자의 근거도 함께 전달.
- 본문 문구 정정은 기존 편집 도구의 `text_replacements`에 문장 번호(1부터)와 `old_text`·`new_text`를 보낸다. 선택 문장에서 원문이 정확히 한 번 일치할 때 그 부분만 치환하며, 대상 밖 문자는 유지한다. 문장마다 한 치환만 허용하고 `sentences`·`updated_sentence_numbers`와 혼용하지 않는다. 빈 치환 목록·동일 문구 치환·모호한 원문은 거절한다. 센티먼트·전체 논점 근거·길이 검증과 배치 원자성은 그대로 적용한다. 문장 추가·삭제는 기존 전체 배열 방식도 지원한다. 의미 보존까지 코드가 판정하지는 않는다.
- 변경 논점 수에 따른 전체 재작성은 강제하지 않는다. 화면 상한을 넘는 구형 본문도 초과한 부분만 한 편집 묶음으로 수정한다. 배포 기준일 때문에 기존 완료 분석을 버리고 최초 분석으로 돌리지 않는다.
- 최초 전망은 완성 객체를 제출한다. 전망 수정은 객체의 바뀐 속성만 제출하고, 생략한 속성은 서버가 직전 값을 유지한다. 배열을 제출하면 전체 배열을 교체하며, `{}`는 변경 없음이다. 직전 이슈 상세도 첫 입력에 별도로 제공한다. 병합 후에는 기존 완성 응답과 근거 검증을 적용하며 저장·화면 조회 형식은 바뀌지 않는다. `response.json`은 모델의 수정 응답, `screen.json`과 `factor_details.json`은 저장 후 완성 화면이다. `change_condition`은 새 문구로 정정할 수 있으나 `null`로 삭제할 수 없다.
- 전망 수정의 요약·결론·요인 설명·이슈 상세 문구는 최종 응답의 `text_replacements`로 부분 치환할 수 있다. 고정된 고객 글 `field`, 배열에만 `item_number`(1부터), `old_text`·`new_text`를 지정하며 방향·감정·ID는 치환하지 않는다. 모든 대상은 직전 발행본 기준이고 일반 수정의 같은 필드·상위 배열과 충돌하면 거절한다. 이슈 항목·결론 키워드는 유지할 유효한 기존 근거와 새 근거를 포함한 전체 `tool_run_ids`가 필요하다. 같은 항목의 근거 목록이 서로 다른 치환도 거절한다. 원문 일치·병합·근거 오류는 기존 모델 수정 기회에 전달하고 발행 전 다시 검증한다. 이전 이슈 상세가 없는 발행본은 기존처럼 완성 이슈를 제출한다.
- 스티커는 모두 에이전트 판단. 자료 부족을 코드가 중립으로 바꾸지 않음.
- 동일 에이전트의 추론 모드를 켜고 가격변동 설명은 최초·수정 모두 effort=low, 전망은 최초·수정 모두 effort=high로 실행한다. 배치·수동·주말 여부로 강도가 달라지지 않으며 최초 전망의 조사·작성·필드 단계도 모두 high다. 서비스가 분석 종류에 따라 강도를 선택하고, worker는 실제 모델 호출의 강도를 manifest의 job.reasoning_effort에 기록한다. 모델 호출 전 실패에는 강도를 기록하지 않는다. 모델 environment.json에도 실제 강도를 기록한다. 추가 판정 에이전트는 없음. SDK의 budget_tokens 값은 DeepSeek가 무시하므로 비용·출력 길이의 상한으로 보장하지 않음. [호환 명세](https://api-docs.deepseek.com/guides/anthropic_api/)
- 수치 상세는 계산 툴 출력에서 생성. 이슈 상세는 에이전트가 생성하고 이슈 스티커는 부모와 일치.
- 중복 요청 ID는 새 모델 호출·새 결과를 만들지 않음. 실패 기록은 그대로 남김.
- 공개 분석의 provider 캐시 식별자는 자료 출처·분석 종류·ETF별로 고정한다. 공식 `CLAUDE_CODE_EXTRA_BODY` 설정으로 `metadata.user_id`만 지정하며, 실제 SDK 세션 ID와 작업공간은 매번 독립적이다. 일반 질문은 이 범위를 지정하지 않는다. 캐시는 적중 여부와 보존 시간을 보장하지 않으므로 최초 미적중 비용도 포함해 측정한다.
- 본문 변경과 독립 기능은 모두 준비된 뒤 발행. 실패하면 툴 감사 기록은 남고 미완성 화면은 발행하지 않음.
- 분석 도구 결과의 JSON이 6,000자를 넘으면 SDK에 큰 파일로 넘기지 않고 첫 원문 페이지와 현재 실행의 `result_id`를 전달한다. `workspace.read_tool_result`의 문자 offset/limit로 후속 페이지를 읽으며, 이어 붙이면 원래 JSON과 같다. 원본 감사 저장·`tool_run_id`는 유지하고 파일 읽기 권한은 넓히지 않는다. `result_id`는 발행 근거 ID가 아니며 현재 실행 동안만 유효하다. 초기 입력과 외부 검색 MCP의 전달 방식은 이 변경 범위가 아니다.

## 수정 분석의 조사 상태

최초 분석은 `cause-investigation`, 이전 발행물이 있는 수정은 `revision-investigation`으로 조사 범위를 정한다. 두 경로 모두 `hypothesis-analysis-workflow`와 `etf-hypothesis-analysis` 전문을 기본 제공한다. 수정은 직전 상태에서 달라진 부분과 중요한 미해결 질문만 조사한다. 기존 자료로 답할 수 있으면 재조회하지 않고, 이미 자료가 없다고 확인한 질문은 새 자료나 확인 가능한 시점이 생겼을 때 다시 연다. 같은 쟁점에서 새 근거가 나오지 않으면 검색어만 바꾸며 계속 탐색하지 않는다. 영향이 없으면 기존 글을 유지하며, 가설 비교 목록을 형식적으로 새로 만들도록 강제하지 않는다.

최초 전망만 `analysis-report-writing`으로 긴 보고서를 작성한다. 가격변동 설명(최초·수정)과 전망 수정은 `focused-analysis-writing`을 사용한다. 논점 수나 초안 단락 수를 채우지 않고 새 설명·변경점과 이유만 적으며, 수정에 영향받지 않은 본문과 근거 ID는 유지한다. 전망 수정은 선택 속성 응답을 사용하고, 가격변동 설명의 필수 출력 필드와 모든 발행 근거 검증 계약은 그대로 따른다.

이전 발행물과 이슈 상세는 첫 모델 입력에 직접 포함한다. `research_state`는 자료 ID·종류·도구명·조회 인자·관측시각·원문 길이의 `catalog`와 직전 작업의 미해결 질문만 처음 전달한다. 과거 검색 목록·문서 본문·수치 표·완료 답안은 첫 입력에서 반복하지 않는다. 저장된 원문을 요약하거나 삭제하는 것은 아니다. 필요한 자료는 `workspace.read_source(source="research_state", subject="자료 ID")`로 조회하며 별칭도 원본 ID로 해석한다. 큰 연구 원문은 기존 6,000자 문자 페이지와 `read_tool_result`로 읽고 이어 붙이면 전체 JSON과 같다. 원천 테이블 전체가 아니라 실제 열람한 페이지·성공한 조사 도구 출력·외부 검색 결과·질문과 메모를 보관한다. 메모와 미해결 질문의 `f1` 같은 번호는 해당 자료의 `reference_ids`로 원래 실행 ID에 연결하며, 이번 실행의 동명 번호와 구분한다.

`current_work`는 발행 당시 실제 workspace의 단계별 질문·메모 자료 ID와 분석 ID를 기록한다. 최초 추가 순서로 최신 메모를 추정하지 않으므로 같은 메모가 A→B→A로 돌아와도 현재 A를 가리킨다. 첫 입력에는 현재 미해결 질문과 메모 조회 ID만 포함한다. 조사 한계로 종료한 `structural_limit` 질문도 미해결로 포함해 새 증거가 나왔을 때 재검토할 수 있게 한다. 해결되거나 영향 없음으로 종료한 질문과 메모 원문은 필요할 때 조회한다. 구형 상태에 이 필드가 없거나 분석 ID가 다르면 `unavailable`로 표시하고 과거 메모를 최신 상태라고 선택하지 않는다. workspace 기록이 없으면 빈 stages를 기록하며 모든 활성 원문은 목록에서 계속 조회할 수 있다. 공개 API·DB 마이그레이션은 없다.

가격변동 최초는 `movement.yaml`, 같은 한국 거래일에 이전 발행물이 있는 수정은 `movement_revision.yaml`을 사용한다. 수정에는 전체 중요도·가격 방향 재정렬 지시를 주지 않는다. `previous_selected_item_ids`가 직전 발행본의 실제 ID와 표시 순서이며, `previous_items`에는 이미 제외된 후보도 있으므로 그 전체를 복원하지 않는다. 유효한 항목과 순서는 유지하고 사실·확정 여부·조건이 바뀐 설명만 교체한다. 다른 주제의 새 이슈를 넣으려고 유효한 기존 항목을 빼지 않으며, 여유가 있을 때 추가할 수 있다. 이는 모델 지시이며 서버가 의미 보존을 강제하는 것은 아니다. 저장된 명시적 `system_prompt`를 사용하는 실험은 기존처럼 그 프롬프트를 우선한다.

자료 생략은 삭제가 아니다. `workspace.retire_research_materials`가 자료 ID와 이유를 명시한 경우에만 다음 상태에서 제외한다. 제외 기록은 이어받고 원본 감사 기록은 남긴다. 최종 본문이나 재선정한 가격변동 항목이 계속 인용하는 자료는 제외할 수 없다.

서버가 발행 직전 `record_research_state:v1` 감사 기록에 현재 상태를 저장한다. 이 내부 기록은 모델 도구나 인용 가능한 근거가 아니다. 다음 실행은 발행까지 완료된 분석의 상태만 읽으므로, 발행 실패나 중단으로 남은 스냅샷은 채택하지 않는다. 기존 DB 스키마·권한을 사용하며 별도 마이그레이션은 없다.

상태 payload는 version 2이며, 동일한 도구 관측 원문을 재조회한 새 실행 ID는 기존 자료 ID의 별칭으로 기록한다. 제외한 원문의 지문도 보존한다. 서로 다른 검색 결과 묶음에 포함된 개별 기사까지 합치는 방식은 아니다. 배포되지 않은 로컬 실험의 version 1 상태는 제외 자료의 지문이 없어 안전하게 복원할 수 없으므로 명시적으로 거부한다. 운영의 기존 분석은 상태 기록 자체가 없으므로 기존 감사 기록 복구 경로를 사용한다.

첫 입력은 연구 자료 목록을 기준시각·현재 수치보다 앞에 배치한다. 선택적 `material_order` 목록으로 기존 자료 목록 뒤에 새 항목을 추가하며, 객체 키는 DB 저장 전후 같은 순서로 표시한다. 저장 원문의 문자열과 배열 순서·자료 값은 변경하지 않는다. 순서 목록이 없는 v2 상태는 자료 ID순으로 시작하고, 구버전 실행으로 목록이 낡으면 활성 `materials`를 기준으로 복구하며 경고한다. 이 목록은 성능 힌트이며 자료의 유지·제외나 최신 메모를 결정하지 않는다.

구형 분석은 연결된 완료 분석 이력의 감사 원문을 복구한다. 저장되지 않은 열람 페이지·메모·제외 판단은 `gaps`에 누락으로 표시하며 만들어 채우지 않는다. 새 수정 실행은 원문을 자동 압축하지 않는다. 입력 초과가 발생하면 오류와 원본 입력을 남겨 운영자가 사례를 보고하고 페이지 분할 등 해결안을 결정한다.

## 목데이터 계산의 임시 선택

- 전체 주식 편입목록·양의 비중 합 1을 사용. 누락·현금·비주식·비양수 EPS/BPS는 해당 계산 실패.
- 수급은 일별 당시 비중으로 합산한 뒤 빈도·연속을 계산. ETF 자체 수급과 구분.
- RSI14와 역방향 Williams14를 임시 지수로 사용. 확률이나 모델 점수로 표현하지 않음.
- 5년 PER 밴드는 문서대로 계산 보류, 카드 생략. 누락을 0으로 채우지 않음.
- 성공·실패·누락·미래 공개자료·상충 뉴스·후속 기사·중요도 역전 시나리오를 따로 검증.
