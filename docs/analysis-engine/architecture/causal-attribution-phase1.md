# 1단계 — 구조 완비와 0세대 원장

> 개념은 `causal-attribution-theory.md` 가 소유한다. 이 문서는 **실행 계약**만 소유한다.
> **1단계 목표:** 모든 구조와 틀을 확정하고, **연역만으로** 감사 가능한 영수증을 생산한다. 계수는 없다.

## 0. 한 장 요약

| 항목 | 결론 |
|---|---|
| 산출물 | **영수증**(자산) + 게시물(부산물). 두 산출물의 문턱이 다르다 |
| 밴드 출처 | **연역 상한만.** 계수는 2단계 |
| 스키마 단위 | **링크**. 사건이 아니다 |
| 검증 | VC1 연역 배터리 **완비** · VC2 네 규율 **완비** · VC3 최소(`breaker` 심각성 문턱) |
| LLM 역할 | **제안 분포.** 어휘·절차 제약 없음. 제출 형식만 강제 |
| 하네스가 아는 인과 | **시간 순서 하나.** 나머지는 부기와 산술 |
| 실패 처리 | **실패도 원장에 남는다.** 관측쌍은 가설이 죽어도 관측된 것 |

> **설계 가정: 모든 데이터가 존재한다.** §1–§8 은 데이터 결손을 설계 입력으로 삼지 않는다. 결손은 설계가 미리 피해 가는 것이 아니라 **런타임에 에이전트가 뱉는 것**이다(`unresolved` · `missing_inputs` · §6.5.2). 오늘 실제로 무엇이 있고 없는지는 **§10 가동 현황**에만 적고, 그것이 §1–§8 을 바꾸지 않는다.
>
> 이 분리가 없으면 설계가 현재 적재 상태에 맞춰 굳고, 데이터를 추가해도 능력이 늘지 않는다.

## 1. 관찰 — 전수

### 1.0 기준선 — $Y$ 의 정의

$Y$ 가 이 문서 전체의 설명 대상이므로 **여기가 틀리면 아래가 전부 틀린다.** §1.2 는 "시장/피어/고유 분해"라고만 했고 나머지가 미정이었다.

$$R_{i,t}=\alpha_i+\beta^m_i R_{m,t}+\beta^p_i R_{p,t}+\underbrace{Y_{i,t}}_{\textbf{설명 대상}}$$

| 항목 | 1단계 결정 | 이유 |
|---|---|---|
| 모델 | **2-factor** — 시장 + 피어 | 1-factor 면 업종 충격이 전부 고유로 새어 미설명이 부풀고 C칸 프레임 검정이 무의미해진다 |
| 시장 leg | `market_series` INDEX | 가용 |
| **피어 leg** | **동종 기업 집합**의 직교화 수익률. ETF 는 구성종목들의 피어 가중합 | 아래 |
| 추정창 | $[T{-}250,\ T{-}31]$ | **최근 30일 제외가 핵심** |
| 추정 | **Huber 로버스트 회귀** | 전수조사에서 사건일 제외는 불가능 — 대형주는 표본이 안 남는다 |
| $\hat\sigma$ | 추정창 잔차의 **MAD** $\times1.4826$ | 사건 오염에 강건 |
| 재추정 | 월 1회, `as_of` 이전 데이터만 | ① |

**ETF 의 피어는 구성종목이 아니라 구성종목들의 피어다.**

$$R_p(E)=\sum_i w_i\,R_{\text{peer}(i)},\qquad \text{peer}(i)\not\ni i$$

ETF 수익률 $\sum_i w_i R_i$ 와 피어 $\sum_i w_i R_{\text{peer}(i)}$ 는 **서로 다른 종목 집합**이라 순환이 없다. 개별 종목도 $\text{peer}(i)$ 가 정의상 자기를 제외하므로 leave-one-out 이 자동이다.

스키마는 이미 이 모양이다 — `price_decomposition_peer` 가 `peer_rank` · `peer_weight_ratio` · `peer_orthogonal_return` 을 담고, 피어 선정은 `policy_version` 이 버전 관리한다. **직교화(`orthogonal`)가 컬럼명에 박혀 있다** — 시장 성분을 뺀 뒤의 피어 수익률이라 시장 leg 와 이중계상되지 않는다.

**미결: 동종 집합 선정 정책.** `instrument` 에 업종 컬럼이 없고 구현체도 아직 없다(`analysis-engine` 에 `peer` 코드 0건). 후보는 상관 기반 랭킹 · `concept` 계층 · 외부 업종 매핑이며, `peer_rank` 가 랭킹을 전제하므로 상관 기반이 스키마와 가장 정합적이다. **1단계 선행조건 11번.**

**최근 30일 제외가 §6.0 과 직결된다.** 되돌림 창(5–20일)이 추정창에 들어가면 어제 사건의 되돌림이 *"정상 수익"* 으로 흡수되어 오늘 $Y_t$ 에서 사라진다. 그러면 후보로 편입해도 설명할 것이 남지 않는다. **기준선이 먼저 먹으면 귀속 자체가 불가능하다.**

$$\mathrm{AR}_{i,t}=Y_{i,t},\qquad \mathrm{CAR}_i[t_1,t_2]=\sum_{t=t_1}^{t_2}Y_{i,t}$$

**CAR 은 별도 계산이 아니라 $Y$ 의 창별 합이다.** $Y_t$ 는 `as_of` 에 존재하고 $\mathrm{CAR}_{post}=\mathrm{CAR}[T{+}1,T{+}n]$ 은 존재하지 않는다 — 같은 산술, 다른 창, 그래서 §1.3 의 두 시점 버전으로 갈린다.

### 1.1 대상

**모든 상장 종목 × 모든 거래일.** 트리거 게이트 없음.

프로덕션은 트리거 기반이지만 **학습 원장은 아니다.** 같은 파이프라인이고 표본 추출만 다르다.

### 1.2 관찰이 산출하는 것 (관찰 카드)

> **원칙: 모델이 계산할 수 없는 것만 준다.**

| 블록 | 내용 | 왜 코드가 주나 |
|---|---|---|
| **RESIDUAL 잔차** | $Y_{i,t}$ 와 분해 (시장 / 피어 / 고유) | 설명 대상 확정. 산술 |
| **PATH 모멘트** | $Y_t$ 수준 · 점프 시각 · **일중 분산비**(사건후~장마감 / 추정창) | in-context 계산 불가 |
| **FLOW 수급 이상** | 거래량 · 투자자별 순매수의 분위 | 계산 불가 |
| **EVENTS 사건 전수** | `available_at ≤ as_of` 인 사건 전량 + **커버리지 플래그** | 완결성 요건. LLM 회상 금지 |
| **CONTRIB 구성 기여** | 구성종목별 기여 분해 (ETF인 경우) | 계산 불가 |

**주지 않는 것:** 후보 원인 순위 ✕ · 채널 분류 ✕ · 유력 가설 힌트 ✕ · **과거 유사 반응 분포(ANALOG) ✕**

**ANALOG 를 생성자에게서 뺀 이유는 §6.1 맹검 규칙과 같다** — 크기 정보다. *"과거엔 $-3\%$ 였다"* 를 보면 실제 $Y$ 가 $-9\%$ 여도 $-3\%$ 를 설명하는 체인을 짠다. **ANALOG 는 검증자에게만 간다**(§6.2) — 약전과 정확히 같은 분리다.

**EVENTS 커버리지 플래그가 필수다.** "사건 없음"이 진짜 없음인지 뉴스 구멍인지 구분 못 하면 부작동 관측(§2)이 오염된다(theory U5).

### 1.3 카드는 두 시점 버전이 있다

$\rho$ 와 $\mathrm{CAR}_{post}$ 는 $T{+}n$ 관측이다. **제출 시점에 주면 미래 정보 누수**(① 위반)다.

| 버전 | 담는 것 | 누가 보나 |
|---|---|---|
| `card@as_of` | RESIDUAL · PATH(당일까지) · FLOW · EVENTS · CONTRIB | **생성자 · 검증자 공통** |
| `card@T+n` | $+\ \rho$ · $\mathrm{CAR}_{post}$ · $se$ · $T{+}n$ 분산비 | **채점 코드만** |

학습 코퍼스를 과거 데이터로 돌릴 때 $T{+}n$ 이 이미 존재하지만 **에이전트 세션에 등록되지 않는다.** ① 의 구체적 형태다.

### 1.4 카드는 누가 조립하나 — 전부 코드

에이전트는 조립에 관여하지 않는다. **카드가 코드 산출물이라는 것이 ④ "후보 집합은 코드" 의 실제 구현**이다 — 에이전트가 카드를 만들면 체리피킹이 가능해진다.

| 블록 | 비용 | 전수 생성 |
|---|---|---|
| RESIDUAL · PATH · FLOW · CONTRIB | 순수 산술 | ✅ 저장. 2,600종목 × 250일 = 650k행/년 |
| EVENTS | PIT 조인 | ✅ 저장. 커버리지 플래그 동반 |

**관찰 산출물은 전수 저장하고, 카드 조립은 표본에 대해서만 한다.** 전수 저장이 필요한 이유는 미설명 잔량 분포(프레임 검정)가 전 패널에서 계산되어야 하기 때문이다.

## 2. 표본 — 2×2 층화

전수 관찰은 산술이지만 **가설 루프는 전수가 될 수 없다**(LLM 비용). 그 사이에 추출이 있고, **어떻게 뽑느냐가 계수의 편의를 결정한다.**

| | 움직임 큼 | 움직임 없음 |
|---|---|---|
| **사건 있음** | **A** 주 표본 | **B** 부작동 — 콜라이더 방어 |
| **사건 없음** | **C** 미설명 분포 — 프레임 검정 | **D** 대조군 — 교정·위약 |

| 칸 | 1단계 최소 목표 | 없으면 |
|---|---|---|
| A | 트리거 전량 | — |
| **B** | ≥ 40건 | $\Pi_\ell$ 이 체계적으로 **과대추정** 쪽으로 치우침 (콜라이더 편의) |
| **C** | ≥ 40건 | "사건으로 설명 가능한 비율"을 영원히 모름 |
| **D** | ≥ 40건 | 교정·위약 표본 없음 |

프로덕션은 A만 돌린다. **학습 표본은 네 칸을 층화 추출한다.**

**C칸은 LLM 을 태우지 않는다.** 사건이 없으면 사건 기반 가설이 성립하지 않고, 남는 것은 수급 체인 하나뿐이라 고정 처리가 가능하다. 40건에 LLM 을 태우는 것보다 **전수 패널에 고정 수급 체인을 돌리는 쪽이 정보가 훨씬 많다.** LLM 예산은 A·B·D 로 간다.

## 3. 하네스 — 네 규율

> **하네스는 인과를 판정하지 않는다. 인과 판정이 가능한 조건을 보존한다.**

각 규율은 추론자가 당길 수 있는 레버를 하나씩 제거한다.

### ① 시간 봉인 — 레버: 미래를 본다

- `as_of` 는 관찰 단계에서 바인딩되고 실행 내내 **불변**
- **모든 도구는 `as_of` 가 부분적용된 형태로만 등록된다.** 호출자가 `as_of` 를 넘기는 시그니처가 **존재하지 않는다**
- 그와 **별도로** 반환된 모든 객체에 대해 경계에서 `available_at ≤ as_of` 재확인

**왜 이중인가** — 미래 정보 누수는 **조용히 결과를 좋게 만든다.** 다른 버그는 성능을 떨어뜨려 눈에 띄지만 lookahead 는 성공으로 위장된다. 실패가 성공으로 위장되는 유일한 항목이다.

### ② 커밋 순서 — 레버: 결과를 보고 시험을 고른다

**먼저 쓴다 → 그 다음에야 읽는다.**

| 먼저 쓴다 | 그 다음 읽을 수 있다 |
|---|---|
| 좌표계 — `as_of` · targets · **$Y$** | 후보 카드 |
| 가설 명제 | 카드 상세 |
| **검정 명세** | **약전 구간** · 검정 도구 |
| 하강 상수의 **출처** | 그 상수의 **값** |
| 세분 축 | 조각별 잔차 |

**append-only + 해시 체인.** 이게 없으면 *"우리는 먼저 선언했다"* 가 반증 불가능한 주장이 된다. 감사는 순서를 **신뢰**하는 게 아니라 **검증**해야 한다.

**세 번째 행이 자기확증을 막는다.** 약전을 먼저 보여주면 약전에 있는 링크로 끝나는 체인을 짜게 되고, 재무 경로가 아닌 설명(수급·규제·심리)이 구조적으로 덜 제안된다. 약전은 자기가 이미 가진 링크만 계속 강화한다. **명세가 커밋된 뒤에만 조회한다** — 세션이 같아도 해시 체인이 순서를 증명한다.

**네 번째 행이 정련의 과적합을 막는다** — *"마진을 어느 기간으로 잡을까"* 를 값을 보고 정하지 못한다.

### ③ 출처 환원 — 레버: 수를 지어낸다

**모든 수량은 네 종류 중 하나로 환원되어야 한다.**

| 라벨 | 요구 | 없으면 |
|---|---|---|
| `observed` | `ref:` — 카드 항목 또는 도구 반환 id | 날조 |
| `derived` | `formula:` + 입력 id 전량 | 재계산 불가 |
| `sampled` | `seed:` + 분포 명세 | 재현 불가 |
| `assumed` | 선언. **`assumed_items` 에 전량 열거** | 숨은 가정 |

**`assumed` 는 허용되지만 숨기는 것은 허용되지 않는다.** 영수증의 `assumed_items` 가 *"숨은 것이 없다"* 의 증명이고, 가정 하나당 `confidence` 가 내려간다.

### ④ 후보 집합은 코드 — 레버: 유리한 후보만 고른다

사건 열거·PIT 클램프·커버리지 판정은 **전부 코드**다. LLM 은 **주어진 집합에서 고르기만** 하고 없는 사건을 떠올릴 수 없다.

카드에 없는 사건을 인용하면 즉시 거부된다(§6.1). 이것이 §1.4 가 카드 조립을 코드로 못박은 이유다.

## 4. 스키마 — 소급 불가하므로 지금 확정한다

### 4.1 링크

**스키마 단위는 사건이 아니라 링크다.** 사건은 재사용되지 않지만 링크는 재사용된다.

```yaml
link:
  link_id:      str
  from:         {node: str, unit: str}
  to:           {node: str, unit: str}
  transfer:
    name:       str
    unit:       str
    form:       scalar | threshold | saturating | custom   # 기본 scalar
    monotone:   "+" | "-" | none                            # 선언. 검사 대상
  interval:                                  # 2단계에서 채워진다
    predict:    "from, z → [lo, hi] (신뢰수준 명시)"
    fit_ref:    str | null       # verified 이면 적합 아티팩트 id
  covariates:   {..}             # 맥락 벡터 전량. 큐레이션 금지 (§4.4)
  domain:       str              # 정의역. 밖에서 쓰면 게이트 실패
  upper_bound:  float            # ū_ℓ. 연역 배터리 입력. 정의에서 나온다
  status:       proposed | verified
  tier:         T1 | T2 | T3 | null
```

**`upper_bound` 는 `interval` 과 별개다.** 상한은 **정의에서 연역**되고(매출감소 ≤ 계약금액, 마진 ≤ 1), 적합 결과가 아니다. `proposed` 링크는 상한만으로 구간을 만든다 — 이것이 0세대가 도는 방식이다.

**링크 동일성은 `(from.node, to.node, transfer.name)`** 이다. 이 셋이 같으면 사건이 달라도 같은 링크이고, 그래서 영수증이 링크별로 모인다.

#### 링크는 곱셈이 아니다 — 함수다

$$\text{to}=f_\ell(\text{from};\ \theta_\ell)$$

**$f_\ell$ 이 스칼라 곱인 것은 가장 흔한 경우일 뿐 요구사항이 아니다.** 배터리가 실제로 요구하는 것은 둘뿐이다.

| 검사 | 진짜 요구 | 곱셈이 필요한가 |
|---|---|---|
| **BOUND** | $\sup_{\theta\in\Theta} f_\ell$ 를 낼 수 있을 것 | ✕ — 단조면 끝점, 아니면 MC max |
| **INVERT** | 한 모수에 대해 풀 수 있을 것 | ✕ — 단조면 이분탐색 유일해, 아니면 해집합 |
| DIM · TIME · CONSIST | 단위 · 순서 · 구조뿐 | ✕ |
| MC | 평가 가능할 것 | ✕ |

**요구는 계산 가능성이고, 단조성은 유일해를 위한 편의다.** 단조가 아니면 INVERT 가 해집합을 내고 그만큼 심각성이 낮아진다 — 금지가 아니라 대가다.

`form` 을 선언하게 하는 이유는 **선언이 검사 대상이 되기 때문**이다. `monotone: "+"` 라고 써놓고 표본에서 부호가 뒤집히면 CONSIST 실패다.

#### 분기는 체인이 아니라 몫으로 쪼갠다

*"규제 → 매출 $-300$억"* 과 *"규제 → 비용 $+100$억"* 은 합류한다. 체인을 DAG 로 만들 수도 있지만 그러지 않는다.

$$\underbrace{\text{규제·매출경로}}_{\text{share}_1}+\underbrace{\text{규제·비용경로}}_{\text{share}_2}+\text{미설명}=Y$$

**가법은 예산 항등식이 이미 담당한다.** 체인 내부를 경로 하나로 유지하면 링크 동일성 · MC · INVERT 가 전부 단순해지고, 표현력은 몫을 나누는 것으로 회수된다. DAG 를 도입하면 얻는 게 없고 링크 재사용 계측이 깨진다.

### 4.2 노드 카탈로그 — DB 위의 온톨로지 도구

**정적 문서가 아니다. DB 에서 생성되고 데이터가 늘면 같이 자라는 도구다.**

> *"이 개념에 붙일 수 있는 데이터가 우리 DB 에 있는가, 있으면 언제부터 · 얼마나 · 어떤 단위로."*

에이전트는 DB 에 직접 붙지 않는다. 카탈로그가 **무엇이 있는지**를 주고 도구가 **어떻게 꺼내는지**를 가진다.

#### 왜 필요한가 — `assumed` 를 검증 가능하게 만든다

> `assumed` 가 *"진짜 데이터가 없다"* 인지 *"찾기 귀찮았다"* 인지 구분할 수 없으면, 그 라벨은 검증 불가능한 자기신고다.

`confidence` 는 `assumed` 개수로 내려간다(③). 카탈로그가 없으면 **게으름과 데이터 부재가 같은 신호를 낸다.** 이 설계 전체가 자기신고를 검증 가능한 것으로 바꾸는 작업인데 여기만 예외가 된다.

| 노드 상태 | `assumed` 판정 |
|---|---|
| `observables: []` | **정당** → 리뷰큐 `missing_inputs` 로 집계 |
| observable 있음 + `lag` 상 `as_of` 부재 | **정당** |
| observable 있음 + 조회 가능 | **부당** → 하강 게이트 롤백 |

**둘째: 비교 대수의 $q$ 값역이 카탈로그다**(§6.2.2). 없으면 검증자가 없는 데이터로 검정을 짜고 실행 시점에 실패하며, *"검정 불가"*(`unresolved`)와 *"검정 실패"*가 구분되지 않는다 — §6.5.1 `QUALITATIVE` 경로의 전제가 무너진다.

#### 항목

```yaml
node:
  name:         매출
  unit:         KRW
  bound:        [0, inf]            # 연역 상한. 링크 bound 자동 공급
  observables:
    - series:      revenue_quarterly
      granularity: 분기 · 기업
      lag:         공시 후 45일       # 수작업
      coverage:    0.94              # 배치 실측
      panel:       true              # 전 종목 → 횡단면 검정 가능
      revisable:   true              # 정정 공시 → PIT 조회 필수. 수작업
```

`lag` 없이는 `as_of` 에 그 값이 있는지 모르고, `panel` 없이는 횡단면 검정을 짤 수 있는지 모르며, `revisable` 없이는 정정 전 값을 집어 **미래를 본다.**

#### 도구 표면

에이전트 컨텍스트에 전량을 넣지 않는다 — 노드가 늘면 안 들어간다.

| | 어디에 | 무엇 |
|---|---|---|
| **요약** | 컨텍스트 | 노드 이름 + 접지 여부 한 줄씩 |
| `catalog.node(name)` | 도구 | observables 전량 + `lag`/`coverage`/`panel` |
| `catalog.search(concept)` | 도구 | 이 개념에 붙는 시리즈가 있나 |
| `catalog.missing(node)` | 도구 | 없으면 무엇이 있어야 하는가 |

**생성자는 카탈로그를 보지 않는다.** 자연어 명제만 내므로 접지 가능성을 알 필요가 없고, 알면 *"데이터가 있는 가설"* 쪽으로 편향된다. 약전과 같은 분리다 — 카탈로그는 검증자부터.

#### 스키마와의 관계 — 대부분 자동 생성

$$\text{카탈로그}=\underbrace{\text{인과 어휘}}_{\text{체인의 양}}\ \times\ \underbrace{\text{접지 가능성}}_{\text{DB 시리즈}}$$

어느 쪽도 상대를 포함하지 않는다.

| | 스키마 | 카탈로그 |
|---|---|---|
| `price_daily.close_price` | ✅ | ✅ 노드 `주가` 의 observable |
| `price_daily.data_version` | ✅ | ✕ 운영 메타 |
| **`영업이익률`** | ✕ 컬럼 없음 (파생) | ✅ 노드 |
| **`파이프라인 가치`** | ✕ | ✅ 노드, `observables: []` |
| `lag` · `revisable` · `bound` | ✕ DDL 에 없음 | ✅ |

세 번째·네 번째 줄이 요점이다. **DB 에 없는 개념도 노드로 존재해야** 그것이 없다는 사실이 기록되고 리뷰큐로 간다.

손으로 다 쓰면 스키마와 **반드시 드리프트한다.** 대부분은 유도된다.

| 필드 | 출처 | 자동 |
|---|---|---|
| `series` · `granularity` | 테이블 · 컬럼 · PK grain | ✅ 마이그레이션에서 |
| `coverage` · `panel` | 실측 | ✅ 배치 쿼리 |
| `unit` | `COMMENT ON COLUMN` · 타입 | ⚠️ 반자동 |
| **노드 어휘 · 노드↔시리즈 매핑** | 의미론 | ❌ 수작업 |
| **`lag` · `revisable`** | 정책 사실 | ❌ 수작업 |

#### 데이터를 추가하면 자동으로 자란다

$$\text{소스 추가}\ \to\ \text{마이그레이션}\ \to\ \underbrace{\text{매핑 · lag 주석}}_{\text{수작업 2줄}}\ \to\ \text{배치가 coverage 실측}\ \to\ \textbf{다음 실행부터 에이전트가 본다}$$

**프롬프트도 코드도 안 고친다.** 데이터를 붙이는 것만으로 에이전트의 검정 능력이 늘어난다 — 카탈로그가 도구이고 $q$ 의 값역이기 때문이다.

역방향도 닫힌다.

$$\text{리뷰큐 } \texttt{missing\_inputs}\ \to\ \text{수집 우선순위}\ \to\ \text{소스 추가}\ \to\ \text{막혔던 검정 해금}$$

**무엇을 수집할지가 추측이 아니라 측정으로 정해지는 이유가 이 루프다.**

#### v1 에서는 거의 빈다 — 그래도 만든다

재무제표가 없어 `매출` · `영업이익` · `배수` 가 전부 `observables: []` 다. **크기가 아니라 존재가 요점**이고, *"매출은 노드로 존재하나 관측이 0개"* 라는 기록이 위 루프의 시작점이다. 비어 있음을 기록하지 않으면 무엇을 수집해야 하는지 영원히 추측이다.

### 4.3 영수증 — 제약 하나의 형식

```yaml
receipt:
  # 조건 — PIT 봉인된 맥락
  as_of:            timestamp
  instrument:       str
  Y:                float                    # 설명 대상
  baseline_ref:     str                      # §1.0 기준선 아티팩트 id
  card_hash:        str

  # 주장
  hypothesis:       str                      # 자연어 명제 (§6.1)
  chain:            [link_instance]          # 구체화 산출. 없을 수 있음
  share_band:       {lo, hi} | null          # **코드 산출** (MC 합성). LLM 출력 아님
  unexplained_band: {lo, hi}                 # 표본별 항등식 폐쇄 결과

  # 검증
  rejected_nulls:   [{null, test, logLambda}]
  surviving:        [str]
  tests_attempted:  int
  logLambda_total:  float                    # 다중검정 보정 후
  argument_score:   {grounding, assumption_density, evidence_grade}

  # 감사
  order_log:        [hash]                   # ② 커밋 순서
  tool_log:         [{call, args, ret, seed}]
  assumed_items:    [str]                    # ③ 숨은 것 없음의 증명
  carried_forward:  [{event_id, band}]       # §6.0 과거 사건 몫
  beta_version:     str | null               # 2단계. 1단계는 null
  contamination:    single_cause | multi_cause | confounded
  verdict:          PUBLISH | QUALITATIVE | HOLD | UNCERTAIN | REVIEW_QUEUE
```

**`raw` 관측과 `derived` 를 분리해 기록하는 이유:** $\Pi_\ell$ 은 **원재료(노드 실측치)에서** 적합한다. 예상은 회귀변수가 아니다(theory §10.3). 이 분리가 순환을 없앤다.

### 4.4 공변량은 큐레이션하지 않는다

승격 게이트의 이질성 검정은 **기록한 축으로만** 돌아간다. 진짜 이질성이 미기록 축에 있으면 영원히 못 찾는다. **저장은 싸고 후회는 비싸다** — 중간 수량 전량을 기록하는 것과 같은 논리다.

**`contamination` 이 없으면 나중에 못 쓴다.** 계수는 `single_cause` 에서만 추정한다.

## 5. 검정 — 배터리 6종이 바닥, 샌드박스가 천장

**연역은 값을 요구하지 않고 경계를 요구한다.** 접지 0으로 작동하고, 이것이 0세대가 자립하는 이유다.

| # | 검사 | 필요한 것 | 실패 시 |
|---|---|---|---|
| **DIM** | **차원 합성** — 체인 단위가 무차원으로 닫히는가 | 단위 선언뿐 | 즉사 |
| **IDENTITY** | **항등식** — $\sum\text{share}+\text{미설명}=Y$ | 정의뿐 | 즉사 |
| **BOUND** | **상한 대조** — 체인 상한 $\ge$ 주장 몫 | 링크 상한 (곱이면 $\prod\bar u_\ell$) | 즉사 |
| **INVERT** | **함의 모수 역산** — 관측이 성립하려면 어떤 모수가 필요한가 | 외부 분포 하나 + 그 모수에 대한 가역성 | 범위 밖이면 즉사 |
| **CONSIST** | **내부 모순** — 링크 간 양립 불가 | 체인 구조뿐 | 즉사 |
| **TIME** | **시간 순서** — 원인 ≺ 결과, `available_at ≤ as_of` | 타임스탬프뿐 | 즉사 |

### 5.1 INVERT 가 가장 강하다 — 예측하지 말고 뒤집는다

$$4{,}800억 = 850억\times\tau\times m\times k\times(1-\pi)\quad\Rightarrow\quad k^\ast=80.4$$

동종 배수 중앙값이 12 면 **6.7배 초과**라 접지 없이 기각된다. 필요한 건 동종 배수 분포 하나뿐이고 그건 체인 접지가 아니라 시장 사실이다.

**그리고 역산은 관측을 입력으로 받으므로 맹검이 필요 없다.** 정방향 예측과 달리 잔차를 봐도 무방하다.

### 5.2 패딩 공격과 방어

링크를 늘려 필요값을 4개로 쪼개면 각각은 그럴듯해 보인다.

**방어:** 링크마다 $\bar u_\ell$ 을 선언해야 하고 **상한들의 곱이 함의값을 포함해야** 한다(BOUND). 상한이 1 근처인 링크를 추가해도 곱이 안 커진다. AC3 과 같은 논리다.

### 5.3 연역도 심각성을 생산한다

$$p_c\approx\frac{\text{연역 허용 구간}}{\text{선험 가능 구간}},\qquad \log\Lambda=-\log_2 p_c$$

상한이 좁을수록 통과가 어렵고, 통과하면 증거가 크다. **측정 없이 밴드를 좁힌다.**

### 5.4 합성은 MC 다 — 구간 산술이 아니다

링크 상한을 구간 산술로 곱하면 최악 코너가 누적돼 밴드가 폭발한다. **각 링크 구간에서 표집해 체인을 통과시킨다**(theory §6.4.1). 링크 4개 $\pm30\%$ 기준 밴드가 2.6배 좁아지고 $\approx2.1$ bit 를 더 번다 — **PR4 달성 가능성이 여기서 갈린다.**

### 5.5 배터리는 바닥이지 천장이 아니다

6종은 **모든 체인에 걸리는 최소 집합**이다. 필요한 검정은 가설마다 다르다.

| | 6종 배터리 | 검증자 검정 |
|---|---|---|
| 적용 | 전 체인 공통 | 이 가설 전용 |
| 작성 | 고정 | **검증자가 짠다** (§6.2) |
| 예 | `DIM` · `INVERT` | 비교 대수로 조립된 이 가설 전용 검정 (§6.2.2) |

**6종만 두면 검정력이 가설 종류에 무관하게 평평해진다** — 그건 검정이 약하다는 뜻이다.

## 6. 실행 — 4단계 계약

### 6.0 과거 사건은 차감하지 않고 후보로 넣는다

어제 사건의 잔여가 오늘 $Y_t$ 에 섞여 있다. 처리 방법이 둘인데 **하나만 안전하다.**

| | 방식 | 판정 |
|---|---|---|
| **차감** | 잔여를 추정해 빼고 나머지만 설명 | ❌ **그 추정이 검정을 안 받는다** |
| **후보 편입** | 과거 사건을 오늘의 후보 목록에 넣는다 | ✅ |

**왜 차감이 안 되는가 — 얼마를 뺄지 모른다.** $\rho$ 는 총 되돌림 비율을 주지만 **감쇠 프로파일**은 주지 않는다.

| 프로파일 | $T{+}1$ 기여 |
|---|---|
| 10일 균등 | $+0.24$pp |
| 반감기 3일 지수 | $+0.49$pp |

**2배 차이**이고 프로파일은 `assumed` 다. 차감하면 이 오차가 조용히 미설명에 섞여 ③ 출처 환원과 예산 항등식을 동시에 우회한다.

**후보 편입은 `EVENTS` 열거 창을 $T{-}n$ 까지 넓히면 끝이다.** 새 컴포넌트가 필요 없다.

| | 차감 | 후보 편입 |
|---|---|---|
| 예산 항등식 | 우회됨 | **닫힌다** |
| 검정 | 안 받음 | **받는다** |
| MC | 점추정 | **밴드** |
| `일간감쇠율` | 영원히 `assumed` | **승격 가능한 링크** |

**부호 함정:** 되돌림은 반대 방향이라 오늘의 *새* 움직임이 raw $Y_t$ 보다 **클** 수 있다. $Y=-1.5$pp 에 되돌림 $+0.24$pp 면 새 움직임은 $-1.74$pp 다.

**카드에는 사건 식별자와 확정 여부만 넣는다.** 과거 영수증의 금액·체인은 LLM 에게 가지 않고, 값은 코드가 바인딩한다 — 영수증 전문 비노출 규율과 충돌하지 않게.

**약전은 여기에 관여하지 않는다.** 약전에서 체인을 조회해 오늘 사건에 적용하면 체인 사전이 되어 ② 를 위반한다. 약전이 일을 덜어주는 방식은 차감이 아니라 **밴드 축소**뿐이다.

### 6.1 제출 — 생성자 · LLM, 도구 0

**출력은 자연어 명제 한 문장이다. 체인이 아니다.**

```yaml
hypothesis: "07-15 발의된 반도체 소재 수입규제가 042700 의 하락을 설명한다"
targets:    [042700]
cites:      [evt_8f2]        # 카드에 있는 사건만 인용 가능
```

체인 구성을 생성자에게 시키면 **정량화가 가능한 가설만 나온다.** *"규제 발의자가 이 기업에 적대적이었다"* 같은 사실 연쇄는 처음부터 체인 모양이 아니고, 체인을 요구하면 그런 가설이 아예 제안되지 않는다.

| 게이트 | |
|---|---|
| 카드에 없는 사건 인용 | 즉시 거부 (④) |
| 복합 가설 | 거부 — 원인이 둘이면 두 건으로 제출 |
| 크기 주장 | **금지** — 정량화는 검증자 몫 |

> **맹검 규칙:** 정방향 크기 예측을 게이트로 쓸 경우 카드에서 **부호만 남기고 크기 관련 전량을 가린다** — $Y$ 수준뿐 아니라 일중 분산비·수급 분위도 크기 정보다. 역산(INVERT)만 쓰면 맹검 불요. **1단계는 INVERT 를 기본으로 하고 맹검은 선택**으로 둔다.
>
> **용어:** 이 문서에서 **경로**는 인과 전이 경로(링크 연쇄)만 가리킨다. 가격 궤적 통계(되돌림 $\rho$ · 분산비 · 점프 시각)는 **PATH 모멘트**라 부르고 경로가 아니다.

### 6.2 검증 — 검증자 · LLM, 자유 탐색 루프

**파이프라인의 무게중심이다.** 추상 명제를 받아 관측 가능한 형태로 내려가고, 경쟁 가설을 세우고, 검정하고, 반복한다.

#### 6.2.1 라운드 구조

| # | 하는 일 | 주체 |
|---|---|---|
| 1 | **구체화** — 추상 명제를 관측 명제로. 메커니즘 분기(매출·비용·심리·수급) | LLM |
| 2 | **경쟁 가설 열거** — 무엇이 이 관측을 똑같이 설명하는가 | LLM |
| 3 | **검정 명세 커밋** — 약전 조회 **전에** 해시 커밋 | 코드가 순서 강제 |
| 4 | 약전 · 도구 · ANALOG 조회 → 실행 → $\log\Lambda$ | 코드 |
| 5 | 결과 수신 → 다음 라운드 또는 종료 | LLM |

**3이 자기확증 방어의 전부다.** 검증자는 약전을 보지만 **명세를 먼저 커밋한 뒤에만** 본다. 세션이 같아도 해시 체인이 순서를 증명한다(②). 이 규율이 없으면 생성자에게서 막은 편향이 검증자로 옮겨올 뿐이다.

#### 6.2.2 검정 명세 — 비교 대수

**제약의 근거는 LLM 을 좁히려는 것이 아니다.** 자유 텍스트 검정을 배제하는 이유는 하나뿐이다.

> **$\neg h$ 가 패널에서 계산 가능해야 한다.**

같은 명세를 전 패널·전 기간에 돌려 **무조건부 분포**를 낼 수 있어야 $\log\Lambda$ 의 분모가 실측된다(§6.2.3). 이 경계보다 조금이라도 더 조이면 부당한 강제다. 그래서 검정 유형을 열거하지 않고 **대수**를 준다.

$$\text{검정}=\bigl(\,\underbrace{A}_{\text{대상}},\ \underbrace{B}_{\text{대조}},\ \underbrace{q}_{\text{수량}},\ \underbrace{w}_{\text{창}},\ \underbrace{\text{agg}}_{\text{집계}}\,\bigr)$$

| 성분 | 값역 |
|---|---|
| $A,B$ | 필터 조합 — 종목축(self · peers(tier) · 속성필터 · 전체) × 시점축(사건일 · 상대창 · 동일조건 과거) × **사건축(사건 없음 · 사건 있음 · 유형별)** |
| $q$ | **카탈로그의 observable 전량** (§4.2) |
| $w$ | 창. `as_of` 클램프 적용 |
| agg | `mean` `median` `frac_above` `frac_below` `count` `corr` `rank_pct` `argmax` |

**대조 형식 둘**

$$\text{단순: } q(A)\ \text{vs}\ q(B) \qquad\qquad \text{이중차분: } [q(A_1)-q(A_2)]\ \text{vs}\ [q(B_1)-q(B_2)]$$

```yaml
tests:
  - id:  T1
    targets: "업종 수요 충격 분기"
    A:   {universe: self,          when: event_day}
    B:   {universe: peers(T1),     when: event_day}
    q:   residual_daily
    agg: frac_below_zero
    h_predicts: [0.70, 1.00]
```

**앞서 쓴 "4종"은 검정 유형이 아니라 데이터 원천 이름이었다** — 층위가 틀렸다. 대수에서는 전부 한 형태의 인스턴스다.

| 옛 표기 | $A$ | $B$ | $q$ |
|---|---|---|---|
| 피어 동조 | self · 사건일 | peers(T1) · 사건일 | 잔차 |
| 수급 분위 | self · 오늘 | self · 과거 250일 | 외국인 순매수 |
| 창 내 타사건 | 창 내 사건 | ∅ | count |
| 과거 유사 반응 | self · 오늘 | 동일조건 과거 | 잔차 |

**원천 4개에서 조합은 수백 개**이고, 옛 열거로는 불가능했던 것들이 자연히 나온다.

| 새로 가능 | 표현 |
|---|---|
| 규제 노출 조건부 횡단면 | $B$ 에 속성필터 추가 |
| 이중차분 | 이중차분 형식 |
| 반응 시점 배치 | $w=[T{-}5,T{+}5]$, agg `argmax` |
| 용량 대비 반응 비선형성 | $q$ 를 바꿔가며 `corr` |

#### 반사실 대조군이 없으면 사건 가설을 칠 수 없다

*"이 사건이 원인"* 을 검정하는 유일한 방법은 **사건이 없던 셀들의 $Y$ 분포와 비교**하는 것이다.

$$B=\texttt{no\_event}\ \Longrightarrow\ \text{"사건 없이도 이만큼 움직이는가"}$$

1회전 E2E 에서 이 대조군이 대수에 없었고, 그 결과 검정 대부분이 $B=\texttt{all}$ 또는
$B=\texttt{same\_day}$ 로 흘러 *"이 셀이 극단인가"* 만 쟀다. $\log\Lambda$ 가 정답 라벨과
**무상관**이었다(findings §1). 사건축 분할은 선택이 아니라 **사건 가설 검정의 전제**다.

#### $q$ 값역은 온톨로지에서 나온다

$q$ 를 가격 파생만으로 두면 어떤 가설에도 같은 검정이 나온다. 사건 온톨로지의 축이 그대로 $q$ 가 된다.

| $q$ | 무엇을 치나 |
|---|---|
| `has_type(T)` | *"이 유형 사건이 원인"* |
| `measure_role(R)` | *"규모가 커서 컸다"* — 계약금액 · 거래금액 |
| `frac_first_in_thread` | *"새 소식이라 컸다"* — 신규성 |
| `n_types` · `n_roles` | *"여러 사건이 겹쳤다"* |
| `hours_since_last_event` | *"직전 발생이라 즉각 반응"* |

**대수 밖은 `unresolved` 로 나간다.** 무엇이 반복해서 막히는지가 대수 확장의 근거이고, 이때도 확장 판단 기준은 같다 — *"그 검정의 무조건부 분포를 패널에서 낼 수 있는가."*

**`null_predicts` 는 검증자가 쓰지 않는다.** 부르게 두면 넓게 불러 게이트를 통과하는 게이밍 표면이 된다.

#### 6.2.3 판별력 게이트

$$\log\Lambda_{\max}=\log_2\frac{\text{ANALOG 실측 분포 폭}}{\bigl|\,[a_h,b_h]\cap\text{실측 분포}\,\bigr|}$$

| $h$ | 실측 $\neg h$ | 겹침 | $\log\Lambda_{\max}$ | |
|---|---|---|---|---|
| $[0.70,1.00]$ | $[0.40,0.60]$ | 0 | $\infty\to$ **6 bit 캡** | ✅ |
| $[0.50,1.00]$ | $[0.40,0.60]$ | 0.10 | $1.0$ | ✅ 경계 |
| $[0.30,1.00]$ | $[0.40,0.60]$ | 0.20 | $0$ | ❌ 거부 |

**게이트 $\ge1$ bit.** 검증자가 통제하는 것은 $h$ 구간뿐이고 **좁게 부를수록 통과하고 크게 번다.** 넓게 불러 안전을 사면 게이트에서 걸린다.

**대칭성:** 관측이 실측 분포 안이면서 $h$ 밖이면 $\log\Lambda<0$ 로 가설이 깎인다. 센 검정은 센 살해자다.

#### 6.2.4 동어반복 금지 — 조작적 정의

> **모든 검정은 카드 밖 관측을 최소 하나 인용해야 한다. 도구 호출 0 인 검정은 자동 거부.**

**형식 요건만으로는 새어 나간다.** $B=\texttt{all}$ 은 형식적으로 카드 밖이지만, $q$ 가 카드에
이미 표시된 수량이면 *"이 셀이 극단인가"* 이고 어떤 가설에도 같은 답을 준다. 대수 층에서 막는다.

$$B=\texttt{all}\ \wedge\ q\in\{\text{카드 노출 수량}\}\ \Rightarrow\ \textbf{거부}$$

같은 $q$ 라도 $B$ 가 **가설 조건부 부분집합**(`no_event` · `same_event_type`)이면 허용된다 —
그때는 대조가 가설에서 나오기 때문이다.

카드 안의 값으로 계산되는 진술은 이미 관측된 것이므로

$$\Pr(\text{관측}\mid h)=\Pr(\text{관측}\mid\neg h)=1\quad\Rightarrow\quad \log\Lambda=0$$

*"외국인이 935억 순매도했으니 수급 때문"* 은 카드 재진술이다. **정보는 카드 밖에서만 들어온다.**

#### 6.2.5 사실 연쇄 추론 — 연역은 항등식만이 아니다

$$\text{정치인 A 발의}\ \to\ \text{과거 기업 B 비판 이력}\ \to\ \text{적대 관계}\ \to\ \text{규제가 표적}$$

이런 연쇄는 형식 연역이 아니지만 **검증자가 판단해야 하는 것**이고, 정량 체인으로는 표현되지 않는다. 두 요건을 건다.

| 요건 | |
|---|---|
| **접지** | 마디마다 `ref:`(문서 id) 또는 `assumed` 라벨. 접지 없는 마디는 ③ 위반 |
| **낙지(落地)** | 연쇄가 **카드 밖 관측 가능 명제**로 끝나야 한다 |

*"적대 관계다"* 로 끝나면 0 bit 다. *"그 발의자가 낸 다른 규제도 이 기업을 쳤나"* 로 내려와야 과거 사례 조회가 되고 그때 bit 가 생긴다. **연쇄의 가치는 길이가 아니라 착지점이다.**

#### 6.2.6 산출 — 검증된 귀무가설과 검증값

```yaml
verdict:
  quantified:
    share_band: [-1.2, -0.4]        # 없으면 null
  rejected_nulls:                    # ← 산출물의 본체
    - null: "수급 충격만으로 설명된다"    test: T2   logLambda: 3.1
    - null: "업종 전반 하락의 일부다"     test: T1   logLambda: 2.4
  surviving:
    - "동일 창의 실적 프리어나운스"
  tests_attempted: 7
```

**살아남은 가설이 아니라 죽은 대안이 산출물이다.**

$$\log\Lambda=\log_2\frac{\Pr(\text{관측}\mid h)}{\Pr(\text{관측}\mid \neg h)}$$

$\neg h$ 가 *"무조건부 분포"* 라는 뭉뚱그린 것이 아니라 **구체적 경쟁 가설**이어야 이 비율이 계산된다. 베이즈 인자는 두 구체 가설 사이에서만 의미가 있다.

**`rejected_nulls` 는 코드가 검증한다.** 배제 주장은 **실제로 실행되고 통과한** 검정을 인용해야
하고, 아니면 `invalid_rejections` 로 격리되며 $\log\Lambda$ 는 보고값이 아니라 실행 결과로 덮인다.
1회전 E2E 에서 **셀의 12%** 가 실행되지 않은 검정을 근거로 배제를 주장했다 — 자기신고를 검증
가능한 것으로 바꾸는 설계인데 verdict 만 예외로 남아 있었다.

`surviving` 이 비어 있는 것이 정상이 아니다. **비어 있으면 열거가 게을렀다고 본다** — 완전성은 증명 불가이므로 공란을 신뢰하지 않는다.

**`unresolved` 도 같다.** 검증자는 **매 라운드 짜고 싶었으나 못 짠 검정을 낼 의무**가 있다. 빈 `unresolved` 는 *"필요한 데이터가 전부 있었다"* 가 아니라 **탐색이 카탈로그 안에만 머물렀다**는 신호다.

$$\text{설계는 완전 데이터를 가정하고, 결손은 여기서 드러난다.}$$

이것이 데이터 로드맵의 유일한 입력이다 — 무엇이 없는지를 사람이 목록으로 관리하지 않고 **에이전트가 매 실행 보고**한다.

#### 6.2.7 탐색 예산

자유 반복은 **다중검정을 폭발시킨다.**

| 항목 | 상한 |
|---|---|
| 라운드 | 6 |
| 검정 총계 | 20 |
| 도구 호출 | 120 |

$$\log\Lambda_{\text{보정}}=\sum\log\Lambda_k-\underbrace{\log_2\binom{\texttt{tests\_attempted}}{\text{채택 수}}}_{\text{다중검정 대가}}$$

**시도는 자유이되 공짜가 아니다.** 20번 짜서 3개를 채택하면 보정이 $\approx10$ bit 를 먹는다. 검증자를 억제하는 것이 프롬프트가 아니라 산술이어야 한다.

### 6.3 정련 — LLM + 도구

| 연산 | 하는 일 | 버는 것 |
|---|---|---|
| **하강** | `assumed` → `observed`, 또는 연역 상한 추가 | 밴드 $\epsilon$ 축소 → bit |
| **세분** | 잔차를 쪼개 조각별 체인 | 커버리지 — **단 조각마다 자기 bit 를 벌어야** |

**게이트:** 각 단계는 `assumed`↓ **또는** 미설명↓ 이어야 한다. 둘 다 아니면 **롤백**.

*"배수를 15로 두면 맞는다"* 는 자유모수를 안 줄이므로 하강이 아니라 **피팅**이고 여기서 걸린다.

### 6.4 반증 — 별도 세션. 통계와 논증 두 축

**taxonomy 없이 작동한다.** 하네스는 "수급 충격"이 뭔지 알 필요가 없다.

| 축 | 무엇을 보나 | 산출 |
|---|---|---|
| **통계** | *"네 체인이 함의하는데 검사 안 된 관측을 대라"* | 반례 후보 → 코드가 실행 |
| **논증** | 접지 누락 · 비약 · 순환 · 미배제 대안 | 결함 지목 → 코드가 채점 |

**두 번째 축이 필요한 이유:** 정량화가 안 되는 가설도 *논리적으로 합당할* 수 있고, 그 합당성은 통계로 재지지 않는다. 반대로 통계만 맞고 논거가 없는 것은 **데이터 마이닝**이다. 두 축이 서로를 견제한다.

**Challenger 는 여전히 판정하지 않는다.** 결함을 지목하고 점수는 코드가 매긴다.

#### 6.4.1 논증 점수 — 인상이 아니라 채점표

| 항목 | 측정 |
|---|---|
| **접지율** | `ref:` 있는 마디 / 전체 마디 |
| **가정 밀도** | `assumed` 수 / 연쇄 길이 |
| **대안 배제** | 근거 있는 `rejected_nulls` 수 |
| **착지** | 관측 명제로 끝났는가 (검정 불가여도 명제는 명확한가) |
| **반례 응답** | Challenger 지목에 응답했는가 |

#### 6.4.2 증거 등급 — 최약 마디가 정한다

| 등급 | 예 |
|---|---|
| **A** | 1차 공시 · 법령 원문 · 감사보고서 |
| **B** | 주요 언론 복수 출처 |
| **C** | 단일 출처 · 업계 관측 |
| **D** | 추론 · 미접지 |

$$\text{evidence\_grade}(h)=\min_{\text{마디}}\text{grade}$$

tier 와 같은 논리다. **연쇄 하나가 D 면 전체가 D 다.**

### 6.5 종료와 판정

**종료:** 정련↔반증 왕복에서 `assumed` 와 미설명이 **둘 다** 안 움직임. (횟수 상한 아님 — 관측 조건)

**판정 — 사전식 4단**

$$\text{자격}\ \succ\ \text{몫별 심각성}\ \log\Lambda_k\ge\tau\ \succ\ \max\textstyle\sum\text{share}_k\ \succ\ \text{수렴}\cdot\text{집합 최소성}$$

2단은 **순위가 아니라 문턱**이다. MDL 은 마지막 칸의 집합 최소성(AC3)에만 남고 **체인 길이에는 걸지 않는다.**

#### 6.5.1 두 축이 만드는 네 칸

| | $\log\Lambda$ 통과 | 미달 |
|---|---|---|
| **논증 강함** | **PUBLISH** — 정량 설명 + share 밴드 | **QUALITATIVE** — 정성 설명 |
| **논증 약함** | **HOLD** — 데이터 마이닝 의심 | **UNCERTAIN** |

**`QUALITATIVE` 가 이 설계에서 가장 조심스러운 칸이다.** 여기가 열려 있으면 수사로 통계를 우회할 수 있으므로 단 하나의 규칙으로 막는다.

> **검정을 못 한 것과 검정에서 진 것은 다르다.**

| 상태 | 논증으로 구제 |
|---|---|
| 검정 **불가** (데이터 부재 → `unresolved`) | ✅ `QUALITATIVE` 가능 |
| 검정 **실행 → 졌음** ($\log\Lambda<0$) | ❌ **절대 불가** |

**논증은 검정의 공백을 메울 수는 있어도 검정의 패배를 뒤집을 수 없다.** 이 한 줄이 정성 경로 전체를 지탱한다.

`QUALITATIVE` 추가 요건: 증거 등급 **B 이상** · 접지율 **≥ 0.8** · `share_band: null` 명시 · 게시문에 *"수치 검정 미수행"* 표기.

**`HOLD` 도 대칭으로 필요하다.** 20번 검정해서 하나 걸렸는데 논거가 없으면 우연이다. 다중검정 보정이 부분적으로 잡지만 economic rationale 없는 통계는 보류한다.

#### 6.5.2 세 갈래 출구 밖 — 리뷰큐

| 출구 | 조건 | 다음 |
|---|---|---|
| `PUBLISH` · `QUALITATIVE` | 위 표 | MTS + 원장 |
| `HOLD` · `UNCERTAIN` | 위 표 | 원장만 |
| **`REVIEW_QUEUE`** | **기존 데이터로 검정 불가가 지배적** | 원장 + **데이터 수집 로드맵** |

```yaml
verdict: REVIEW_QUEUE
missing_inputs: [peer_residual_daily, analyst_revision_ts]   # (observable, statistic) 로 dedupe
```

`missing_inputs` 를 집계하면 **무엇을 수집해야 가장 많은 가설이 검정 가능해지는지**가 나온다. 데이터 로드맵을 추측이 아니라 측정으로 정한다.

## 7. 산출 — 두 갈래, 다른 문턱

| | 원장 (자산) | 게시 (부산물) |
|---|---|---|
| **실패한 가설** | ✅ 기록 | ✕ |
| 접지 0 + 연역만 통과 | ✅ | ⚠️ `QUALITATIVE` 또는 `UNCERTAIN` |
| `contamination = multi_cause` | ✅ (**링크 재사용 계측** · 미설명 분포) | ✅ |
| 미설명 > 50% | ✅ | ⚠️ 부분 설명으로 명시 |

**게시 문구 규약:** 우리 산출물은 `causal-learn+` 기준으로 causal evidence 가 아니라 **감사된 귀속**이다(theory §8.4). *"이 사건이 원인이다"* 가 아니라 **"이 사건이 $[-1.2,-0.4]$pp 를 설명하고, 경쟁 가설 2개를 배제했고, 가정 $n$개로 도출했고, 이 관측이 나오면 죽는다"** 로 쓴다.

**미설명도 밴드로 쓴다.** 몫이 전부 MC 밴드이므로 표본마다 $\text{미설명}^{(j)}=Y-\sum_k\text{share}_k^{(j)}$ 로 닫는다. *"미설명 36%"* 가 아니라 *"미설명 $[21\%,52\%]$"* 다. 몫이 밴드인데 미설명만 점값이면 항등식이 닫히지 않는다.

### 감사 번들 — "감사 가능"의 조작적 정의

제3자가 **재실행 없이** 검증할 수 있어야 한다.

```
순서 로그      해시 체인 — 무엇이 언제 커밋됐나 (가설 → 명세 → 약전 조회 순)
출처 그래프    모든 수량 → 4종 중 하나
도구 원장      호출 인자 · 반환 · 시드 · 버전
가정 목록      assumed 전량 — 숨은 것이 없다는 증명
배제 목록      rejected_nulls + surviving
최종 배분      share_band · 미설명 밴드 · logLambda · 논증 점수
```

## 8. 에이전트 하네스 요약

> 상세는 `causal-attribution.drawio` **`merged-design`** · **`actor-sequence`** 페이지.

| 도구 | **0** | 전체 + ANALOG | 전체 | 전체 + 교란자 |
| 약전 | **✕** | ○ **명세 커밋 후** | ○ | ○ |

## 9. 1단계 선행조건

| # | 항목 | 상태 |
|---|---|---|
| 1 | 잔차 분해 $Y_{i,t}$ (시장/피어/고유) | 필요 — 좌표계의 전제 |
| 2 | 일중 경로·되돌림 산출 (PATH) | 필요 — 정보량 최고 블록 |
| 3 | 사건 커버리지 플래그 (EVENTS) | **신규.** 없으면 부작동 칸이 오염 |
| 4 | 링크·영수증 테이블 | **신규.** 소급 불가하므로 최우선 |
| 5 | 해시 체인 순서 로그 | **신규.** 값싸고 ② 의 전제 |
| 6 | 도구 `as_of` 부분적용 등록기 | **신규.** ① 의 전제 |
| 7 | **노드 카탈로그 도구** (§4.2) | **신규.** 마이그레이션에서 생성 + 배치가 coverage 실측 + 수작업(매핑 · lag/revisable). 없으면 `assumed` 가 검증 불가 자기신고가 되고 데이터 증설이 에이전트 능력으로 이어지지 않는다 |
| 8 | **ANALOG 집계** (§6.2) | **신규.** 검증자 전용 — 무조건부 분포가 없으면 판별력 게이트가 게이밍된다 |
| 9 | **리뷰큐 · `missing_inputs` 집계** (§6.5) | **신규.** 값싸다. 없으면 데이터 로드맵을 추측으로 정한다 |
| 10 | **기준선 추정기** (§1.0) | **신규. 0번 선행조건** — $Y$ 가 없으면 아무것도 못 센다 |
| 11 | **수급 패널 적재** (거래량 · 외국인 · 기관) | **신규 · 최우선.** 1회전 E2E 에서 에이전트가 555회 요구했다(findings §4) |
| 12 | **동종 집합 선정 정책 + 피어 산출** (§1.0) | **신규.** 상관 기반 랭킹 유력. 없으면 1-factor 로 퇴화하고 업종 충격이 전부 고유로 샌다 |

**4·5·6 이 없으면 1단계 원장이 감사 불가**이고, **7 이 없으면 링크 분해가 망가지며, 10·11 이 없으면 $Y$ 자체가 없다.**

**선언형 검정으로 바꾸면서 샌드박스가 선행조건에서 빠졌다**(§6.2.2). 임의 코드 실행 표면이 사라져 격리·결정성 요구가 전부 소멸한다 — v1 에서 가장 큰 단순화다.
