# 설명 과정 디버깅 일지 (causal-attribution)

방법은 매 라운드 동일하다: **산출물을 다시 읽고 → 두 문장이 어긋나거나 선언이 배선
안 된 지점을 찾고 → 배선을 역추적해 수술하고 → 라이브로 재검증하고 → 테스트로 응고.**
새 라운드는 이 표에 한 행을 추가한다 (커밋 해시 필수 — 추적 가능성이 일지의 존재 이유).

테스트 궤적: 419 (감사 시작) → 467. 라이브 셀: 000660 2026-06-01(+1.29%) ·
06-02 · 07-02(−14.57%, 무사건) · 07-16(−11.53%, 거절) · 05-04~07-13 z 발화 12일.

## 20라운드 — 표현력 측정기: 어휘가 담을 수 있는 가설의 비율

사용자가 핵심 문제를 정의했다: *"우리가 어떤 가설을 검증하고자 할 때 이게 우리
온톨로지 체계로 얼마나 변환될 수 있는가를 측정해야 한다. 무조건 온톨로지를 강요하지
않고 자율 산문으로 자연스러운 가설 위에서 그게 얼마나 환원 가능하냐."*

### 왜 지금까지 못 쟀나 — 구조가 막고 있었다

```
hypothesize._SYSTEM:29   "아래 **닫힌 어휘**의 값만 쓸 수 있다"
hypothesize.propose:152  _kill("접지 밖 사건타입 날조: …")
```

어휘를 프롬프트 첫 줄에 박으니 **어휘가 못 담는 가설은 발화조차 되지 않는다.**
게다가 어휘 밖은 "날조"라 부른다 — 그 한 단어가 전혀 다른 둘을 합친다: 모델이
없는 사건을 지어낸 것(환각)과, 우리 어휘가 그 현상을 못 담은 것(표현력 부족).
미도달/부재를 갈랐던 병이 어휘 축에서 반복됐다.

### 분모를 어떻게 잡나 (사용자 답)

*"검정과 가설 에이전트가 접근 가능한 툴과 환경을 그대로 준 생성자·채점자."*
LLM 상투구도 기사 본문도 아닌 **우리 시스템이 실제로 보여주는 증거 위에서 나온
가설**이 모집단이다. 생성자는 같은 `Catalog`·같은 `Machine`·같은 셀을 쓰고
**어휘만 못 본다**(테스트가 프롬프트에 어휘 문자열 부재를 강제).

### 측정기 자신이 네 번 틀렸다 — 라이브가 매번 잡았다

의미 정직성은 못 잰다(쏠림 탐지가 마지막 신호).

**어휘엔 있는데 계산기가 없다.** '환율 급등'은 `거시` 계열 z 로, '리밸런싱'은
`수급` 계열 z 로 잡힐 수 있고 데이터도 붙어 있다(`fx_usdkrw` 342행 ·
`s3_investor_flow` · `us_market` 274행). `_INNOVATION` 확장이 방아쇠 구멍의
절반을 메운다 — 상류 온톨로지를 안 건드리고.

나머지 절반(목표주가 리포트)은 `s3_estimate_line` 이 스키마만 있고 0행이다.
