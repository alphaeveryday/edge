# 층 분해 스코프 설계 — 어디를 설명할 것인가

한 줄: **하루 수익률을 대수 분해로 세 층(시장·군집증분·고유)으로 쪼개고, 층마다 유의성·기여도로 분석 스코프를 고른다. 분해는 산술, 귀속은 게이트.**

`causal-attribution-design.md` §1 의 "크기는 산술, 인과는 역사"를 **시간축에서 횡단면축으로 복사한 것**이다. `tree.py` 가 하루를 창으로 쪼개듯, 이 층은 종목 수익률을 요인으로 쪼갠다.

---

## 1. 대수 분해 (nested means, LOO)

$$r_i = \underbrace{m^{(-i)}}_{\text{시장}} + \underbrace{\big(\bar r_c^{(-i)} - m^{(-i)}\big)}_{\text{군집증분}} + \underbrace{\big(r_i - \bar r_c^{(-i)}\big)}_{\text{고유}}$$

- $m^{(-i)} = (S_{all} - r_i)/(n_{all}-1)$ — 자기 제외 시장 평균
- $\bar r_c^{(-i)} = (S_c - r_i)/(n_c-1)$ — 자기 제외 군집 평균 ($n_c \ge 5$, 미만은 군집 없음)

### 왜 회귀가 아니라 평균인가

| | β·γ 회귀 직교화 | **계층 평균** |
|---|---|---|
| 추정 | OLS 2-leg | **없음. 뺄셈** |
| 표준오차 | 있음 | 없음 |
| 직교성 | 표본 내만 | **항상** |
| 순서 의존성 | 있음 | **없음** (계층이 순서) |
| 산업≈시장 공선성 (반도체) | γ 표준오차 폭발 | **안 생김** (회귀가 아니므로) |
| ETF 합산 | 종목마다 다른 바스켓 → 불가 | **가능** |

마지막 줄이 결정적이다. top-3 상관 피어(EXP-002)는 종목마다 다른 3종목이라 $\sum_i w_i \cdot (\text{피어 성분})$ 이 하나의 "층"으로 뭉치지 않는다. **top-3 는 예측(R²) 도구이지 회계 단위가 아니다.**

대가는 $\beta=1$ 강제다. 그 이질성은 분해가 아니라 **노출 가설**이 맡는다 — "군집 베타가 높은 종목이 더 반응했나"는 기존 `edge_test` 가 그대로 검정한다.

### 검증 (실데이터)

KODEX 200 · 200종목 · 2026-07-15~31 · DataGuide 수정주가:

```
항등식   max |m + inc + idio − r|            = 5.6e-17   ✓
직교성   max |Σ_{i∈c} idio_i|  (n_c ≥ 5)     = 6.2e-15   ✓
```

LOO 에서도 두 성질이 유지된다:
$$\textstyle\sum_i \Big(r_i - \tfrac{S-r_i}{n-1}\Big) = S - \tfrac{nS-S}{n-1} = 0$$

## 2. 스코프 판정 — 게이트 둘

### 게이트 A · 시장 지배

$$\text{share}_{mkt} = \frac{|\sum_i w_i m_i|}{\sum_L |\sum_i w_i L_i|} \ \ge\ 0.50 \;\Rightarrow\; \textbf{시장 장세}$$

개별 귀속 스코프를 **열지 않는다.** 산출은 분해 + 그 사실. 지금 시스템이 시장 장세에 개별 종목 뉴스 16개를 긁는 것이 실패 양식이다.

### 게이트 B · 커버리지

$$\frac{\sum_{\text{선정}} w_i c_i}{\sum_i w_i(\text{inc}_i + \text{idio}_i)} \ \ge\ 0.50$$

**분모가 ETF 전체가 아니라 군집+고유 합이다.** ETF 전체로 잡으면 시장 층이 혼자 목표를 채우고 아무것도 설명 안 한 채 종료한다.

미달은 실패가 아니라 판정이다 — *"광범위 분산, 개별 서사 없는 날"*.

### 스코프 후보

| 종류 | 단위 | 기여 |
|---|---|---|
| 군집증분 | **클러스터** | $\sum_{i \in c} w_i \cdot \text{inc}_i$ |
| 고유 | 종목 | $w_i \cdot \text{idio}_i$ |

군집 스코프는 **클러스터당 1개**다. 종목당이 아니다 — 이것이 캐시의 본체.

### 선정 (탐욕, 결정론)

```
① 게이트 A → 시장 지배면 종료
② 후보 중 |t| ≥ 2 만 남긴다      (t = 성분 / σ₂₅₀, 탈락 수를 보고)
③ 목표와 같은 부호로 |기여| 내림차순 누적, 50% 도달 시 정지
④ 상위 SCOPE_CAP 개만 검정, 나머지는 "선정됐으나 미검정"
```

## 4. 캐시 설계

### 이득 (잔차 + ward + K=25, 200종목)

```
전 구성종목을 고유 스코프로 다루면    200 워크플로우
군집 층으로 접으면                    20 워크플로우   (10배)
군집 스코프 1개가 덮는 종목           중앙값 7 · 최대 17 · 커버 182/200 · 고아 17
```

> raw 수익률 상관으로 하면 유효 군집이 4개(최대 64)로 접혀 "50배"가 나오지만, 그건 클러스터가
> 유니버스의 1/3 이라 군집 층이 시장과 분리되지 않은 결과다 — 과대평가다. EXP-003 §5.

### 유효기간 — ARI 실측

| 경과 영업일 | 1 | 5 | 10 | 21 | 63 |
|---|---:|---:|---:|---:|---:|
| 잔차 + ward K=25 | 0.91 | 0.68 | 0.68 | 0.67 | 0.55 |
| 잔차 + average K=40 | 0.95 | 0.93 | 0.87 | **0.83** | 0.66 |
| raw + average K=25 | 0.94 | 0.77 | 0.63 | 0.48 | 0.33 |

ward 는 모양이 좋고 안정성이 중간, average 는 반대다. **모양을 택한다** — 거대 클러스터는 군집
층을 시장과 구분 불가능하게 만들어 층 자체를 무의미하게 하지만, TTL 이 짧은 것은 재계산으로
해결된다. ward 기준 TTL 은 보수적으로 **5영업일**.

### 캐시 키

```
클러스터 정의   (유니버스, 룩백=252, K, MIN_CL, 기준일 // 5)     TTL 5영업일
패널 검정 결과  (층, 사건타입, 노출, 취약성, 부호, split, day)   ← 종목 무관
오늘 적용 판정  + instrument_id                                   ← 캐시 불가
```

두 번째가 큰 이득이다. `_POINT_PANEL` 은 이미 `WHERE event_type_code = '{etype}'` 만 걸고 **종목 조건이 없다** — 셀 100개가 같은 패널을 100번 다시 계산하고 있다. 키에서 종목을 빼면 중복이 즉시 사라진다.

## 5. 구현

### 5-1. `adapters/sql_surface.py` — v_daily 3성분 노출

```sql
_xs  AS (SELECT trade_date, sum(lr) s_lr, count(*) n_xs FROM _ret
         WHERE lr IS NOT NULL GROUP BY 1 HAVING count(*) >= 50),
_mkt AS (SELECT ..., (x.s_lr - t.lr)/NULLIF(x.n_xs-1,0) AS mkt_lr, ...),
v_daily AS (
    SELECT m.*,
           CASE WHEN count(*) OVER di >= 5
                THEN (sum(m.lr) OVER di - m.lr)/(count(*) OVER di - 1) - m.mkt_lr
                ELSE 0.0 END AS ind_lr,
           m.lr - m.mkt_lr - (동일식) AS ar_ind
    FROM _mkt m WINDOW di AS (PARTITION BY m.trade_date, m.cluster_id))
```

σ 는 v_daily 에 넣지 않는다 — 250행 윈도가 공유 뷰를 무겁게 한다. 소비자 CTE 에 둔다.

> ⚠️ `v_daily` 는 공유 HAND_VIEW. 소비자: `statics/paneltest`·`statics/premium`·`causal/p2_hypotheses`·`adapters/causal_data` + 테스트 5개. `ar_ind` 가 LOO 로 바뀌면 P0–P9 레인의 모든 잔차가 바뀐다. 별도 브랜치 + 레지스트리 전량 재판정 전제.

### 5-2. `statics/cluster.py` (신규, ~80줄)

**입력은 raw 수익률이 아니라 시장 차감 잔차** $u_i = r_i - m^{(-i)}$ 다 (EXP-003 §5).
시장 층은 클러스터를 몰라도 계산되므로 순환이 없다. raw 를 쓰면 시장 공통분이 상관을
지배해(평균 |ρ| 0.343 vs 잔차 0.139) average linkage 가 chaining 하고, 유니버스의 1/3짜리
거대 클러스터가 나와 군집 층이 시장과 분리되지 않는다.

```
입력      252일 잔차 상관 (1 − ρ 거리)
linkage   ward
K         최대 클러스터 ≤ 유니버스/8 을 만족하는 최소 K     ← 상수 하나로 튜닝 자유도 제거
MIN_CL    5   (미만은 군집 자격 없음 → 고유로 흡수)
캐시      파일, TTL 5영업일 (ARI 실측 기반)
```

클러스터에 **이름을 붙이지 않는다** — ID 와 구성종목 목록으로만 지칭. 이름을 지으면 그게 날조다.

### 5-3. `statics/scope.py` (신규, ~130줄)

```python
LAYERS    = ("시장", "군집증분", "고유")
LAYER_COL = {"시장": "mkt_lr", "군집증분": "ind_lr", "고유": "ar_ind"}
T_MIN, COVER_TARGET, MKT_DOMINANT, SCOPE_CAP = 2.0, 0.50, 0.50, 5

@dataclass(frozen=True, slots=True)
class Component:  instrument_id | cluster_id, layer, value, weight, sd
@dataclass(frozen=True, slots=True)
class Selection:  by_layer, market_share, dominant, scopes, covered, reached, thin, capped

def decompose_cell(lake, etf_id, day) -> list[Component]   # 합=1 assert
def select(comps, ...) -> Selection
```

### 5-4. `paneltest._base()` — 종속변수 스위치 (1줄)

```python
f AS (SELECT instrument_id, trade_date, {LAYER_COL[layer]} AS ar, ...)
```

검정 코드는 손대지 않는다.

### 5-5. `narrate` — 층 문장 2개 + 가드 1개

```
[층] 시장 −6.27%p (52%) · 군집증분 −4.09%p (34%) · 고유 −1.80%p (15%)
     → 시장 지배. 개별 귀속 스코프를 열지 않는다
[스코프] 선정 1/204 · 군집+고유 순 커버리지 69% · |t|<2 탈락 198 · 미검정 5
```

가드: `dominant=True` 인데 고유 층 엣지를 적용하면 `NarrationError`.

### 5-6. 순서

```
0. 순열검정 벡터화              필수 선행 (n=1000/300일에 8초 — 층 3배면 못 돈다)
1. LOO + ind_lr 노출            SQL 6줄
2. tv_chg 제거 · 부호 일치 검사   2줄
3. cluster.py + scope.py + 종속변수 스위치
4. narrate 층 문장 + dominant 가드
5. 패널 캐시 (종목 무관 키)
6. 배치 러너
7. 레지스트리 전량 재판정        ar_ind 정의가 바뀌었으므로 필수
```

## 6. 한계 — 이 실증이 말하지 않는 것

| | 내용 |
|---|---|
| 표본 | **12영업일 · ETF 1개.** 파일럿이다. 계절성·장세 국면 미반영 |
| 비중 집중 | KODEX 200 은 시총가중(삼성전자 ~30%). 스코프가 적은 것은 비중 집중 효과가 크다. 동일가중·섹터 ETF 는 다를 것 |
| 군집 정의 | 산업 분류가 S3 레이크에 **없다** (`W_SECTOR` 는 지수·규모 태그였다). RDB `instrument_classification` 이 진짜 축이고, 여기서는 상관 클러스터로 대체했다 |
| 클러스터 품질 | average linkage 가 거대 2개 + 파편을 만든다. Ward·상관 임계·관계 그래프 교차 등 대안 미검증 |
| σ | 250일 추정창 미적용 (t 게이트는 설계만, 실증에서는 기여도만 사용) |

## 7. 후속 — 발동 조건이 있는 것만

| | 발동 조건 |
|---|---|
| GICS 다계층 중첩 분해 | RDB 분류가 붙고, 상관 클러스터보다 군집 층이 잘 잡힐 때 |
| 매크로 층 분리 (FX환·R금리신용 개통) | 시장 층 \|t\|≥2 가 자주 뜰 때 |
| 전이 패널 연속 노출 (분류거리·홉수·세그먼트중복) | 군집 층 가설이 계속 판정불가일 때 |
| lead-lag · 창 단위 층 분해 | 전 종목 5분봉이 실제로 붙었을 때 |

조건 없이 미리 만들지 않는다.
