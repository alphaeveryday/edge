# 포트폴리오 관리자 대시보드 설계

상태: 사용자 승인 후 구현. 운영 적용 여부는 GitHub 배포 결과를 확인한다.

## 목적과 화면

운영자가 방문 활동, 분석 처리 현황, 단계별 입력과 리포트 신청을 한 화면에서 확인한다. 경로는 `/portfolio/admin.html`이며 일반 사용자 화면과 별도 진입점을 사용한다.

상단에는 최근 2분 활성 방문자, 오늘 방문자, 오늘 분석 요청, 대기·진행·성공·실패를 표시한다. 모든 날짜 집계 기준은 한국 시간이다. 분석 처리 상태 집계는 분석 작업만 대상으로 하며 추가 채팅과 구분한다.

본문은 `분석 요청`, `저장된 입력`, `리포트 신청` 세 탭으로 구성한다. 최신순 목록, 기간·상태 필터, 페이지 이동을 제공한다. 한 번에 최대 50건만 조회한다. 목록의 한 행을 누르면 오른쪽 상세 영역에서 입력값을 읽으며 모바일에서는 상세 화면으로 전환한다.

- 분석 요청: 익명 방문자 식별자, 요청 시각, 상태, 현재 단계, 처리 시간, 실패 사유. 상세에는 제출 당시 ETF·현금·금액 또는 비중·계좌·투자 방식·기간·월 적립금·관심사·질문·세금 정보와 저장된 결과가 나온다.
- 저장된 입력: 다음 단계로 넘어갈 때 저장된 최신 초안과 저장 시각. 분석 제출 전 이탈한 입력도 확인한다. 글자 입력 중의 모든 변경이나 과거 수정 이력을 저장한다고 표시하지 않는다.
- 리포트 신청: 이메일, 신청 시각, 연결된 분석. 발송 상태는 실제 구현대로 접수만 표시한다.

관리자는 사용자 원본을 수정하거나 분석을 재실행하지 않는다. 이번 범위는 조회와 접속 계측이다.

## 실시간의 정의

일반 사용자 페이지가 보이는 동안 30초마다 익명 방문자 쿠키로 heartbeat를 전송한다. 페이지를 처음 열거나 다시 보이게 할 때도 전송한다. 최근 2분 내 신호가 있으면 활성으로 집계한다. 같은 브라우저의 여러 탭은 한 방문자로 센다. 관리자 화면은 일반 방문자로 집계하지 않는다.

대시보드는 10초 간격으로 갱신한다. 탭이 숨겨지면 갱신을 멈추고, 복귀 시 즉시 갱신한다. 조회 오류 시 이전 결과를 최신인 것처럼 표시하지 않고 마지막 갱신 시각과 오류를 표시한다. 로그인 만료 시 민감한 데이터를 화면에서 지우고 로그인 화면으로 돌아간다.

방문자는 사람 수가 아니라 쿠키 기준이다. 다른 기기나 쿠키 삭제는 새 방문자다. 브라우저 강제 종료 후 활성에서 빠지기까지 최대 2분이 걸린다. 계측 배포 이전 방문자 수는 복원하지 않으며 과거에는 기존 분석·초안 기록만 제공한다.

## 별도 관리자 인증

두 가지 구현 방식 중 이번에는 첫 방식을 권장한다.

1. 기존 포트폴리오 API에 독립 관리자 인증을 추가한다. 별도 관리자 자격과 세션을 쓰되 기존 서버·배포를 재사용한다. 단일 운영자용으로 작고 명확하다.
2. 별도 인증 서비스의 호스팅 로그인으로 연결한다. 다중 관리자와 MFA 확장이 쉽지만 이번 기능에 인증 서비스와 배포 구성이 추가된다.

첫 방식은 공개 회원가입 없이 관리자 한 계정으로 시작한다. 일반 방문자 쿠키는 관리자 API 접근 권한을 주지 않는다. 운영 비밀번호는 무작위 생성하여 전용 AWS Secrets Manager 리소스에서 보관한다. 비밀값을 저장소, URL, 분석 에이전트, GitHub 로그에 노출하지 않는다. 관리자에게 전달할 때는 권한이 제한된 AWS 조회 경로를 사용한다.

관리자 쿠키는 HttpOnly·Secure·SameSite=Strict이며 관리자 API 경로에 한정한다. 서버 측 세션을 사용하고 만료·로그아웃·자격 변경 시 접근을 거부한다. 로그인 시도 횟수를 제한하고, 관리자 응답은 no-store로 처리한다. 모든 관리 API가 같은 권한 검사를 거치며 자격이 설정되지 않았으면 접근을 허용하지 않는다. 입력·이메일은 HTML로 해석하지 않고 텍스트로 표시한다.

## 저장과 배포

기존 독립 PostgreSQL의 `portfolio_jobs`, `portfolio_input_*`, `portfolio_report_requests`를 읽는다. 방문자 활동·일자별 활동·관리자 세션·로그인 제한용 기록은 같은 모듈이 소유한 별도 테이블로 저장한다. 외부 검색이나 모델 호출은 필요하지 않다.

Terraform으로 비밀 저장소와 최소 IAM 권한을 관리한다. 관리자 자격은 API에만 전달하고 분석 워커에는 전달하지 않는다. CloudFront를 수동 변경하지 않고 GitHub PR, CI, Terraform 및 기존 배포 워크플로를 사용한다. 일반 랜딩과 포트폴리오 페이지 경로는 유지한다.

## 구현과 운영

- Terraform 선행 PR #1229: 전용 Secret 메타데이터, 호스트 읽기 권한, dev 배포 역할의 해당 Secret 조회·초기값 저장 권한. 2026-10-13 apply 성공, 삭제·교체 없음.
- 실제 비밀번호는 후속 앱 배포에서 Secret에 값이 없을 때만 무작위 생성한다. 값은 Terraform state에 저장하지 않는다. 계정은 `admin`이다. API에는 SHA-256만 전달하고 분석 워커에는 전달하지 않는다.
- 관리자 세션 8시간, 서비스 전체 로그인 시도 15분당 20회. 비밀번호를 바꾸면 GitHub 배포를 다시 실행해 API의 해시를 갱신하며 기존 세션은 무효화한다.
- 추가 테이블: `portfolio_admin_sessions`, `portfolio_admin_login_attempts`, `portfolio_presence`, `portfolio_visit_days`. 모두 독립 포트폴리오 DB에 속하며 기존 입력 테이블의 writer는 바뀌지 않는다.
- 방문 기록은 90일 유지한다. 초안은 기존 정책대로 방문자당 최신 10건이며 수정 이력은 제공하지 않는다.
- 관리자 페이지와 API는 별도 진입점이고, 일반 페이지에만 heartbeat를 연결한다. 자동 갱신 실패 시 마지막 성공 시각과 오류를 표시한다.

## 검증과 완료 기준

- 비로그인·일반 방문자·틀린 관리자 자격으로 모든 관리자 API 접근이 차단된다.
- 로그인 성공·실패 제한·세션 만료·로그아웃·교차 출처 요청 차단을 검증한다.
- 여러 탭 중복 제거, 2분 활성 기준, 한국 날짜 경계, 분석과 채팅 분리 집계를 검증한다.
- 초안과 분석 제출 당시 입력을 혼동하지 않고 숫자·빈 값·금액 입력 방식을 그대로 보여 준다.
- 모바일·데스크톱에서 로그인, 목록·필터·페이지 이동·상세·자동 갱신·통신 실패·세션 만료를 검증한다.
- 로컬 Codex 리뷰, CI, Terraform plan 검토 후 GitHub로 배포한다.
- 배포 후 미인증 차단과 관리자 조회를 확인하며 실제 사용자 입력을 테스트 로그나 대화에 출력하지 않는다.
