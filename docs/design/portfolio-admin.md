# 포트폴리오 관리자 대시보드 설계

상태: SSM 전용 접속 및 관리자 상세·이메일 집계 개선 승인(2026-10-13). 운영 적용 여부는 GitHub 배포 결과를 확인한다.

## 목적과 화면

운영자가 방문 활동, 분석 처리 현황, 단계별 입력과 리포트 신청을 한 화면에서 확인한다. SSM 터널을 연 PC의 `http://localhost:18080/portfolio/admin.html`에서 확인한다. 공개 도메인에는 관리자 화면이나 API를 제공하지 않는다.

상단에는 최근 2분 활성 방문자, 오늘 방문자, 오늘 분석 요청, 대기·진행·성공·실패를 표시한다. 모든 날짜 집계 기준은 한국 시간이다. 분석 처리 상태 집계는 분석 작업만 대상으로 하며 추가 채팅과 구분한다.

오늘·누적 고유 이메일과 누적 리포트 신청 레코드 수도 별도로 표시한다. `portfolio_report_requests.email`의 양끝 공백을 제거하고 소문자로 변환해 중복을 제거하며 빈 이메일은 고유 개수에서 제외한다. 오늘은 Asia/Seoul 자정 이상 다음 자정 미만에 저장된 레코드 기준이다. 이메일 개수는 사람 수가 아니다. 신청은 `(job_id, owner)`로 upsert하므로 레코드 수는 반복 클릭 횟수가 아니며, 이메일을 바꾼 이력도 복원하지 않는다. 기존 테이블을 조회하며 스키마 변경은 없다.

본문은 `분석 요청`, `저장된 입력`, `리포트 신청`, `테스트 분석`, `버전별 검증` 탭으로 구성한다. 최신순 목록, 기간·상태 필터, 페이지 이동을 제공한다. 한 번에 최대 50건만 조회한다. 목록에서 상세를 열면 데스크톱·모바일 모두 목록 위에 전체 너비의 상세 영역을 표시한다.

- 분석 요청: 익명 방문자 식별자, 요청 시각, 상태, 현재 단계, 처리 시간, 실패 사유. 상세에는 제출 당시 ETF·현금·금액 또는 비중·계좌·투자 방식·기간·월 적립금·관심사·질문·세금 정보와 저장된 결과가 나온다.
- 저장된 입력: 다음 단계로 넘어갈 때 저장된 최신 초안과 저장 시각. 분석 제출 전 이탈한 입력도 확인한다. 글자 입력 중의 모든 변경이나 과거 수정 이력을 저장한다고 표시하지 않는다.
- 리포트 신청: 이메일, 신청 시각, 연결된 분석. 발송 상태는 실제 구현대로 접수만 표시한다.

상세는 `고객 결과`, `고객 입력`, `출처와 인용` 탭으로 나눈다. 결과가 있으면 고객 결과를, 아직 없으면 고객 입력을 먼저 연다. 고객 결과는 기존 `ReportView`를 재사용해 현재 평가, 추천 비중·실행 행동·계좌별 제안, 예상 수익률·배당률과 산정 근거, 과거 성과, 인사이트, 각 분석 단계의 본문·한계를 보여 준다. 고객용 스타일과 CSS 변수는 Shadow DOM 안에서 불러와 관리자 스타일과 격리한다. 이전 결과에 없는 항목은 임의 수치로 채우지 않는다. 비중이 빠지면 자료 없음으로 표시하고 불완전한 추천 성과는 차트를 그리지 않으며, 실제 0은 유지한다.

출처 탭은 `report.sources`와 각 근거의 인용문을 구분해 보여 준다. `evidence.source_id`로 출처를 연결하고 저장된 `passage_id`가 있을 때만 인용 ID를 표시한다. 연결할 출처가 없으면 그 사실을 표시하며 원문 링크는 HTTP(S)만 허용한다. 전체 결과 JSON은 선택적으로 여는 원본 보기로 남긴다.

추가 질문은 접지 않고 질문 전문, 고객에게 보여 준 답변 문단·한계, 요청 시각(KST), 대기·작성 중·완료·실패와 실패 사유를 표시한다. 질문이 없으면 빈 상태를 보여 준다. 저장된 답변 원본은 별도로 열 수 있으며 관리자 화면에서 질문을 보내는 기능은 제공하지 않는다.

관리자는 사용자 원본을 수정하거나 분석을 재실행하지 않는다. 이번 범위는 조회와 접속 계측이다.

## 테스트 분석 구분

운영자가 실행 ID를 확인한 테스트는 `portfolio_jobs.test_label`에 출처를 저장한다. 질문 내용이나 방문자가 같다는 이유로 고객 요청을 분류하지 않는다. `분석 요청`과 `리포트 신청`은 고객만 표시하고 테스트 입출력·후속 답변은 `테스트 분석` 탭에서 조회한다. 일반 목록의 기본 scope는 customers이며 테스트 탭은 tests를 명시한다. 상단 통계는 탭과 무관하게 고객 분석·고객 이메일 신청만 집계한다. 방문자·일별 방문·저장된 입력에서는 분석이 모두 명시적 테스트인 방문자만 제외한다. 고객 분석도 있는 방문자는 유지하며, 분석을 제출하지 않아 테스트 여부를 확인할 수 없는 방문자는 분류하지 않는다.

운영자 전용 `admin_store.delete_test_reports()`는 테스트로 표시된 분석에 연결된 이메일 신청만 삭제한다. 같은 이메일 주소나 방문자를 사용하는 고객 신청은 보존한다. HTTP 삭제 경로는 제공하지 않는다. 화면에는 지표명·값·실행 상태를 표시하고 집계 방식이나 사용 방법을 반복 설명하는 안내 문구는 생략한다.

표시는 신뢰된 운영 경로의 `admin_store.mark_tests(job_ids, label)`로만 지정한다. 존재하지 않는 ID가 포함되면 전체 변경을 취소하며 재실행은 중복 기록을 만들지 않는다. 공개 입력으로 표시를 지정할 수 없고 SSM 관리자 HTTP는 계속 읽기 전용이다. 고객의 원본 입력·결과를 변경하거나 삭제하지 않는다. 리밸런싱은 “내 포트폴리오에서 바꿀 것” 카드 하나에 종목·계좌별 매수·매도 금액과 현금 투입을 표시한다. 공개 보고서와 관리자 보고서가 같은 컴포넌트·스타일을 사용한다.

## 배포 버전별 검증 이력

`버전별 검증` 메뉴는 버전·실행 환경별로 20개 유형의 기대 결과, 실행 당시 입력, 실제 고객용 보고서, 소요 시간, 실패와 재시도를 조회한다. `portfolio_verification_runs`는 버전과 20개 유형의 명세를 고정하고 `portfolio_verification_attempts`는 회차별 입력·결과를 보존한다. 후속 성공이 이전 실패를 덮어쓰지 않는다. 과거 자료를 가져올 때는 실제 입력을 별도로 보존하며 Git 버전을 확인할 수 없으면 저장된 코드·지침 식별자 또는 미기록 상태를 표시한다. 로컬 검증 결과를 운영 실행으로 표시하지 않는다.

배포 아카이브에 체크아웃한 실제 Git 커밋을 넣고, 서비스 기동 확인 뒤 해당 버전의 20개 유형을 자동 등록한다. 이미지에 기록된 커밋과 다른 버전으로 검증을 실행할 수 없다. 배포 등록만 한 유형은 `미실행`이며 실제 모델 실행은 별도 운영 명령으로 시작한다. 매 배포마다 모델 20건을 자동 실행하지 않는다. 직접 모델 검증은 고객 접수·대기열을 통과하지 않으며 고객 작업과 할당량을 공유하지 않는다.

자동검사는 추천 유무·합계·일부 명시 제약과 계산값을 확인한다. 설명 품질, 계좌 간 이동, 절세 판단까지 모두 검증했다고 주장하지 않는다. 실제 답변을 검토할 수 있게 전체 보고서를 제공한다. 12분 넘게 완료 기록이 없는 실행은 중단 의심으로 표시하며, 운영자가 재실행하면 이전 중단을 실패로 보존하고 새 회차를 생성한다.

새 관리자 조회 경로는 `/verification-runs`, `/verification-runs/{id}`, `/verification-runs/{id}/{case}/{attempt}`이며 모두 기존 `/api/portfolio/admin` 아래 SSM 읽기 전용 경계를 따른다. 고객 화면이나 공개 API에는 추가하지 않는다.

## 방문 신호와 갱신

일반 사용자 페이지가 보이는 동안 30초마다 익명 방문자 쿠키로 heartbeat를 전송한다. 페이지를 처음 열거나 다시 보이게 할 때도 전송한다. 최근 2분 내 신호가 있으면 활성으로 집계한다. 같은 브라우저의 여러 탭은 한 방문자로 센다. 관리자 화면은 일반 방문자로 집계하지 않는다.

대시보드는 10초 간격으로 갱신한다. 탭이 숨겨지면 갱신을 멈추고, 복귀 시 즉시 갱신한다. 연결 실패 시 입력과 조회 결과를 화면에서 지우고 다시 연결 안내를 표시한다.

방문자는 사람 수가 아니라 쿠키 기준이다. 다른 기기나 쿠키 삭제는 새 방문자다. 브라우저 강제 종료 후 활성에서 빠지기까지 최대 2분이 걸린다. 계측 배포 이전 방문자 수는 복원하지 않으며 과거에는 기존 분석·초안 기록만 제공한다.

## SSM 전용 접속

사용자가 승인한 최종 방식은 SSM 포트 포워딩이다. 새 EC2·VPN·공개 관리자 도메인을 만들지 않는다. 기존 서버에서 관리자 전용 프로세스를 실행하고 Docker 포트는 `127.0.0.1:18080:8094`로만 게시한다. 공개 API 프로세스에는 관리자 라우터가 없고 Caddy에서도 관리자 경로를 차단한다.

SSM은 IAM이 허용한 사용자만 연결할 수 있다. 별도 공용 관리자 비밀번호를 사용하지 않는다. 관리자 앱은 읽기 전용이며 허용 Host는 `localhost:18080`, `127.0.0.1:18080`뿐이다. 다른 Origin·cross-site 브라우저 요청을 거부하고 응답에 no-store·프레임 차단을 적용한다. 서버나 사용자 PC 자체가 장악된 경우까지 SSM이 보호한다고 주장하지 않는다.

`edge-portfolio-admin-tunnel` Session 문서는 서버·로컬 포트 18080을 고정하며 임의 포트·원격 호스트·셸 매개변수를 받지 않는다. `edge-portfolio-admin-access` 정책은 지정 EC2와 이 문서, 접속 설정 조회 및 자기 세션 제어만 허용한다. 관리자용 역할에는 기존 셸 정책이나 광범위한 SSM 정책을 추가하지 않는다. 사용자가 승인한 기존 work 인증으로 edge-portfolio-admin-local 역할을 AssumeRole한다. 이 역할은 확인된 IAM 사용자 junyoung727만 신뢰하고 관리자 접속 정책만 연결한다. SSO 생성은 조직 SCP에 막혀 사용하지 않는다.

PC의 `scripts/open-admin.ps1 -Profile edge-portfolio-admin`이 연결과 브라우저 열기를 수행한다. AWS CLI v2와 Session Manager plugin이 필요하다. work의 기존 자격은 역할 발급에만 사용하고 SSM에는 1시간짜리 전용 역할 자격으로 접속한다. 스크립트는 직접 IAM 사용자나 다른 역할을 거부한다. 접속 종료는 스크립트 창에서 Ctrl+C다. 마지막 화면의 데이터는 다음 조회가 실패하면 제거된다(10초 갱신 + 최대 15초 요청 제한).

## 저장과 배포

기존 독립 PostgreSQL의 작업·입력·리포트·방문 활동 테이블을 읽는다. 이전 비밀번호 방식의 세션·로그인 시도 테이블과 Secrets Manager 자격은 삭제하지 않고 미사용 상태로 남겨 롤백 시 데이터 손실을 피한다. 새 관리자 프로세스에는 DB 연결만 전달하며 모델 키·관리자 비밀번호·AWS 키는 전달하지 않는다.

공개 UI는 `dist`, 관리자 UI는 `dist-admin`으로 나눠 빌드한다. 관리자 파일은 EC2 배포 아카이브에만 넣는다. GitHub 배포가 기존 S3의 관리자 HTML과 `admin-*` 파일을 제거하고 캐시를 무효화한다. 공개 API와 관리자 포트는 별도 프로세스다. CloudFront 설정 수동 수정은 하지 않는다.

AWS 자원·SSM 문서·IAM 정책은 Terraform, 서버·앱은 GitHub OIDC와 SSM 배포로 관리한다. Terraform 선행 변경을 적용한 뒤 앱을 배포한다. 운영 검증은 외부에서 관리자 페이지/API 차단, 기존 방문자 세션 정상, 실제 SSM 터널을 통한 관리자 읽기를 확인한다. 사용자 입력·비밀번호를 검증 로그에 출력하지 않는다.

## 검증과 완료 기준

- 공개 도메인과 공개 API 프로세스에서 관리자 경로 접근이 차단된다.
- SSM 연결 성공·종료와 교차 출처·Host 위조 차단을 검증한다.
- 여러 탭 중복 제거, 2분 활성 기준, 한국 날짜 경계, 분석과 채팅 분리 집계를 검증한다.
- 초안과 분석 제출 당시 입력을 혼동하지 않고 숫자·빈 값·금액 입력 방식을 그대로 보여 준다.
- 이메일 중복 제거와 KST 자정 경계, 유효한 반복 신청의 upsert를 전용 일회성 PostgreSQL에서 검증한다.
- 합성 결과로 전체 보고서·출처와 인용 ID·후속 답변 상태·부분 숫자와 실제 0을 검증하고 고객용 보고서 스타일 회귀를 확인한다.
- 모바일·데스크톱에서 목록·필터·페이지 이동·상세·자동 갱신·연결 실패·재접속를 검증한다.
- 로컬 Codex 리뷰, CI, Terraform plan 검토 후 GitHub로 배포한다.
- 배포 후 공개 경로 차단과 SSM 관리자 조회를 확인하며 실제 사용자 입력을 테스트 로그나 대화에 출력하지 않는다.
