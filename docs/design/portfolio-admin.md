# 포트폴리오 관리자 대시보드 설계

상태: SSM 전용 접속 전환 승인(2026-10-13). 운영 적용 여부는 GitHub 배포 결과를 확인한다.

## 목적과 화면

운영자가 방문 활동, 분석 처리 현황, 단계별 입력과 리포트 신청을 한 화면에서 확인한다. SSM 터널을 연 PC의 `http://localhost:18080/portfolio/admin.html`에서 확인한다. 공개 도메인에는 관리자 화면이나 API를 제공하지 않는다.

상단에는 최근 2분 활성 방문자, 오늘 방문자, 오늘 분석 요청, 대기·진행·성공·실패를 표시한다. 모든 날짜 집계 기준은 한국 시간이다. 분석 처리 상태 집계는 분석 작업만 대상으로 하며 추가 채팅과 구분한다.

본문은 `분석 요청`, `저장된 입력`, `리포트 신청` 세 탭으로 구성한다. 최신순 목록, 기간·상태 필터, 페이지 이동을 제공한다. 한 번에 최대 50건만 조회한다. 목록의 한 행을 누르면 오른쪽 상세 영역에서 입력값을 읽으며 모바일에서는 상세 화면으로 전환한다.

- 분석 요청: 익명 방문자 식별자, 요청 시각, 상태, 현재 단계, 처리 시간, 실패 사유. 상세에는 제출 당시 ETF·현금·금액 또는 비중·계좌·투자 방식·기간·월 적립금·관심사·질문·세금 정보와 저장된 결과가 나온다.
- 저장된 입력: 다음 단계로 넘어갈 때 저장된 최신 초안과 저장 시각. 분석 제출 전 이탈한 입력도 확인한다. 글자 입력 중의 모든 변경이나 과거 수정 이력을 저장한다고 표시하지 않는다.
- 리포트 신청: 이메일, 신청 시각, 연결된 분석. 발송 상태는 실제 구현대로 접수만 표시한다.

관리자는 사용자 원본을 수정하거나 분석을 재실행하지 않는다. 이번 범위는 조회와 접속 계측이다.

## 실시간의 정의

일반 사용자 페이지가 보이는 동안 30초마다 익명 방문자 쿠키로 heartbeat를 전송한다. 페이지를 처음 열거나 다시 보이게 할 때도 전송한다. 최근 2분 내 신호가 있으면 활성으로 집계한다. 같은 브라우저의 여러 탭은 한 방문자로 센다. 관리자 화면은 일반 방문자로 집계하지 않는다.

대시보드는 10초 간격으로 갱신한다. 탭이 숨겨지면 갱신을 멈추고, 복귀 시 즉시 갱신한다. 연결 실패 시 입력과 조회 결과를 화면에서 지우고 다시 연결 안내를 표시한다.

방문자는 사람 수가 아니라 쿠키 기준이다. 다른 기기나 쿠키 삭제는 새 방문자다. 브라우저 강제 종료 후 활성에서 빠지기까지 최대 2분이 걸린다. 계측 배포 이전 방문자 수는 복원하지 않으며 과거에는 기존 분석·초안 기록만 제공한다.

## SSM 전용 접속

사용자가 승인한 최종 방식은 SSM 포트 포워딩이다. 새 EC2·VPN·공개 관리자 도메인을 만들지 않는다. 기존 서버에서 관리자 전용 프로세스를 실행하고 Docker 포트는 `127.0.0.1:18080:8094`로만 게시한다. 공개 API 프로세스에는 관리자 라우터가 없고 Caddy에서도 관리자 경로를 차단한다.

SSM은 IAM이 허용한 사용자만 연결할 수 있다. 별도 공용 관리자 비밀번호를 사용하지 않는다. 관리자 앱은 읽기 전용이며 허용 Host는 `localhost:18080`, `127.0.0.1:18080`뿐이다. 다른 Origin·cross-site 브라우저 요청을 거부하고 응답에 no-store·프레임 차단을 적용한다. 서버나 사용자 PC 자체가 장악된 경우까지 SSM이 보호한다고 주장하지 않는다.

`edge-portfolio-admin-tunnel` Session 문서는 서버·로컬 포트 18080을 고정하며 임의 포트·원격 호스트·셸 매개변수를 받지 않는다. `edge-portfolio-admin-access` 정책은 지정 EC2와 이 문서, 접속 설정 조회 및 자기 세션 제어만 허용한다. 관리자용 역할에는 기존 셸 정책이나 광범위한 SSM 정책을 추가하지 않는다. 권한을 연결할 사용자 IAM/SSO 역할은 사용자의 지정이 필요하다. 정책 생성과 사용자 연결 완료를 구분해 보고한다.

PC의 `scripts/open-admin.ps1 -Profile <SSO프로필>`이 연결과 브라우저 열기를 수행한다. AWS CLI v2와 Session Manager plugin이 필요하며 정적 마스터키로 대체하지 않는다. 접속 종료는 스크립트 창에서 Ctrl+C다. 마지막 화면의 데이터는 다음 조회가 실패하면 제거된다(10초 갱신 + 최대 15초 요청 제한).

## 저장과 배포

기존 독립 PostgreSQL의 작업·입력·리포트·방문 활동 테이블을 읽는다. 이전 비밀번호 방식의 세션·로그인 시도 테이블과 Secrets Manager 자격은 삭제하지 않고 미사용 상태로 남겨 롤백 시 데이터 손실을 피한다. 새 관리자 프로세스에는 DB 연결만 전달하며 모델 키·관리자 비밀번호·AWS 키는 전달하지 않는다.

공개 UI는 `dist`, 관리자 UI는 `dist-admin`으로 나눠 빌드한다. 관리자 파일은 EC2 배포 아카이브에만 넣는다. GitHub 배포가 기존 S3의 관리자 HTML과 `admin-*` 파일을 제거하고 캐시를 무효화한다. 공개 API와 관리자 포트는 별도 프로세스다. CloudFront 설정 수동 수정은 하지 않는다.

AWS 자원·SSM 문서·IAM 정책은 Terraform, 서버·앱은 GitHub OIDC와 SSM 배포로 관리한다. Terraform 선행 변경을 적용한 뒤 앱을 배포한다. 운영 검증은 외부에서 관리자 페이지/API 차단, 기존 방문자 세션 정상, 실제 SSM 터널을 통한 관리자 읽기를 확인한다. 사용자 입력·비밀번호를 검증 로그에 출력하지 않는다.

## 검증과 완료 기준

- 공개 도메인과 공개 API 프로세스에서 관리자 경로 접근이 차단된다.
- SSM 연결 성공·종료와 교차 출처·Host 위조 차단을 검증한다.
- 여러 탭 중복 제거, 2분 활성 기준, 한국 날짜 경계, 분석과 채팅 분리 집계를 검증한다.
- 초안과 분석 제출 당시 입력을 혼동하지 않고 숫자·빈 값·금액 입력 방식을 그대로 보여 준다.
- 모바일·데스크톱에서 목록·필터·페이지 이동·상세·자동 갱신·연결 실패·재접속를 검증한다.
- 로컬 Codex 리뷰, CI, Terraform plan 검토 후 GitHub로 배포한다.
- 배포 후 공개 경로 차단과 SSM 관리자 조회를 확인하며 실제 사용자 입력을 테스트 로그나 대화에 출력하지 않는다.
