# Orca UI 1.0

포폴 서비스의 고객·관리자 화면에 적용하는 디자인 시스템. 토스의 공개 TDS와 UX 라이팅 운영 방식을 참고해 Orca의 웹 제품에 맞게 구현한다. 공개되지 않은 내부 규정까지 복제했다는 뜻은 아니다.

## 원천과 결정

2026-10-17 확인. 다음 문서가 벤치마크 근거다.

- [TDS Colors](https://tossmini-docs.toss.im/tds-mobile/foundation/colors/): 회색 정보 위계와 파란 인터랙션. 작은 글씨는 명암 대비를 위해 더 짙은 단계 사용.
- [TDS Typography](https://tossmini-docs.toss.im/tds-mobile/foundation/typography/): 제목·본문·보조 문구의 역할 기반 크기. 웹에서는 rem과 유동 높이로 확대 지원.
- [Button](https://tossmini-docs.toss.im/tds-mobile/components/button/), [TextField](https://tossmini-docs.toss.im/tds-mobile/components/TextField/text-field/), [ListRow](https://tossmini-docs.toss.im/tds-mobile/components/ListRow/list-row-overview/), [FixedBottomCTA](https://tossmini-docs.toss.im/tds-mobile/components/BottomCTA/fixed-bottom-cta/): 상태가 일관된 조작부, 제목·내용·보조 액션 순서, 모바일 하단 주요 행동.
- [TDS 운영](https://toss.tech/article/toss-design-system), [시스템 재고](https://toss.tech/article/44097): 실제 사용 사례를 먼저 모으고, 반복되는 결정과 접근성을 공통 구현에서 해결한다.
- [라이팅 원칙](https://toss.tech/article/8-writing-principles-of-toss): 다음 행동이 보이는 문구, 짧고 명확한 해요체, 반복 설명 제거, 선택 존중.

## 작업 단위와 완료 기준

| 단위 | 산출물 | 검증 |
|---|---|---|
| 기반 | 의미별 토큰, 공통 버튼·필드·메시지·제목, 기존 아이콘 재사용 | 원천 중복·생값 색상·기본 상태 자동 검사 |
| 화면 이관 | 입력 5단계, 접수·분석·결과·부분 결과·실패, 저장·구독 팝업, 대시보드 5탭, 관리자 | 기존 기능 회귀, 모바일·PC, 초점·확대·모션 검사 |
| 반복 적용 | 실제 컴포넌트 전시 화면, 작업 규칙, 기여·버전·출시 절차 | 전시 화면 격리, CI 검사, 운영 미리보기 |

화면과 공통 기반은 함께 작동해야 하므로 하나의 배포 가능한 PR로 묶는다. 금융 계산, 분석 정책, 인증·저장 경계는 그대로 둔다.

## 정보와 배치

- 입력: 한 단계에 한 결정. 제목 → 필수 입력 → 선택 입력 → 다음 행동. 투자 목적은 계속 선택이다.
- 결과: 결론 → 바꿀 종목과 금액 → 추천 구성 → 근거·성과 → 계좌 전략. 매수·상승은 빨강, 매도·하락은 파랑이며 문구·부호를 반드시 병기한다.
- 대시보드: 총자산과 손익 → 자산 구성·배당 → 보유 목록. 상세 수정과 기록은 해당 탭에서 한다.
- 고객 화면은 편안한 간격, 관리자는 높은 정보 밀도를 사용하되 색상·상태·조작법은 공유한다.
- 모바일은 한 열과 하단 주요 버튼, PC는 최대 폭 안에서 관련 정보 두 열. 고정 버튼에는 본문 여유와 safe-area를 확보한다.
- 팝업: 저장이 주요 행동, 이메일 구독이 보조 행동, 평가는 마지막. 닫기·Escape와 기존 초점 복원을 유지한다.

## 원천 파일과 계약

`apps/etforca/portfolio-ui/src/design-system/tokens.css`가 색상·글자·간격·곡률·모션의 원천이다. `components.tsx`와 `components.css`는 공통 조작부를 소유한다. 화면 CSS는 화면별 구조·배치를 다루며 시각 속성에는 의미별 토큰을 사용한다. 기존 EDGE 콘솔의 `ui-kit` 아이콘을 재사용하며 콘솔의 금융 색상 의미를 포폴에 가져오지 않는다.

전시 화면은 `/portfolio/?preview=design-system`. 실제 화면과 동일한 컴포넌트를 렌더링하고 고객 API·분석·메일 발송 없이 동작한다. `confirmation.tsx`의 native dialog는 삭제·덮어쓰기의 취소, Escape, 초점 복원, 언마운트 시 취소를 공통 처리한다. 고객 화면 스타일은 `src/styles.css`, 관리자 구조는 `src/admin/styles.css`이며 관리자 안의 고객 보고서도 같은 토큰·컴포넌트 스타일을 Shadow DOM에 주입한다.

확인 후 비동기 작업을 수행하는 호출부는 작업이 끝나고 조작부를 다시 활성화한 뒤 `restoreFocus()`를 호출한다. 취소는 확인창이 직접 복원한다. 고정 CTA는 실제 높이만큼 본문 공간을 확보한다. 차트 축은 SVG 좌표 단위로 함께 확대하고, 정확한 금액과 선택 날짜는 차트 아래 rem 텍스트로 제공한다.

버튼은 primary / secondary / plain / danger, 필드는 기본 / 초점 / 오류 / 비활성, 메시지는 안내 / 성공 / 오류를 제공한다. 로딩 버튼은 이름을 유지하고 중복 입력을 막는다. 필드는 항상 연결된 label 또는 aria-label이 있어야 한다. 모달은 native dialog와 기존 초점 복원을 유지한다.

색상만으로 상태를 전달하지 않는다. 본문 대비 4.5:1, 의미 있는 그래픽·초점 대비 3:1, 주요 터치 영역 44px 이상, 키보드 조작, 200% 글자 확대, reduced-motion을 검증한다. API 실패·빈 상태·일부 자료 없음·긴 종목명·큰 금액도 정상 상태와 같이 설계한다. 결측은 0으로 꾸미지 않는다.

## 반복 가능한 제작 절차

1. 과제: 사용자가 하려는 일, 다음 행동, 데이터·권한·실패 상태를 적는다.
2. 재사용: 전시 화면과 기존 호출부를 확인한다. 같은 역할의 컴포넌트가 있으면 사용한다.
3. 설계: 모바일·PC 배치와 기본/빈/로딩/실패/긴 내용/부분 자료 상태를 정한다.
4. 구현: 공통 토큰과 조작부를 사용한다. 새로운 공통 API는 실제 두 번째 사용처 또는 기존 컴포넌트로 해결되지 않는 근거가 있어야 한다.
5. 검증: `pnpm --filter portfolio-ui check:design`, `build`, `test:e2e`. 전시 화면·실제 화면·키보드·확대를 확인한다.
6. 리뷰: 화면 목적·데이터 정확성·접근성·문구·모바일/PC를 함께 본다. 디자인 변경은 코드와 같은 PR에서 검토한다.
7. 출시: dev PR → CI → 배포 → 버전이 표시된 미리보기 확인. 이상 시 해당 PR을 되돌린다.

## 운영과 변경 관리

포폴 프론트 유지보수자가 토큰과 컴포넌트의 소유자다. 승인 기록은 PR에 남긴다. 토큰 이름·컴포넌트 props 변경은 모든 호출부를 한 PR에서 이관하고 버전을 올린다. 제거할 API는 대체 경로·사용처 검색·이관을 먼저 끝낸다. 단순 시각 수정도 전시 화면과 대표 고객 화면을 함께 확인한다. 별도 Figma 사본을 코드와 경쟁하는 원천으로 만들지 않는다.

출시 기록: 1.0 — 토스 공개 패턴 기반 토큰·공통 조작부, 고객/관리자 이관, 전시 화면, CI 규칙 도입.
