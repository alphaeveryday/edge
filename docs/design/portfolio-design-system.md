# Orca UI 1.1

포폴 서비스의 고객·관리자 화면에 적용하는 디자인 시스템. 토스의 공개 TDS와 UX 라이팅 운영 방식을 참고해 Orca의 웹 제품에 맞게 구현한다. 공개되지 않은 내부 규정까지 복제했다는 뜻은 아니다.

## 원천과 결정

2026-10-17 확인. 다음 문서가 벤치마크 근거다.

- [TDS Colors](https://tossmini-docs.toss.im/tds-mobile/foundation/colors/): 회색 정보 위계와 파란 인터랙션. 작은 글씨는 명암 대비를 위해 더 짙은 단계 사용.
- [TDS Typography](https://tossmini-docs.toss.im/tds-mobile/foundation/typography/): 제목·본문·보조 문구의 역할 기반 크기. 웹에서는 rem과 유동 높이로 확대 지원.
- [Button](https://tossmini-docs.toss.im/tds-mobile/components/button/), [TextField](https://tossmini-docs.toss.im/tds-mobile/components/TextField/text-field/), [ListRow](https://tossmini-docs.toss.im/tds-mobile/components/ListRow/list-row-overview/), [FixedBottomCTA](https://tossmini-docs.toss.im/tds-mobile/components/BottomCTA/fixed-bottom-cta/): 상태가 일관된 조작부, 제목·내용·보조 액션 순서, 모바일 하단 주요 행동.
- [TDS 운영](https://toss.tech/article/toss-design-system), [시스템 재고](https://toss.tech/article/44097): 실제 사용 사례를 먼저 모으고, 반복되는 결정과 접근성을 공통 구현에서 해결한다.
- [라이팅 원칙](https://toss.tech/article/8-writing-principles-of-toss): 다음 행동이 보이는 문구, 짧고 명확한 해요체, 반복 설명 제거, 선택 존중.

## 작업 단위와 완료 기준

| 단위 | 산출물 | 검증 |
|---|---|---|
| 기반 | 의미별 토큰, 공통 버튼·필드·메시지·제목, 기존 아이콘 재사용 | 원천 중복·생값 색상·기본 상태 자동 검사 |
| 화면 이관 | 입력 5단계, 접수·분석·결과·부분 결과·실패, 저장·구독 팝업, 대시보드 5탭, 관리자 | 기존 기능 회귀, 모바일·PC, 초점·확대·모션 검사 |
| 반복 적용 | 실제 컴포넌트 전시 화면, 작업 규칙, 기여·버전·출시 절차 | 전시 화면 격리, CI 검사, 운영 미리보기 |

화면과 공통 기반은 함께 작동해야 하므로 하나의 배포 가능한 PR로 묶는다. 금융 계산, 분석 정책, 인증·저장 경계는 그대로 둔다.

## 정보와 배치

- 입력: 한 단계에 한 결정. 제목 → 필수 입력 → 선택 입력 → 다음 행동. 투자 목적은 계속 선택이다.
- 결과: 결론 → 바꿀 종목과 금액 → 추천 구성 → 근거·성과 → 계좌 전략. 매수·상승은 빨강, 매도·하락은 파랑이며 문구·부호를 반드시 병기한다.
- 대시보드: 한눈에(총자산·손익 → 구성·배당 → 보유 목록), 배당 달력, 수익 기록, 백테스트, AI 포폴 분석. 최근 분석은 기존 결과 화면을 재사용하고 새로 분석하기를 제공한다. 보유 수정은 한눈에의 행에서 열고 수익은 자동 기록한다. 시세·환율·비중은 고객에게 입력시키지 않는다.
- 고객 화면은 편안한 간격, 관리자는 높은 정보 밀도를 사용하되 색상·상태·조작법은 공유한다.
- 모바일은 한 열과 하단 주요 버튼, PC는 최대 폭 안에서 관련 정보 두 열. 고정 버튼에는 본문 여유와 safe-area를 확보한다.
- 모바일 보유 목록은 비중·평가금액·수익률·평가손익을 먼저 보여주고 상세 버튼으로 나머지 수치를 펼친다. PC는 전체 열을 유지한다. 연간 배당 표와 그래프는 올해의 이번 달을 처음부터 보여주며 다른 연도는 1월부터 시작한다. 화면 크기·글꼴 변경 뒤에도 초기 월을 유지하되 사용자가 직접 탐색한 뒤에는 위치를 되돌리지 않는다.
- 팝업: 저장이 주요 행동, 이메일 구독이 보조 행동, 평가는 마지막. 닫기·Escape와 기존 초점 복원을 유지한다.
- 대시보드 재방문: 같은 브라우저에서 대시보드가 정상 로드된 첫 방문을 기록하고, 두 번째 방문부터 방문당 한 번 앱 다운로드 바텀시트를 보여 준다. 탭 전환·React 재실행은 재방문으로 세지 않는다. 3초 뒤 표시하되 다른 팝업·종목 수정·분석 탭에서는 기다린다. 재방문에서는 이메일 팝업 대신 앱 안내를 보여 주며, 닫은 뒤 같은 방문에서는 다시 열지 않는다. 방문 기록을 저장할 수 없으면 앱 팝업을 자동으로 띄우지 않는다. 미리보기 방문 기록은 고객 기록과 분리한다. 실제 ZIP 소개 이미지 6장과 App Store 이동 버튼을 사용하며 전시 화면에서도 같은 시트를 확인할 수 있다.

## 원천 파일과 계약

`apps/etforca/portfolio-ui/src/design-system/tokens.css`가 색상·글자·간격·곡률·모션의 원천이다. `components.tsx`와 `components.css`는 공통 조작부를 소유한다. 화면 CSS는 화면별 구조·배치를 다루며 시각 속성에는 의미별 토큰을 사용한다. 기존 EDGE 콘솔의 `ui-kit` 아이콘을 재사용하며 콘솔의 금융 색상 의미를 포폴에 가져오지 않는다.

전시 화면은 `/portfolio/?preview=design-system`. 실제 화면과 동일한 컴포넌트를 렌더링하고 고객 API·분석·메일 발송 없이 동작한다. `confirmation.tsx`의 native dialog는 삭제·덮어쓰기의 취소, Escape, 초점 복원, 언마운트 시 취소를 공통 처리한다. 고객 화면 스타일은 `src/styles.css`, 관리자 구조는 `src/admin/styles.css`이며 관리자 안의 고객 보고서도 같은 토큰·컴포넌트 스타일을 Shadow DOM에 주입한다.

확인 후 비동기 작업을 수행하는 호출부는 작업이 끝나고 조작부를 다시 활성화한 뒤 `restoreFocus()`를 호출한다. 취소는 확인창이 직접 복원한다. 모바일 고정 CTA는 실제 높이만큼 본문 공간을 확보한다. 1100px 이상 PC 입력에서는 CTA를 본문 다음 흐름에 두어 요청사항을 덮지 않는다. 성과 차트는 컨테이너 실측 폭에 맞춰 좌표와 포인터 계산을 함께 바꾸고 높이를 180~300px로 유지한다. 정확한 금액과 선택 날짜는 차트 아래 rem 텍스트로 제공한다.

축의 여백은 실제 글자 폭으로 측정하고 글꼴 로딩·크기 변경 뒤 다시 계산한다. 긴 숫자나 확대된 글자 때문에 그래프 영역이 좁아지면 최소 80px의 그리기 영역을 확보하고 차트 안에서 가로로 이동한다. 페이지 전체에 가로 넘침을 만들지 않는다.

버튼은 primary / secondary / plain / danger, 필드는 기본 / 초점 / 오류 / 비활성, 메시지는 안내 / 성공 / 오류를 제공한다. 로딩 버튼은 이름을 유지하고 중복 입력을 막는다. 필드는 항상 연결된 label 또는 aria-label이 있어야 한다. 모달은 native dialog와 기존 초점 복원을 유지한다.

데이터 조회 대기는 공통 `Loading`과 기존 spinner를 사용한다. 포트폴리오 읽기·첫 시세 준비·최근 분석 복원은 서로 다른 문구로 구분하고, 오류 시에는 동작 중 모션 대신 재시도 행동을 제공한다. 모션 감소 설정에서는 회전을 멈추며 상태 문구는 남긴다. 대시보드 선택 탭은 `tab=overview|dividends|returns|backtest|analysis`로 복원하고, 보유 목록 조회 실패가 독립적인 최근 분석 조회를 막지 않는다.

색상만으로 상태를 전달하지 않는다. 본문 대비 4.5:1, 의미 있는 그래픽·초점 대비 3:1, 주요 터치 영역 44px 이상, 키보드 조작, 200% 글자 확대, reduced-motion을 검증한다. API 실패·빈 상태·일부 자료 없음·긴 종목명·큰 금액도 정상 상태와 같이 설계한다. 결측은 0으로 꾸미지 않는다.

## 반복 가능한 제작 절차

1. 과제: 사용자가 하려는 일, 다음 행동, 데이터·권한·실패 상태를 적는다.
2. 재사용: 전시 화면과 기존 호출부를 확인한다. 같은 역할의 컴포넌트가 있으면 사용한다.
3. 설계: 모바일·PC 배치와 기본/빈/로딩/실패/긴 내용/부분 자료 상태를 정한다.
4. 구현: 공통 토큰과 조작부를 사용한다. 새로운 공통 API는 실제 두 번째 사용처 또는 기존 컴포넌트로 해결되지 않는 근거가 있어야 한다.
5. 검증: `pnpm --filter portfolio-ui check:design`, `build`, `test:e2e`. 전시 화면·실제 화면·키보드·확대를 확인한다.
6. 리뷰: 화면 목적·데이터 정확성·접근성·문구·모바일/PC를 함께 본다. 디자인 변경은 코드와 같은 PR에서 검토한다.
7. 출시: dev PR → CI → 배포 → 버전이 표시된 미리보기 확인. 이상 시 해당 PR을 되돌린다.

## 운영과 변경 관리

포폴 프론트 유지보수자가 토큰과 컴포넌트의 소유자다. 승인 기록은 PR에 남긴다. 토큰 이름·컴포넌트 props 변경은 모든 호출부를 한 PR에서 이관하고 버전을 올린다. 제거할 API는 대체 경로·사용처 검색·이관을 먼저 끝낸다. 단순 시각 수정도 전시 화면과 대표 고객 화면을 함께 확인한다. 별도 Figma 사본을 코드와 경쟁하는 원천으로 만들지 않는다.

출시 기록: 1.0 — 토스 공개 패턴 기반 토큰·공통 조작부, 고객/관리자 이관, 전시 화면, CI 규칙 도입.


## 1.1 화면 마감 규칙

[조사·레퍼런스·문제 해결 기록](portfolio-ui-detail-research.md)에 판단 근거와 전후 화면을 남긴다.

- 글꼴: 고객·관리자 엔트리에서 `fonts.css`를 불러온다. Pretendard Variable 1.3.9 원본을 OFL 라이선스와 함께 빌드에 포함한다. 외부 폰트 CDN을 요청하지 않으며 swap과 시스템 대체 글꼴을 유지한다. 원본 파일은 약 2.06 MB이며 해시 자산으로 캐시한다.
- 위계: 총자산을 가장 크게, 비교 금액은 그다음, 라벨은 15px 역할 토큰을 사용한다. 카드 제목은 22px 역할 토큰, 구성 금액은 13px 역할 토큰이다. 숫자는 tabular-nums를 유지한다.
- 정렬: 보유 종목은 PC에서 고정된 종목 열과 가로 스크롤 비교 표, 모바일에서 라벨이 붙은 카드로 표시한다. 나란한 카드의 제목은 같은 높이의 heading 영역에서 시작한다. 자산 범례는 도넛 아래 이름·비중을 정렬한다.
- 상태 의미: 예상 배당은 청록색, 실수령은 별도 계열로 표시하며 합산하거나 겹쳐 쌓지 않는다. 연간 내역은 예상/실수령 모드를 분리하고 선택 월을 표시한다. 미확인 손익은 상승·하락 색을 갖지 않는다. 추가/수정 제목과 저장 중/완료 상태를 구별한다.
- 강조: 배경을 어둡게 하는 overlay 색을 그림자에 재사용하지 않는다. 큰 자산 행은 눌러도 축소하지 않고 배경으로 반응한다. 보조 칩과 주 행동의 시각적 무게를 구분한다.
- 문구: 버튼에는 행동명을 유지하고, 진행을 막는 조건은 현재 단계 가까이 설명한다. 비중 합계와 개별 종목 미입력을 구분한다. 선택 한도에서는 해제 후 재선택할 수 있음을 보여 준다.
- 검수: 같은 데이터·폭의 전후 화면, 글꼴 로드 이후의 동일 프레임 정렬, 320/768/1440px, 200% 글자, 긴 금액, 상태 변경, 키보드와 모션 감소를 확인한다. 시각 선호는 기능 테스트 통과와 별도로 평가한다.

출시 기록: 1.1 — 자체 제공 글꼴, 금융 정보 정렬·밀도·범례, 반응형 차트, PC CTA 흐름, 입력·저장 상태 마감.

## 고객 흐름과 입력 보존

### 자산 분류와 배당 표시

지역과 테마는 별도 축이다. 지역은 국내·미국·중국·일본·인도·유럽·아시아·신흥국·미국 외·글로벌·현금·미분류를 사용한다. 테마는 시장 대표·AI/기술·반도체·배당·커버드콜·채권·금/원자재·부동산·헬스케어·친환경/에너지·금융·현금·미분류를 사용한다. 알려진 종목 ID를 우선하고 이름의 명시적 투자 대상을 보조로 사용한다. 복합 테마는 커버드콜→반도체→AI/기술→배당 순으로 대표 테마 하나를 배정해 중복 집계하지 않는다. 상장 국가·거래 통화를 투자 지역으로 대체하지 않으며 제외 국가와 운용사 이름을 투자 대상으로 해석하지 않는다.

배당 요약은 현금 합계·연간 예상·월평균을 보여준다. 일부만 확인된 연간 합계는 완전한 연간 배당률이나 월평균으로 확대하지 않는다. 연간 종목×월 표는 확인된 값만 합산하며 조회 범위 밖과 미기록을 —로 표시한다. 기존 백테스트의 분배금 재투자 계산과는 별도 화면이다.

[UX 점검 기록](portfolio-ux-audit.md)의 16개 문제 단위를 회귀 기준으로 사용한다. 입력은 같은 탭의 sessionStorage에서 복원하며 금액·비율 값을 별도로 보관한다. 미리보기와 고객 보관 키를 분리하고, 완료한 분석과 연결된 초안만 자동 정리한다. 절세 창의 미적용 입력은 전체 분석을 막지 않는다.

작성 중인 자산을 버리는 이동에는 확인을 제공한다. 백테스트 조합과 기간은 탭 이동 후에도 유지한다. 시세·환율·비중과 수익 기록은 서버가 계산하며 수동 입력 폼을 제공하지 않는다. 비중만 가져온 경우 총 투자금을 받아 금액으로 바꾸고, 실제 수량 없이 추적하는 보유분은 금액 기준임을 표시한다. 저장 완료는 화면과 보조 기술에 함께 전달한다. 배당 차트는 향후 12개월을 연·월로 표시하고 좌우 스크롤·키보드·이동 버튼을 지원한다.

첫 종목 입력에서는 계좌를 옅은 배경의 패널로 묶고 종목 사이에는 구분선, 수정 가능한 숫자·검색 필드에는 테두리를 둔다. 모바일에서는 입력한 내 포트폴리오 도넛을 계좌 입력 위에 먼저 보여주며 PC에서는 오른쪽에 둔다. 분석 대기·진행 화면은 단계 표시와 함께 종목·산업·경제 분석에서 포트폴리오 매니저·리스크 매니저로 이어지는 역할 도식을 유지한다. 도식은 한 AI의 검토 관점이며 독립 에이전트의 동시 실행을 뜻하지 않는다.

자동 팝업은 현재 읽는 초점을 유지한다. 직접 여는 팝업은 초점을 이동하고, 닫을 때 실제 진입 직전 위치로 복귀한다. 목록 키보드 탐색은 목록 내부만 스크롤한다.

대시보드 보유 목록은 수량·평균매수가가 비어 있는 행에 기본 강조색 테두리와 입력 안내를 함께 표시한다. 해당 편집창이 실제로 열리면 그 방문 동안 강조를 해제하며 탭 이동으로 되살리지 않는다. 보유가 없는 행과 현금에는 입력을 요구하지 않는다.

대시보드 이메일 안내는 진입 약 10초 뒤 여는 모달이다. 기존 자동 안내의 초점 유지 방식과 달리 native dialog 안에서 초점을 관리하며 닫을 때 이전 조작부로 복귀한다. 자산 편집·다른 팝업·숨겨진 탭·AI 분석 화면에서는 노출을 미룬다. 기존 구독자와 안내를 닫은 브라우저에는 반복 표시하지 않고, 신청 버튼과 이메일 확인을 통해 동의를 받는다. 미리보기는 모의 응답만 사용한다.

이 안내의 뉴스레터 신청은 compact 변형을 사용한다. 짧은 제목·한 문장 설명·실제 예시 이메일 캡처·이메일 입력·신청 버튼 순서로 배치하며 중복 소개와 인용문은 생략한다. 캡처를 누르면 전체 이미지를 볼 수 있다. 수신 동의와 해지 안내는 유지한다.

연간 예상 배당과 배당률·월평균은 최근 1년의 확인된 주당 현금 분배금 원값과 보유 수량·현재 환율로 계산한다. 표시용으로 반올림한 배당률을 금액 계산에 역산하지 않는다. 향후 월별 일정의 일부 구간이 비어 있다는 이유로 연간 배당을 0원으로 환산하지 않는다. 월별 달력과 연간 표는 확인된 금액과 해당 월의 관측 범위를 별도로 관리한다. 당일 갱신되지 않은 자료는 연간 파생 수치를 확정하지 않는다.
