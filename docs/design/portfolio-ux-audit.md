# 포트폴리오 고객 흐름 UX 점검

2026-10-18. 입력 → 분석 접수 → 결과 읽기 → 대시보드 저장 → 자산·배당·수익 기록 수정 흐름을 점검했다. 미관 평가와 구분해, 고객의 입력이 사라지거나 다음 행동이 막히거나 저장 결과를 오해하는 문제를 대상으로 삼았다.

## 구조를 바꾼 이유

입력 임시 보관은 `inputDraft.ts` 한 곳에서 읽고 검증한다. 서버 초안·분석 결과·대시보드의 기존 API와 소유권 검사는 그대로 사용한다. 금액과 비율은 서로 자동 환산하지 않는다. 총액이 없는 비율 입력에 임의 금액을 만들지 않기 위해서다.

대시보드는 저장 API 전체가 성공했다고 현재 작성 중인 폼까지 저장됐다고 판단하지 않는다. 해당 폼의 저장·명시적인 취소·성공한 재조회에만 미저장 상태를 해제한다. 금융 계산은 기존 `workbook.ts`를 사용하고 UI는 어떤 입력으로 계산하는지 드러낸다.

투자 목적은 선택 사항이다. 절세 창의 필수 선택 검사는 그 창의 적용에만 해당하며, 창을 취소하면 기존 정보로 포트폴리오 분석을 계속한다. 새 라이브러리·AWS 자원·API·데이터베이스 스키마는 추가하지 않았다.

- 입력·접수·진행·결과·부분 결과·실패·대시보드·빈 대시보드·구독 확인·디자인 시스템을 운영 미리보기에서 확인한다. 미리보기는 실제 고객 API 쓰기·LLM 분석·메일 발송·PostHog 수집을 만들지 않는다.
- 320·768·1440px, 키보드, 초점, 200% 글자 확대, reduced-motion, 저장 실패, 여러 탭, 저장소 사용 제한을 검증 범위에 둔다.

검증 실행 결과와 배포 커밋은 이 문서를 추가한 PR의 CI·배포 기록을 따른다. 실제 고객 인터뷰, 실기기 Safari, 모든 모바일 키보드 조합은 확인하지 않았다. sessionStorage는 같은 탭의 임시 보관이며 기기 간 복원·영구 백업을 약속하지 않는다. 이번 작업은 UI 흐름 검증이며 새로운 LLM 분석 품질 평가를 실행한 것은 아니다.
