# 투자정보 기만 검증 서비스 설계

상장종목 투자자를 오인하게 한 주장과 후속 해명을 원문과 시간순 기록으로 대조해 `etforca.com/truth/` 에 공개한다. 조사 기준은 [투자정보 기만 검증 조사 방법론](truth-investigation-methodology.md)이 정본이다. 이 문서는 그 방법론을 데이터·화면·자동 갱신으로 옮기는 방식을 정한다.

## 1. 구성

| 모듈 | 역할 | 배포 |
|---|---|---|
| `apps/etforca/truth-web` | 정적 화면 3장(홈·사건 상세·목록). 빌드 도구 없음 | `deploy-truth-web.yml` → 랜딩 버킷 `truth/` 접두어 |
| `apps/etforca/truth-agent` | 사건 계약 검사, 공개 데이터 생성, 매시 사건 갱신 에이전트 | 컨테이너 이미지 → ECS Fargate 예약 실행 |

사이트는 랜딩(`etforca.com`)·포트폴리오(`/portfolio/`)와 같은 CloudFront·버킷을 쓰고 접두어만 나눈다. 새 배포·인증서·DNS가 필요 없다.

## 2. 데이터 계약

사건 하나 = JSON 파일 하나다. 형식은 [case.schema.json](../../apps/etforca/truth-agent/src/edge_truth_agent/case.schema.json), 스키마로 표현할 수 없는 규칙은 `edge_truth_agent/cases.py` 가 검사한다. 필드는 방법론 §7 '사건 결과'에 대응한다.

| 방법론 항목 | 필드 |
|---|---|
| 연결 종목 | `instruments` (1개 이상) |
| 조사 대상 발언자와 수신자 | `speaker`, `audience` |
| 공개용 두 문장 | `headline[0]`, `headline[1]` |
| 목록·홈에서 훑어 읽는 짧은 제목 (주체 이름 + 무슨 일, 6~28자, 판정·감정 낱말 금지) | `title` |
| 뉴스 배정 (이름·별칭, 사건 고유 주제어) | `aliases`, `topics` — 공개 관련 보도는 제목에 이름과 주제어가 함께 있을 때만 붙는다 |
| 적용 유형과 유형별 판정 | `behaviors[]` — 6유형 × 확인·의심·반증·자료 부족 |
| 행동·고의·피해·법적 책임의 확인 수준 | `levels`, `legalStatus` |
| 가장 설명력 높은 가설·가장 강한 반증·결론을 바꿀 증거 | `ach` |
| 경제적 수혜자·위험 부담자 | `beneficiary` (미확인이면 생략) |
| 원문 위치·접근일 | `sources[]` (`publishedAt`, `accessedAt`) |

검사기가 지키는 규칙:

- **판정은 공식 출처로만 바뀐다.** `confirmed`(밝혀짐)는 공식 판단(`official`)이나 법정공시(`disclosure`), `refuted`(해소)는 공식 판단만 근거로 삼는다. 보도나 당사자 해명은 판정을 바꾸지 못한다. 근거 출처는 주소가 기관·공시 도메인이어야 하고, 반론으로 인용된 출처일 수 없다.
- **확인일은 근거가 나온 날이고, 기록일은 출처를 본 뒤다.** `resolvedAt` 은 근거 출처 발행일과 같아야 하고, `flaggedAt` 은 가장 이른 출처 접근일보다 이를 수 없으며, 출처 접근일은 그 출처 발행일보다 이를 수 없다. 두 날짜를 옮겨 '먼저 기록한 사건'처럼 보이게 해 적중률을 부풀리는 것을 막는다.
- **인용은 출처 목록 안에서만 한다.** 본문·대조·반론·유형 판정이 가리키는 `sourceId` 는 모두 `sources` 에 있어야 한다.
- **공개 문장은 확인 수준을 넘지 않는다.** `headline` 에 '거짓말'·'사기꾼' 같은 단정어를 쓰지 않는다. 수사기관·당사자 주장은 주체를 밝혀 쓴다.
- **미래 날짜는 없다.** 확인일·공개일·접근일이 오늘 이후면 거부한다.

공개 데이터는 사건 파일에서 코드가 만든다(`edge_truth_agent/site.py`).

| 파일 | 내용 |
|---|---|
| `truth/data/index.json` | 홈·목록·검색용 요약 (사건별 한 줄) |
| `truth/data/cases/<id>.json` | 상세 페이지용 사건 전체 |

공개본에는 비공개 보관 위치(`sources[].snapshot`)와 내부 표시(`locked`)를 싣지 않는다.

## 3. 화면이 보여주는 숫자

- **확인된 거짓 이슈**: `status = confirmed` 인 사건 수. 공식 판단으로 행위가 확인된 사건이다.
- **적중률**: 이 서비스가 확인일보다 **먼저** 기록한 사건(`flaggedAt < resolvedAt`) 중 `confirmed` 비율이다. 확인 뒤에 정리한 사건은 '밝혀짐·해소'로만 표시하고 적중률에 넣지 않는다. 그런 사건이 아직 없으면 '집계 전'으로 표시한다.
- **파급력 가치**: 0~100억원 범위의 점수(`impact`, 단위 억원)다. 방법론 §3에 따라 조사 우선순위를 정하는 값이며 증거가 아니다. 상세 화면에 이 한계를 함께 적는다.

## 4. 사건 갱신 (에이전트)

매시 실행하며, 판단은 모델이 하고 조회·검사·저장·판정 반영은 코드가 한다(AGENTS.md Rule 5).

1. **기사 배정 (코드)**: 기존 뉴스 레인이 레이크에 쌓은 기사(1분 수집 원본 + 하루 2회 정제본)에서 지난 실행 이후 기사를 읽고, 사건의 종목명·별칭과 맞는 기사를 사건별로 쌓아 둔다. 쌓인 기사는 그 사건을 실제로 조사하거나 계획이 건너뛸 때까지 남는다(사건당 최신 20건).
2. **관련 보도 추가 (코드)**: 제목에 이름과 사건 주제어가 함께 있는 기사를 `related` 에 붙인다.
3. **조사 계획 (모델)**: 후보 사건이 있으면 계획 세션을 연다. 후보는 쌓인 기사가 있거나, 한 번도 조사하지 않았거나, '다음에 찾아볼 것'이 남았고 24시간이 지난 사건이다(코드가 고른다). 계획 세션은 후보 목록(제목·상태·파급력·새 기사·할 일 개수·마지막으로 본 때)과 새 기사 제목만 보고, 조사할 사건 순서(최대 4건)와 건너뛸 사건을 정한다. 노트 본문은 보지 않는다. 계획은 비공개 버킷 `plans/<날짜>/<실행>.md` 에 남는다.
4. **사건별 세션 (모델)**: 계획 순서대로 사건 세션을 **하나씩** 연다. 세션은 그 사건 파일, 새 기사, 그 사건의 **조사 노트 하나**(비공개 버킷 `notes/<사건 id>.md`: '다음에 찾아볼 것'과 최근 조사 기록 8개)를 받는다. 하네스는 pi 이며 기본 도구(bash·파일 읽기·쓰기)는 모두 끄고 아래 도구만 준다. 세션당 도구 50회, 마지막 5회는 마무리(노트·검사·끝내기) 전용이다.
   - 편집: 사건 JSON 의 칸 단위 보기·문자열 교체·값 설정·본문 추가 (정확히 한 군데 일치할 때만 교체, 먼저 보지 않은 사건은 수정 거부)
   - 찾기 창구 ① 빅카인즈 수집 기사 검색(최근 21일), ② Exa 웹 검색·원문 가져오기 (가져온 원문은 인용 검증용으로 보관)
   - 판정 제안, 파급력 점수 설정, 검사(`check`)
   - 조사 노트 갱신(`write_notes`): 다음에 찾아볼 것(통째 교체)과 이번 조사 기록 한 항목. 형식·지난 기록 보존은 코드가 맡는다. 끝내기 전에 반드시 한 번 쓴다.
5. **검사와 렌더 (코드)**: 세션 안에서 `check` 도구가 계약 검사와 실제 화면 렌더를 하고, 통과해야 `finish` 로 끝낼 수 있다. 세션이 끝나면 코드가 같은 검사와 렌더를 다시 하고, 깨진 사건만 이전 버전을 유지한다. 세션이 실패했거나 되돌린 사건은 코드가 노트에 그 사실을 적고, 쌓인 기사는 다음 실행의 계획 후보로 남는다(3번까지), 그런 사건이 있으면 실행이 실패 코드로 끝난다. 알림은 보내지 않고 로그와 실행 보고로 본다.
6. **게시 (코드)**: 비공개 버킷의 사건 파일을 조건부 쓰기로 갱신하고, 공개 데이터를 다시 만들어 `truth/data/` 에서 바뀌었거나 빠진 파일만 올린다.

새 사건은 사람이 seed 로 넣는다. 에이전트(모델)는 기존 사건 관리에만 쓰고, 새 사건 찾기(`run discover`)는 운영 일정에 두지 않는다. 수동으로 돌리면 세션을 차례로 열어 최대 3건을 등록한다. 새 사건은 서로 다른 매체 2곳 이상의 보도가 있을 때만 '판단 중'으로 등록한다. 에이전트가 등록한 사건은 화면에 'AI 감시 중'으로 표시한다. 사람이 손본 사건에 `locked: true` 를 두면 에이전트가 수정하지 않는다.

## 5. 처음 게시하는 사건

정정·게시 중단이 급하면 `deploy-truth-web.yml` 을 `reseed=true` 로 수동 실행해 seed 로 공개 데이터를 다시 쓴다(seed 에 없는 사건 파일은 지운다).

`apps/etforca/truth-agent/seed/` 의 33건은 사람이 조사한 시작 사건이다. 처음 4건(하이브·금양·홈플러스 단기채·고려아연 2024년 증자)은 2026-10-20 기준 공개자료 조사이고, 나머지 29건은 탐색목록(`reports/한국 주식 기만 사건 탐색목록.md`)의 후보 행을 2026-10-21 기준으로 추가 조사해 옮긴 것이다.

- 판정: 밝혀짐 5건, 해소 2건, 판단 중 26건이다. 밝혀짐·해소는 판결 원문(law.go.kr·scourt.go.kr)·금융위 의결·법정공시를 직접 열어 확인한 경우만이고, 확정 판결이 보도로만 확인되면 판단 중으로 두고 `legalStatus` 에 적었다.
- 모든 출처는 조사 때 직접 열어 읽은 주소이고, 핵심 주장마다 서로 다른 출처 2곳 이상을 두었다. 종목 코드는 거래소(KIND) 상장·상장폐지 목록과 대조했다.
- 탐색목록 행 중 종목이 익명이거나(공식 원문이 종목을 가림) 상장종목 연결·출처 2곳 조건을 채우지 못한 행, 기존 사건과 같은 행은 넣지 않았다.
- 모두 확인 뒤에 정리했으므로 적중률에 들어가지 않는다. 예시용 가상 사건은 게시하지 않는다. 대표 사진(`cover`)은 넣지 않았다(언론 사진 무단 사용 방지).

## 6. 한계

- 저장된 뉴스는 제목과 200자 안팎의 요약뿐이다. 기사 문장을 인용하려면 원문을 가져와 보관한 뒤 그 원문과 대조한다.
- 1분 뉴스 수집은 평일 장중에만 돈다. 그 밖의 시간에는 하루 2회 정제본이 들어올 때 새 기사가 반영된다.
- 이 서비스의 판정은 공개자료 대조이며 법적 판단이 아니다. 수사·제재 단계는 `legalStatus` 에 마지막으로 확인한 절차만 적는다.
