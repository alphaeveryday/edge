# Ontology backing views

These ordinary PostgreSQL views preserve the existing object identities and expose the keys needed for graph edges. They do not modify ingestion tables or copy records into graph storage.

Flyway applies them. `libs/schema/migrations-cloud/V202610241930__adopt_ontology_views.sql` creates the `ontology_view` schema, all views in dependency order, and SELECT for `agent_ro` and (when the role exists) `ontology_graph_ro`, including default privileges for later views. Do not apply files from `views/` by hand. To change a view, edit its file here and add a new migration with the same `CREATE OR REPLACE VIEW` text in the same pull request; `tests/test_ontology_view_migrations.py` fails when a file and its newest migration differ. `CREATE OR REPLACE VIEW` can only add columns at the end; renaming or removing a column needs `DROP VIEW` first (no CASCADE) and any dependent view recreated in the same migration. View PK/FK roles are contracts checked by validation; PostgreSQL views do not create those constraints.

The Company–Equity path uses `company.id`, `equity.id`, and `equity.issuer_id`. The equity view supplies both Equity nodes and Company→Equity edges. No separate issuer-relation view or reverse-edge copy is necessary. Run `check_core.sql` after application; it raises an error on missing/duplicate identities or a changed issuer relationship.

Core cloud verification on 2026-10-05: 2,766 companies, 2,766 equities, and 2,766 issuer pairs matched the source. Forward and reverse PuppyGraph queries returned the same exact pairs. The pilot used PuppyGraph 1.13.0, image digest `sha256:8e362b158d8dde1ae9ed6df54f6751630af72a47d061bb2db42fa16547b368f7`, with external PostgreSQL reads and no local replication. These results establish correctness for this path and dataset, not a performance advantage or whole-ontology completion.

Deployment credentials and environment-specific launch scripts are intentionally not part of the SQL package. The `ontology_graph_ro` login role has a password, so it is created outside Flyway; the migration only grants to it. Roll back a view with a new migration that runs an explicit `DROP VIEW ontology_view.<name>`, after checking its dependents; do not use CASCADE.

`puppygraph-schema.json` is the graph mapping (26 node and 39 edge labels over these views, no connection or credentials). It is the copy uploaded to the 2026-10-05 pilot. The ECS service in `infra/terraform/modules/ontology-graph` uploads it at every start, because PuppyGraph 1.13 keeps no schema across restarts. `tests/test_puppygraph_schema.py` fails when a mapped view column or source table column no longer exists, so change the mapping in the same pull request as the view.
