# ADR-002: 뉴스 본문 수집과 LLM 정규화 입력 계약

## Context

최신 구간 뉴스 정규화는 DeepSeek V4 Pro 티처(gate+type)로 수행한다(2026-06~07 기실행, 60,893건).
그런데 BigKinds 저장 `content`는 **~208자 절단 발췌**다(중앙값 208자, p99 246자) — 지금까지 "본문"으로
취급하던 필드가 실제 본문이 아니다. 진짜 본문은 기사 원문 URL(`link`, 결측 0%)에만 있다.

제목-only 입력의 손실과 본문 전달의 비용을 2026-06 층화표본(n=1,500, 수집 성공 1,408)으로 실측했다.
아래 근거의 수치는 전부 `exp_body_vs_title.sqlite`(라벨 8,631행 + 호출별 토큰 usage)에서 재현 가능하다.

## Decision

1. **본문은 원문 URL에서 수집한다.** 상장사 프리필터 통과분만(월 ~44k건), 호스트별 동시 4·간격 0.3s의
   예의 준수 크롤 + trafilatura 노이즈 제거. 전역 병렬은 호스트 수가 상한이다.
2. **LLM 정규화 입력 = 제목 + 수집 본문 앞 600자(`body600`)를 표준으로 한다.**
   full(3000자)은 재판정·감사 경로에만, 저장 발췌(excerpt)는 수집 실패·크롤 전 임시 대체재로만 쓴다.
3. **분류 호출은 thinking OFF를 고정한다.** (reasoning 토큰이 `max_tokens`를 잠식해 빈 응답·재시도
   스톨을 만들던 실측 결함의 재발 방지. 판정(judge) 경로만 thinking 유지.)
4. **게이트는 계단화한다.** 인코더 증류 모델이 EVENT 후보를 1차 압축(recall 우선)하고, LLM은 통과분만
   본다. 증류 모델 승격 기준은 기존 head 선례 수준(teacher-relative ≈ 90%) 충족이다.
5. **인자(entity/quantity/time) 추출은 결정론 어셈블러가 수집 본문으로 수행한다.** LLM에 위임하지 않는다.

## Why — 핵심 실측 근거

**(1) 제목만으로는 게이트·타입이 깨진다.** full-body 기준 대비(n=1,407):

| 입력 | doc_class 일치 | EVENT 게이트 일치 | type 일치 |
|---|---|---|---|
| 제목만 | 81.8% | 86.6% | 76.7% |
| 발췌(저장) | 87.1% | 89.9% | 85.5% |
| **body600** | **90.3%** | **93.2%** | **87.2%** |

제목-only는 EVENT 판정 13.4% 플립(놓침 82 + 과잉 107), 타입 교정 145건(진출↔출시↔제휴 등
인접 타입이 본문에서 구체화). body600은 full 정보의 90%+를 회복한다.

**(2) 하류 결정론 추출의 이득이 더 크고, 비용은 0이다.** (n=1,408)

| 입력 | entity | quantity | time |
|---|---|---|---|
| 제목만 | 53.1% | 21.3% | 0.7% |
| **full(수집)** | **87.4%** | **76.3%** | **30.0%** |

**(3) 비용은 통제 가능하다.** v4-pro 실측 토큰×공식 단가(캐시 히트 시스템 프롬프트 포함):
body600 = **$229/100만건** (full $475의 48%) — 월 44k건 $10, 20년 백필 7.9M건 $1.8k.
게이트 계단화(2안 인코더) 적용 시 LLM행 문서가 ~40%로 줄어 월 ~$4.

**(4) 수집은 싸고 예의를 지킬 수 있다.** 실측 15.6 docs/s(호스트별 동시 4·0.3s), 성공 93.9%,
평균 1,342자(발췌의 6.5배). 프리필터 월분 47분, 전체 월분 2.2h.

**(5) 인코더 복제는 가능하다 — 분류와 아규먼트 span 모두.** 분류: 최저가 하한(TF-IDF+선형, 티처
6만건 증류)만으로 EVENT 이진 87.7%(F1 0.898) — 저장소 BERT류 head 선례는 89.5~92.4%
teacher-relative. 아규먼트: 티처 span 프로브(EVENT 300건, body600, `exp_arg_extraction.py`)에서
span 실존율 **99.3%**(verbatim — BIO 정렬로 토큰 라벨 파생 가능), 필수 role 충족 **98.4%**,
ISSUER류가 결정론 링커와 **둘 다 링크 시 97.9% 일치**(불일치 나머지는 대부분 미상장·별칭 밖 주체
= 결정론이 버리던 케이스). 비용 $279/1M건, 분류와 단일 호출로 합치면 두 태스크 합산 ~$310/1M.
단 AMOUNT는 티처도 안 뽑는다(0건) — 수량·시간은 regex가 이미 76%/30%로 소유(결정 5 유지).

## Alternatives

| 대안 | 판단 |
|---|---|
| 제목-only 유지 (현행) | 가장 싸지만 게이트 13.4% 플립·타입 76.7%는 스레딩·novelty 품질을 직접 훼손 |
| 저장 발췌만 사용 | 수집 없이 +5~9pp — 임시 대체재로만. 208자 절단이라 quantity/time 추출 상한이 낮음 |
| full(3000자) 표준 | 정보 상한이지만 body600 대비 +10pp 미만 이득에 비용 2.1배 |
| flash로 전환 | body600 기준 $74/100만건. 티처 품질 검증 전 — 게이트 1차 후보로만 |
| 인코더-only | 분류는 되나 신규 타입·저빈도 타입·리뷰 큐 품질이 티처 없이는 표류 |

## Consequences

- 수집 파이프라인이 신설된다(호스트 예의 정책 포함). 링크 부패 리스크: 실패율 4.7%는 2026년 기사
  기준 — 과거 연도 백필일수록 생존율이 떨어지므로 발췌 폴백이 계약의 일부다.
- 어셈블러 `--content-glob`의 의미가 "발췌"에서 "수집 본문"으로 승격되어야 한다(입력 소스 교체).
- 아규먼트 인코더 증류(BIO/MRC)가 후속 후보로 열린다: 역할 배정(SUPPLIER↔CUSTOMER)과
  비상장·자유텍스트 역할(CONTRACT_OBJECT·PRODUCT·PARTNER)은 인코더가 span을 뽑고,
  ORG_KR_* ID 연결은 기존 결정론 별칭 인덱스가 유지한다. 링킹까지 인코더로 옮기지 않는다.
- 수치 의미 레코드(`exp_numeral_probe.py`, n=123+79): 수치 span 실존율 99.8~100%,
  num_type(목표주가·계약금액 등) 분류·방향(상향/하향) 감지는 인코더 증류 가능 형태.
  단 개정(from→to) 페어링은 numeral-행 스키마의 metric_ref 키 조인이 12%로 깨짐 —
  개정 레코드는 {지표, from, to, 방향} 단일 오브젝트 스키마로 뽑아야 하며, 해당 타입
  (실적·가이던스·애널리스트, EVENT의 ~6%)만 LLM 조립을 유지한다. regex는 여전히
  어셈블러 완결성용 값 추출만 소유한다(결정 5의 범위 명확화).
- 티처 캐시·epoch_out 스키마는 불변. 입력 변형은 라벨 provenance(`model` 태그)로 구분한다.
- 인코더 증류 학습 라벨은 이미 확보된 티처 캐시(60,893건)로 시작하고, body600 라벨로 갱신한다.

## Revisit when

- 크롤 실패율이 월 15%를 넘거나(링크 부패), 언론사 차단이 관측될 때.
- flash 또는 증류 인코더가 body600 기준 teacher-relative 95%+를 달성해 pro 호출이 감사 전용으로
  물러날 수 있을 때.
- BigKinds가 전문(full-text) 제공 계약으로 바뀌어 수집 자체가 불필요해질 때.
