## 가설이 틀려서 고친 것

| 관측 | 원인 | 고친 곳 | 효과 |
|---|---|---|---|
| 종류 이름을 `Security`로 지어내 오류, 그 뒤 구조 읽기 | 도구가 유효한 종류 이름을 알려 주지 않았다 | `object_type` 인자를 실제 종류 목록(enum)으로 | 오류 0, 구조 읽기 0 |
| 37건을 다 받은 뒤에도 검색어·종류를 바꿔 최대 8회 재검색 (입력 12만 토큰) | 응답이 무엇을 기준으로 찾았는지 말하지 않아 누락을 의심했다 | 응답에 `matched_properties`·`match` 추가, 설명에 "변형 검색 불필요" | 1회 검색, 입력 1.8만~4.1만 토큰 |
| 검색으로 찾은 종목을 `resolve_securities`로 "확인" | 같은 자료를 두 번 읽는 것을 검증으로 여겼다 | `resolve_securities` 설명에 "다른 도구가 돌려준 대상은 이미 확인된 것" | 재확인 호출 0 |
| 구조 응답이 23KB | 링크마다 표시용 이름 묶음이 실려 있었다 | 역방향 이름만 남김 | 16KB |

내 가설이 틀렸던 것: `search_objects`를 2회 이하로 본 기준. 회사를 찾은 뒤 그 회사 ID로 주식을 다시 검색한 세 번째 호출은 발행 관계를 따라간 올바른 조회였다. 기준을 "같은 인자 반복 없음, 3회 이하"로 고쳤다. 이 경로는 `get_linked_objects`가 들어오면 `Company_Issues_Equity` 링크로 가야 한다.
