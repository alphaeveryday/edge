## 풀지 못한 것

- **없는 것을 확인하는 질문에서 검색이 20~35회로 늘어난다** (P-LO-1 "보통주 말고 더 있는지", 입력 최대 62만 토큰). 에이전트는 관계 조회를 맞게 한 뒤, 주식 자료에 우선주가 아예 없다는 것을 알아내려고 다른 종목·다른 자료 종류를 계속 찾는다. 판단 자체는 타당하다. 실제로 주식 자료에는 보통주만 있다. 도구 응답 문구로는 멈추지 않았다. 엔진의 조사 규칙(`prompts/research.md`의 "빈 검색은 구조적 한계가 아니다")과 맞물린 문제라 도구 범위 밖이다.

## 밸류 도구가 실패하는 원인 (진단만, 2026-10-06)

기준선 실행 `6e29f273…`의 입력으로 확인했다. PLUS K방산 구성 10종목의 최근 4분기 자료다.

- `calculate_valuation`은 4분기 모두에 EPS와 BPS가 **둘 다** 있어야 계산한다. 그런데 BPS는 1·3분기 보고서에 대부분 없다(`BPS_ABSENT_IN_LATEST_VERSION`, 2026-Q1 7종목·2025-Q3 5종목). PER은 EPS 4분기만, PBR은 최근 분기 BPS만 있으면 되므로 조건이 필요 이상으로 넓다. 지금 통과하는 종목은 LIG넥스원·SNT다이내믹스 2개뿐이다.
- 조건을 지표별로 나누면 PER은 7종목(비중 합 65.7%), PBR은 7종목(65.3%)에서 계산된다. 개별 종목 밸류와 `calculate_valuation_range`의 입력은 생긴다.
- ETF 전체 가중 PER·PBR은 그래도 70%에 못 미친다. 한화에어로스페이스(24.1%)의 2025-Q3·Q4 EPS와 전 분기 BPS, 한화시스템(9.8%)의 전 분기 값이 저장소에 없다. 이것은 수집 쪽 공백이라 도구로 풀 수 없다 → 뷰 기록에 옮긴다.

## 열린 문제

- 기준시각이 적용되지 않는 종류가 있다. 회사·주식·ETF·기관·개념·지수는 현재 상태 한 줄뿐이라 자를 시각이 없고, 응답의 `cutoff_applied`가 false다. 사건 묶음은 열린 시각으로 자르지만 요약 문구에는 이후 사건이 반영돼 있을 수 있다.
- 실행기는 그래프 도구만 가진 에이전트를 돌린다. 엔진의 기존 DB 도구와 함께 있을 때의 선택은 아직 확인하지 않는다.
- `get_etf_holdings`는 엔진의 기존 도구를 대체하지 못한다. 수집 완전성 상태가 뷰에 없다 (뷰 기록 참조).
- 그래프 연결이 긴 실행 중 끊긴 적이 있다("defunct connection"). 실행마다 연결을 새로 여는 것으로 피했다.
- `src/uv.lock`에 `neo4j` 추가와 무관한 `sys_platform != 'emscripten'` 마커 변경이 섞여 있다. 로컬 uv가 다시 쓴 것이다.
