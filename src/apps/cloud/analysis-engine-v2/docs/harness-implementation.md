# 분석 작업 하네스

승인 범위: OMP의 작업 상태·미완료 알림·후속 실행 패턴을 현재 SDK에 적용한다. 분석 방법은 AGENTS.md, 시스템 프롬프트는 작업 수행·도구 경계·완료 처리에 집중한다. 기본 스킬 강제 읽기나 결과물 파일 제출 검사는 추가하지 않는다.

## 작업 단위와 검증

1. 개별 종목 밸류는 관측된 종목 자료로 계산하고 전체 ETF 가중 계산은 확인된 구성 비중의 합이 70% 이상일 때만 한다(ALPHA-1238에서 바뀐 규칙). 안전한 자료 오류를 내부 오류와 구분한다.
2. 최초 입력은 대상·자료 목록·범위·누락 정보를 요약한다. 기존 원자료를 페이지로 다시 읽을 수 있게 한다. 고정 시점과 원본 감사 기록은 보존한다.
3. 분석별 notes/ 안에 마크다운 읽기·쓰기·수정 및 폴더 생성을 허용한다. 승인 문서·플러그인·작업공간 밖은 수정하지 못한다. 작업 상태와 메모는 감사 스냅샷으로 남긴다.
4. OMP처럼 TODO 상태를 보존하고 미완료 작업이 남은 정상 종료에 구체적인 알림을 넣어 같은 대화를 재개한다. 최대 3회 후에도 남으면 미완료로 실패하며 발행하지 않는다. 도구 호출·사용자 출력 JSON은 기존 계약을 유지한다.
5. 고정 자료 반복 실행으로 공개 대안 조사와 결론 수정 여부를 평가한다. 타임아웃·재개·중복 전달과 모델별 실행을 별도 확인한다. JSON 적합성은 의미 품질 통과로 보고하지 않는다.

## 운영 경계

도구 계산·라우팅·재시도·상태 저장은 코드가 맡고 질문·중요성·경쟁 설명·근거 해석은 모델이 맡는다. 모든 할 일을 완료 처리했다는 사실만으로 투자 판단의 충분성이 증명되지는 않는다. 자료 미확보와 구조적 불가능을 구분하는 행동 평가는 별도로 기록한다.

Jira 이슈는 ALPHA-1239다. 로컬 작업은 이슈 없이 시작했고, dev에 올리면서 이슈를 만들었다.

## 문맥 압축과 조사 재개

DeepSeek 모델을 SDK에 전달할 때 `[1m]`을 붙여 100만 토큰 문맥을 명시한다. `CLAUDE_CODE_AUTO_COMPACT_WINDOW=1000000`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=80`을 설정한다. 실행 바이너리 2.1.289는 출력 여유 20,000토큰을 뺀 유효 문맥 980,000의 80%, 즉 784,000토큰에서 자동 압축한다. 800,000에서 정확히 실행된다고 설명하지 않는다. 초기의 200,000 설정은 폐기했다.

PreCompact에서 기존 notes/와 TODO를 감사 스냅샷에 보존한다. 다음 허용 도구의 PreToolUse에 AGENTS.md 재독, 색인과 관련 메모 복구, 미해결 질문 조사 재개를 전달한다. 복구 지시 전달 전 StructuredOutput은 거절한다. 도구 없이 종료하면 runner가 결과를 채택하지 않고 같은 클라이언트에 복구 메시지를 보내 다시 실행한다. Python SDK에서 지원하지 않는 PostCompact에 의존하지 않는다. 압축 실패에도 복구 지시가 남을 수 있으며 이 경우 기존 대화에서 조사를 재확인한다.

메모를 새로 작성하는 모델 호출은 PreCompact 안에서 실행하지 않는다. 모델이 조사 중 notes/index.md와 주제별 메모를 갱신하도록 지시하며, 훅은 이미 저장된 상태를 보존한다. 색인·상태 주입은 총 12,000자 이내이고 전체 메모를 무조건 재주입하지 않는다. 압축은 동일 실행 내부에서 이루어지므로 작업 폴더를 유지하며 전체 실행 종료 시 임시 작업 폴더를 제거한다.

로컬의 실제 SDK와 가짜 제공자 응답을 연결한 통합 시험에서 contextWindow=1000000, 780,000토큰 응답 뒤 압축 없음, 785,000토큰 응답 뒤 자동 PreCompact와 compact_boundary, 이후 도구 요청의 복구 지시 주입을 확인했다. 이는 실제 제공자에 80만 토큰을 보내는 장문 품질 시험과 다르다.

추가 검증: 전체 회귀 테스트 452개 통과, 생략 없음. 실제 DeepSeek API도 `deepseek-flash[1m]`으로 성공했고 실행 결과의 contextWindow=1000000을 확인했다. 미완료 작업 후속 실행도 성공했다. 실제 API에 80만 토큰을 보낸 압축 시험은 수행하지 않았다.

아직 미구현: TODO에 등록되지 않은 중요한 질문의 누락 탐지, 완료 표시의 의미 검토와 추가 조사 경로 판단, 조사 단계와 최종 JSON 작성 단계의 분리, Fargate 강제 종료 시 신호 처리·감사 업로드 후 정리 강화. 질문과 조사 충분성은 의미 판단이므로 단순히 빈 TODO를 차단하는 방식으로 해결됐다고 주장하지 않는다. 이 변경은 로컬이며 클라우드 배포 전이다.

근거: [DeepSeek의 Claude Code 연결 안내](https://api-docs.deepseek.com/quick_start/agent_integrations/claude_code/), [SDK 문맥 설정](https://code.claude.com/docs/en/model-config), [PreCompact 출력 제약](https://code.claude.com/docs/en/hooks#precompact).

## 2026-10-05 로컬 검증

- 전체 테스트 449개 통과, 생략 없음. wheel 빌드와 새 하네스·작업 문서·도구의 패키지 포함을 확인했다.
- 과거 실행 원자료를 같은 JSON 직렬화로 비교하면 최초 자료 입력은 185,141자에서 3,844자로 줄었다. 별도 전달되는 분석 지침과 도구 정의는 이 수치에서 제외했다. 원문은 input.json 및 read_source로 보존된다.
- 실제 SDK에서 폴더 생성 → Markdown 작성 → 수정 → 읽기 → 작업 완료 기록을 확인했다. 미완료 작업을 남긴 첫 응답은 발행하지 않고 같은 클라이언트에 후속 메시지를 보내 완료된 마지막 응답만 채택하는 시험도 통과했다.
- 중단 상태의 메모·작업을 새 작업 공간에서 복구하고 원자료가 달라지면 재개를 거절하는 테스트를 통과했다. 취소 시 도구 감사 기록이 끝날 때까지 기다리고, 중복 워커가 관측을 덮어쓰지 않으며 완료된 작업의 재전달이 모델을 다시 호출하지 않는 기존 회귀 검사도 통과했다.

### 실제 모델 고정 자료 평가

가상의 Nova 수주 증가 사례를 사용했다. DB 뉴스는 비어 있고 PDF 읽기는 실패하며 대체 IR에는 이번 분기의 매출 정체·마진 하락 또는 계약상 정보 비공개가 있다. 정답은 각각 이익 감소·방향 미확정이다. 가짜 URL에 자료를 반환했던 평가기 결함은 수정했고, 초기 실행 결과는 최종 버전 결과와 구분한다.

| 실행 | 외부 IR 확인·방향·인용 | 분석 도구 호출 |
|---|---|---|
| 이전 하네스 Flash / 공개 자료 | 통과 | 8 |
| 이전 하네스 Flash / 비공개 자료 | 통과 | 6 |
| 최종 하네스 Flash / 공개 자료 | 통과 | 6 |
| 최종 하네스 Pro / 공개 자료 | 통과 | 14 |

개발 중 Flash 공개·비공개 반복 실행과 Pro 비공개 실행에서도 올바른 방향을 도출했지만, 중복 조회가 있었다. 초기 인용 검사는 모든 인용을 IR로 제한해 검색·실패 기록의 정당한 병기를 거절했다. 존재하는 응답 ID와 핵심 IR 인용을 분리해 수정했다. `deepseek-pro`라는 잘못된 모델명의 400 오류 실행은 품질 평가에서 제외했으며 실제 지원 이름은 `deepseek-v4-pro`였다.

이 작은 사례는 이전 하네스도 통과했다. 따라서 품질 개선의 통계적 증거가 아니며 실제 ETF의 재귀 탐구가 충분해졌다는 증거도 아니다. 짧은 사례에서는 작업 목록이 자발적으로 작성되지 않았다. 상태 기능은 별도 실제 SDK 시험에서 검증했으며 작업 등록·완료 선언의 의미가 올바른지까지 코드로 보장하지 않는다.

### 로컬 리뷰에서 수정한 문제

1. SDK 0.2.160 환경의 실행 바이너리 2.1.289는 옵션에 지정한 TodoWrite를 실제 도구 목록에 노출하지 않았다. mock 테스트만으로 발견하지 못했고 실제 시험에서 확인했다. 자체 내부 MCP `workspace.update_tasks`로 대체하여 상태를 도구 실행에서 직접 저장했다. 별도 서버·포트는 없다.
2. 평가기의 추측 URL 반환과 과도한 IR 전용 인용 조건을 수정했다. 실패 실행을 삭제하거나 통과로 덮어쓰지 않았다.
3. 파일 쓰기 권한은 notes/의 Markdown으로 제한하고 상위 경로·승인 문서·플러그인·링크 경로는 거절한다. 시스템 프롬프트와 AGENTS.md의 새 책임을 문서·대시보드 목록에 반영했다.

### 범위와 남은 운영 검증

OMP 18.4.4의 미완료 작업 알림(최대 3회), 중간 상태 갱신 알림(12회 조사 호출 후, 최대 2회), 작업 기억 패턴을 SDK에 적용했다. OMP 전체 런타임을 복사하지는 않았다. OMP의 중간 알림은 성공한 변경 도구 기준이지만 이 분석 워커에서는 성공한 조사 도구 기준이다.

명시적 runner 재개는 메모와 작업 목록 복구이며 제공자 대화 세션 복구가 아니다. 클라우드 큐에서 중단 작업을 자동 복구하는 기능은 추가하지 않았다. Fargate에서 새 이미지 실행·강제 중단·S3 복원 시험, 실제 ETF의 전후 반복 평가, GitHub 머지·배포는 이 로컬 검증에 포함되지 않는다.

재현 명령: 패키지 디렉터리에서 `python -m pytest tests -q`, `uv build --wheel`. 모델 평가는 `python -m edge_analysis_v2.quality.harness_eval --env-file <환경파일> --artifacts <새 실행폴더> --case available --model deepseek-flash`로 실행하며 실제 API 비용이 든다. `unavailable`과 `deepseek-v4-pro`도 지원한다. 고정 자료 평가에는 투자 분석 DB 발행이 없다.

## 2026-10-06 dev 반영 시 리뷰로 고친 것

최신 dev 위로 옮긴 뒤 별도 에이전트의 독립 리뷰를 받았다. 엔진 테스트 544개 통과.

| 지적 | 고친 내용 |
|---|---|
| 도구 오류 결과의 키가 `isError`여서 SDK 0.2.160이 무시했고, 실패가 모델과 대시보드에 성공으로 보였다 | 핸들러가 `is_error`를 돌려준다 |
| `notes/index.md` 자리에 폴더가 있으면 문맥 압축 처리에서 예외가 나 복구 지시가 사라졌다 | 색인이 파일일 때만 읽는다 |
| 압축 뒤 첫 호출이 최종 제출이면 복구 지시가 두 번 전달됐다 | 거절 사유로 전달한 뒤 비운다 |
| 종료 처리의 메모 저장 실패가 원래 예외(타임아웃·취소)를 덮었다 | 저장 실패를 삼키고 원래 예외를 유지한다 |
| 원자료를 `read_source` 뒤로 옮기면서 자료 한계 안내(`source_gaps`, `history_preview`)가 첫 입력에서 빠졌다 | 첫 입력에 그대로 싣는다 |
| 압축 기록 `compactions.jsonl`이 관측 업로드 대상에 없었다 | 업로드 대상에 넣었다 |
| 가중 밸류 도구의 설명이 바뀌었는데 가상 자료 모드의 정의 버전이 그대로였다 | `calculate_weighted_valuation`·`get_instrument_factors`를 v3으로 올렸다 |

리뷰에서 확인만 하고 남긴 것: 완료 표시만 있는 작업 목록 하나로도 질문 등록 조건이 충족된다(위 "아직 미구현"의 완료 표시 의미 검토와 같은 문제). `resume`은 운영 호출부가 아직 없다.
