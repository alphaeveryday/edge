## 접속과 권한

- SSM 프로세스가 종료돼 15432/15433 포트가 닫혀 있었음. 기존 고정 터널을 숨김 실행으로 복구. 대시보드 DB 목록 81건 재조회 성공.
- 사용자의 명시 지시에 따라 `work`로 [권한 SQL](../scripts/grant_source_reader.sql)을 적용. 전용 `edge_analysis_v2_reader`에 원천 5테이블 SELECT와 조회 함수 5개의 EXECUTE만 추가.
- 변경 후 전용 reader로 실제 조회. INSERT·UPDATE·DELETE·TRUNCATE 권한 없음, 관리자 역할 속성 없음 확인. writer의 원천 테이블 SELECT 권한도 없음 유지.
- 원래 시점 조회 함수는 writer에만 열려 있었음. 후속 구현은 함수의 판본 선택 규칙을 재사용하고 원본 전체 조회는 조사에 사용.
- reader는 로컬 접속 초기 설정에서 생성되는 역할임. 모든 환경에 존재하지 않으므로 이번 개발 접근 권한 SQL을 공통 Flyway 마이그레이션으로 넣지 않음. Flyway 이력도 변경하지 않음.
- 원천 데이터·테이블 구조·기존 서비스 권한·새 AWS 자원 변경 없음. 터널 자동 재시작은 미구현.

## 재검증

- [보유량 조회 SQL](../scripts/inspect_source_readiness.sql)을 reader로 실행해 6개 결과 집합 확인. 읽기 전용 트랜잭션·쿼리 15초 제한 사용.
- 권한 변경과 행수 조사는 실제 DB에서 검증. 에이전트 재실행·배포 테스트는 하지 않음.
- 후속: 가상/실제 입력과 이전 분석을 분리한 뒤 구성·뉴스·수급·차트를 차례로 연결. 매크로·재무는 데이터 적재 후 이 SQL을 다시 실행하고 계열·종목·필요 이력까지 충족할 때 연결.
