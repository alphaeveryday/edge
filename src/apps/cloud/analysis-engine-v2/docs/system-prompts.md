에이전트의 분석·작성 지시는 아래 YAML 두 개가 단일 기준(SoT)이다. 서버는 분석 종류에 맞는 `system_prompt` 본문을 그대로 모델에 전달한다. 옵시디언이나 리서치 문서를 추가로 읽어야 실행할 수 있는 구조가 아니다.

| 실행 지시문서 | 담당 |
|---|---|
| [movement.yaml](../src/edge_analysis_v2/prompts/movement.yaml) | 오늘의 배경 탐색·설명·중요도 선정 |
| [outlook.yaml](../src/edge_analysis_v2/prompts/outlook.yaml) | 1개월 전망 조사·본문 편집·요약과 판단 |

- 분석 행동·말투를 바꾸려면 해당 YAML을 수정한다. 공통 품질 원칙은 두 파일에서 일치시킨다.
- 툴 인자·반환 형식과 최종 JSON은 코드의 툴 정의·응답 스키마를 따른다. YAML에 별도 스키마를 복제하지 않는다.
- 옵시디언의 취향·워크플로우·메타 규칙은 설계 배경과 제안 기록이다. 이 문서만 수정해 실행 규칙이 바뀌지는 않는다. 앱 화면 계약의 역할은 그대로 유지한다.
- 실행마다 `system_prompt.txt`에 실제 전달한 지시를 기록한다. 현재 YAML과 과거 실행의 지시는 다를 수 있다.
- 로딩·전달·기록 일치는 `test_model_runner.py`로 확인한다. 분석 품질은 같은 입력의 실제 모델 결과와 반례를 따로 검수한다. 코드 테스트 통과를 문장 품질 합격으로 간주하지 않는다.

이번 정리에서는 전망의 네 질문·경쟁 설명·산업과 상위 5종목 연결·조사 종료 판단을 실행 지시에 반영했다. 오늘 움직임은 질문에 따라 조회하고 설명·순위를 갱신한다. 의미 없는 수치 변경만으로 항목을 추가하지 않으며, 과거 시점이 명시되지 않은 낡은 현재 수치는 재사용하지 않는다. 실행 한도와 응답 스키마는 변경하지 않았다.
