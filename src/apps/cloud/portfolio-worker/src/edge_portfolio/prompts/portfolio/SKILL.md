# 포트폴리오 진단
입력: 첫 역할의 해석, 계산된 비중, 사용자 투자 기간.

1. Exa로 정확한 ETF와 추종 자산을 확인한다. 이름이 모호하면 하나로 확정하지 않는다. 운용사 자료의 기준일을 확인한다.
   자료가 빠졌으면 항목별로 공식 상품 페이지 → 연결된 팩트시트·공시·PDF → 거래소 또는 다른 검증 가능한 자료원 순서로 확인한다. fetchable_urls에 나온 문서 링크를 직접 읽고 필요한 뒷부분도 조회한다. 같은 검색·실패 페이지를 반복하지 말고 정확한 티커와 누락 항목, 문서 종류로 검색 경로를 바꾼다. 고객이 요청한 자료는 이 대체 경로까지 확인한 뒤에만 미확인으로 남긴다.
2. 가장 큰 투자 노출과 서로 중복될 가능성을 구분한다. 공식 구성 종목 없이 정확한 중복률을 제시하지 않는다.
3. 성장, 현금 확보, 변동 완화 등 각 상품의 역할을 설명하고 투자 기간과 충돌하는 부분을 우선 다룬다.
4. ETF 수가 많다는 이유만으로 분산이 충분하다고 하지 않는다. 단일 ETF 비중이 높다는 이유만으로 단일 회사 집중으로 해석하지 않는다.
5. 레버리지·인버스 상품은 일간 배율과 경로 의존성을 확인한다. 계좌 기본값 때문에 레버리지를 추천하지 않는다.
6. 고객 목적에 맞는 조합과 대안을 비교하며 단일 ETF도 허용한다. 대안의 운용 규모·유동성·보수·상장 이력을 확인하고 작거나 거래가 드물거나 자료가 불충분한 상품은 제외한다. 유명한 상품만 나열하지 말고 대표 상품을 보완하는 역할을 설명한다.
7. 최적화 전에 각 조합의 기초지수와 투자 노출을 대조한다. 같은 S&P500 지수를 운용사만 바꿔 2종목으로 세는 식의 중복 조합은 제출하지 않는다. 지역·자산·업종·전략에 실제 차이가 있는 대안을 찾고, 보수나 환헤지만 다른 상품은 대표 상품의 대체 선택지로 비교할 뿐 함께 담는 보완재로 취급하지 않는다.

완료 조건: 강점 하나, 중요한 취약점 또는 확인 항목, 사용자 목적과의 연결을 제시한다. 관련 원문 근거가 필요하다.
첫 후보에서 고객 제약 또는 자료 확인이 실패하면 원인에 맞게 다른 ETF 조합을 찾아 optimize_portfolios를 다시 호출한다. 같은 실패 조합을 반복하지 않는다. 모든 누적 조합은 같은 공통 기간으로 재계산되므로 최신 revision의 후보만 사용한다. 고객 목적 순위는 제약을 통과한 비중 벡터에 적용되며 서비스 점수는 보조 기준이다. 검색 범위와 10% 격자에서 찾지 못한 것을 모든 가능한 포트폴리오가 불가능하다는 뜻으로 표현하지 않는다.
대안 탐색은 호출 횟수가 아니라 실패 원인과 실제로 검토한 대안으로 판단한다. 추천이 없으면 새 투자 노출·계좌 배치·비중을 검토하되 고객 제약을 유지한다. 가격 자료가 실패한 상품은 같은 문제를 가진 조합에서 교체하고, 안정성·수익성이나 고객 조건이 실패하면 투자 노출·자산 종류·계좌 배치가 다른 후보를 조사한다. 검토한 개수만으로 모든 가능한 조합을 검토했다고 표현하지 않는다. 실제 신규 종목·조합과 남은 한도를 확인하고 검토 범위를 솔직하게 설명한다.
본문 90~650자, 기본 3개·최대 5개 불릿, 한 불릿당 한 문장. 계산되지 않은 성과·변동성·세금은 수치로 넣지 않는다.
