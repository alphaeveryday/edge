툴 호출 결과를 에이전트에게 넘기기 전에 PostgreSQL에 저장하는 연결 모듈이다. 이미 생성된 분석 ID에 실행을 연결하고, 저장된 결과만 반환한다. 원천 조회와 계산 방식은 바꾸지 않는다.

- 입력: 기존 동기 툴 호출 함수, 등록할 툴 정의, 분석 종류·ID, 관측 시각 문맥.
- 성공: 기존 호출 ID와 전체 반환값을 그대로 저장 → 저장된 반환값 전달.
- 계산 실패: 새 실행 ID에 실패를 기록 → 실행 ID가 포함된 오류 전달. 원본 예외 문자열은 저장하지 않음.
- 저장 실패: 결과 반환 중단. 자동 재실행이나 파일 저장으로 우회하지 않음.
- 툴이 인수 객체를 수정해도 최초 호출 인수 보존. 등록되지 않은 함수는 호출하지 않음.
- 분석 부모 행은 호출 전에 커밋되어 있어야 함. 연결은 전용 autocommit PostgreSQL 연결.
- 이번 범위: 호출 경계와 실제 로컬 수급 툴 연결 검증. SDK 엔트리포인트·대시보드·클라우드 적용은 후속 작업.

검증:

- 단위 17개 + PostgreSQL 통합 7개. 호출 중 인수 변경, 계산 실패, 저장 실패, 미등록 함수, 정의 충돌 검사 포함.
- 기존 로컬 `ToolRuntime`의 F4 시나리오로 외국인 최근 5일 순매수 합계 호출: `30,000,000원`. 툴 반환값 = 로컬 기록 = DB 저장값 확인.
- 같은 실제 툴에 999일 요청: 실패 기록과 실행 ID 조회 확인. 이 확인은 기존 미등록 툴 코드에 의존하는 수동 연결 검사이며 CI 검사가 아님.
- 원천은 목데이터, DB는 로컬 PostgreSQL. 실제 LLM 호출·SDK 기본 경로 변경·클라우드 검증은 아직 수행하지 않음.
