## 요약

DB 테이블만 추가해도 기존 분석 엔진의 전체 테스트와 두 앱의 Docker 빌드가 실행됐습니다. 최근 성공 실행에서 분석 엔진 테스트만 11분 40초 걸렸습니다. 이 PR은 테스트를 삭제하지 않고, 바뀐 파일에 필요한 검사만 선택합니다.

예를 들어 v2 코드만 수정하면 v2를 검사하고, v1 코드가 함께 바뀌면 v1 검사도 실행합니다. 기존 개발자의 코드 변경이나 공통 의존성 변경에서 회귀 검사가 빠지지 않도록 선택 규칙을 테스트했습니다.

## 실행 규칙

| 변경 | 실행할 검사 |
|---|---|
| v1 분석 엔진 | v1 단위 테스트·이미지 빌드·두 서비스 DB E2E |
| 데이터 파이프라인 | 해당 단위 테스트·이미지 빌드·DB E2E |
| v2 | v2 단위 테스트 |
| v2 계산 라이브러리 | 라이브러리와 v2 단위 테스트 |
| 클라우드 마이그레이션만 | DB E2E·SQL 직접 참조 테스트, 등록된 v2/계산 라이브러리 검사 |
| 공통 의존성·ontology·이 CI 또는 분류하지 못한 Python 파일 | 모든 등록 패키지 검사·기존 이미지 빌드·DB E2E |
| 문서만 | 경로 선택 테스트·최종 결과 확인만 |

스키마 전용 Flyway·ERD 검사와 JVM 검사는 변경하지 않습니다. SQL을 직접 읽는 `test_evidence_save.py`와 `test_schema_vocab.py`는 DB E2E에서 계속 실행합니다.

## v2 패키지가 아직 없는 현재 dev에서의 동작

현재 dev에는 v2 패키지가 없습니다. 등록된 패키지만 공통 회귀 검사 대상으로 사용합니다. v2 파일이 바뀌었는데 패키지가 없거나 uv workspace에 등록되지 않았다면 실패합니다. 전체 로컬 v2 구현이나 의존성을 이번 PR에 가져오지 않습니다.

## 누락을 막는 방법

- 이름 변경은 삭제 경로와 새 경로를 모두 확인합니다.
- 경로 조회·분류 실패는 최종 체크 실패로 이어집니다.
- 선택한 검사가 취소되거나 예상 밖으로 생략돼도 최종 체크는 실패합니다.
- GitHub 실행 요약에 선택한 검사 목록과 생략 규칙을 표시합니다.
- 문서 PR에도 가벼운 감지·최종 체크가 생깁니다. 무거운 앱 검사는 실행하지 않습니다.

## 검증

- 선택기 구현 전 테스트 실패 확인 후 구현.
- 선택 규칙·누락 패키지·단계별 패키지 도입·혼합 변경·실제 Git rename·최종 결과 검사 15개 통과.
- actionlint 1.7.7 워크플로 구문·표현식 검사 통과(ShellCheck는 별도 실행하지 않음). 실제 GitHub CI 결과는 PR 체크에서 확인.
- CI 자체를 바꾼 이 PR에서는 보수적으로 기존 전체 회귀 검사를 실행합니다. 이 PR부터 모든 검사를 생략하는 변경이 아닙니다.

## 범위

변경 파일은 Python 워크플로, 경로 선택기, 선택기 테스트, 이 설명 4개입니다. 앱 코드·기존 테스트·배포 워크플로·DB 스키마는 변경하지 않습니다. 병합 후 새 PR 실행부터 선택 규칙이 적용됩니다.
