분석 실행기가 원천 테이블을 바꾸지 않고 v2 결과만 저장할 수 있도록 DB 권한을 분리한다. 기존 읽기 계정은 유지하고, 새 결과 저장 역할을 Flyway로 만든다.

| 대상 | 허용 |
|---|---|
| 움직임·전망 결과 6개 테이블 | 조회·추가·수정·삭제 |
| 툴 정의·실행 2개 테이블 | 조회·추가만. 기존 근거 수정·삭제 불가 |
| 뉴스·가격·수급 등 원천 | 별도 권한 없음 |
| 스키마·테이블 생성, 역할 관리 | 불가 |

- 역할: `edge_analysis_v2_writer`. 최초에는 NOLOGIN. 비밀번호를 마이그레이션에 넣지 않음.
- 후속 연결 작업에서 전용 Secrets Manager 자격을 설정하고 LOGIN 허용. 그 전에는 직접 접속 불가.
- 기존 동명 역할이 있으면 중단. 권한 충돌을 덮어쓰지 않음.
- 기존 PUBLIC 권한은 변경하지 않음. 임시 테이블 등 PUBLIC에서 상속되는 권한은 그대로 남음.
- `dev` 병합 시 기존 schema-migrate가 개발 RDS에 적용. 신규 서버·수집 작업 없음.
- ERD 테이블 구조 변경 없음. 기존 결과 테이블에 대한 권한만 추가.

검증: 로컬 PostgreSQL에서 역할 속성·테이블별 유효 권한과 실제 저장·권한 거부를 확인한 뒤 PR 생성 및 CI 통과 후 병합.
